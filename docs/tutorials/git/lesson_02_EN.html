Git and GitHub, Step by Step

Lesson 2Install and set up

Make a GitHub account, install VS Code and Git, open a terminal, and tell Git who you are. You do this once on each computer.

⏱ 45 minYou need: A computer with Windows 10 or 11, macOS or Linux, and an internet connection

In this lesson you will

  • Create a free GitHub account
  • Install VS Code and Git
  • Open a terminal inside VS Code and type your first command
  • Tell Git your name and email, and set three useful defaults
1

What you will install

You need three things. All of them are free.

What What it is Why you need it
A GitHub account Your login on the website github.com To keep your projects online and share them
VS Code A text editor made by Microsoft To write your files, and to type commands in its built-in terminal
Git A program that runs on your computer To take the snapshots of your work

If you use a computer at work or at a university, you may need permission to install programs. Ask your IT team if an installer refuses to run.

Good to know

VS Code is not part of Git. You could use any editor and any terminal. We use VS Code because it puts the editor and the terminal in one window, which makes every lesson easier to follow.

2

Step 1: Create a GitHub account

In your browser
  1. Go to github.com/signup.
  2. Type your email address, a password and a username, and follow the prompts. GitHub asks you to verify your email address: follow the instructions in the email it sends you.
  3. If GitHub asks you to choose a plan, choose Free.

Choose your username with care. It becomes part of your web addresses: your profile will be at github.com/your-username, and in Lesson 8 your web page will be at your-username.github.io/my-page/. Short, lower-case names that you would be happy to show an employer work best.

Key idea

In this series, your-username stands for your GitHub username. Wherever you see it, type your own username instead.

If something went wrong

I did not get GitHub’s email. Look in your spam folder. If it is not there, ask GitHub to send it again, or try another email address.

“This email can’t be used” or “We couldn’t create your account”. GitHub suggests trying another browser, turning off browser extensions, or waiting a while and trying again. For “This email can’t be used”, also try another email address.

3

Step 2: Install VS Code

  1. Go to code.visualstudio.com and click the download button for Windows.
  2. Open the file you downloaded and click through the installer. On the page Select Additional Tasks, leave Add to PATH (requires shell restart) ticked. It is ticked already.
  3. When the installer finishes, open VS Code.
  1. Go to code.visualstudio.com and click the download button for macOS.
  2. In Finder, open Downloads. If you see a .zip file there, double-click it to unpack it. Drag Visual Studio Code onto Applications in the Finder sidebar, then open it from Applications. If macOS asks whether you are sure you want to open it, click Open.
  3. Do not skip this step: Git uses it to open VS Code when it needs a message from you. Press Cmd+Shift+P: a search box opens at the top of the window. Type shell command and choose Shell Command: Install ‘code’ command in PATH. If VS Code says it will prompt for administrator privileges, click OK and type your Mac’s password.

  1. Go to code.visualstudio.com and download the .deb file (Ubuntu, Debian) or the .rpm file (Fedora).

  2. Open the file to install it with your software centre. If that does not work, install it from a terminal instead: open one (on Ubuntu, press Ctrl+Alt+T), then type these two commands, without the $, pressing Enter after each. The first goes to the folder the file was downloaded to; the second installs it, for example on Ubuntu:

    Terminal
    $ cd ~/Downloads$ sudo apt install ./code_*.deb

    Type your password when asked, as described in Step 3.

  3. Open VS Code from your applications menu.

In VS Code
  1. VS Code opens with a Welcome tab. Close it (click the × on the tab), and any panel on the right: you will not need them.
  2. Turn on Auto Save: open the File menu and click Auto Save, so that a tick appears next to it. From now on VS Code saves your files as you type. Without it, Git cannot see changes you have not saved, which confuses everyone at first.
Tip

If a file’s tab ever shows a dot (●) instead of an ×, the file is not saved. Press Ctrl+S (Cmd+S on a Mac) to save it.

4

Step 3: Install Git

  1. Go to git-scm.com/install/windows and click Click here to download the latest version of Git for Windows.
  2. Open the file you downloaded. If Windows asks whether you want to allow this app to make changes to your device, click Yes. The installer has many pages. Click Next on all of them, except these two:
    • On Choosing the default editor used by Git, open the drop-down list and choose Use Visual Studio Code as Git’s default editor.
    • On Adjusting the name of the initial branch in new repositories, choose Override the default branch name for new repositories. The box below it already says main. Leave it.
  3. Click Install, then Finish.

Git for Windows also installs Git Bash, a terminal that understands the same commands as the terminals on macOS and Linux. We use it in the next step.

macOS can install Git for you, as part of Apple’s “command line developer tools”.

  1. Open the Terminal app: press Cmd+Space, type Terminal and press Return.

  2. Type this command, without the $, and press Return:

    Terminal
    $ xcode-select --install

  3. A window asks whether you want to install the tools. Click Install, agree to the licence, and wait until it says the software was installed. It can take 10 minutes or more.

If the terminal says the command line tools are already installed, you already have Git. That is good news, even if the message contains the word error.

Open a terminal: on Ubuntu, press Ctrl+Alt+T; on other systems, open Terminal from your applications menu. Then use your system’s package manager. Type each command without the $ and press Enter. On Ubuntu or Debian:

Terminal
$ sudo apt update$ sudo apt install git

On Fedora:

Terminal
$ sudo dnf install git

Type your password when asked. Nothing appears while you type it, or a * for each character; that is normal. If apt asks Do you want to continue? [Y/n], press Enter. If dnf asks Is this ok [y/N], type y and press Enter: there, Enter alone means no.

5

Step 4: Open a terminal in VS Code

A terminal is a window where you give the computer instructions by typing them, instead of clicking. Each instruction is called a command. You type it and press Enter (Return on a Mac), and the computer answers with some text.

In VS Code
  1. If VS Code was open while you installed Git, close it and open it again, so that it finds Git.
  2. Open the Terminal menu and click New Terminal. A panel opens at the bottom of the window, with a blinking cursor.

On Windows, VS Code opens PowerShell by default. Switch it to Git Bash, so that every command in this series works exactly as shown:

  1. Press Ctrl+Shift+P, type default profile and choose Terminal: Select Default Profile.
  2. Choose Git Bash.
  3. Close the terminal you have: click the bin icon at the top right of the terminal panel. Then open a new one with Terminal > New Terminal.

The new terminal shows something like this, with your own name and computer:

Terminal
you@LAPTOP MINGW64 ~$

The terminal shows something like this, with your own name and computer:

Terminal
you@MacBook ~ %

macOS uses % at the end where the other systems use $. It means the same thing.

The terminal shows something like this, with your own name and computer:

Terminal
you@laptop:~$

The text before the cursor is called the prompt. It tells you that the terminal is ready for a command. In this series, every command is shown after a $, which stands for the prompt.

Try your first command. Click in the terminal panel, type git --version (only what comes after the $), and press Enter:

Terminal
$ git --versiongit version 2.56.0

The line below the command is what the computer answers. Your version number may be different, and that is fine: anything from 2.28 upwards works for this series. Windows adds .windows and a number to the version, and macOS adds (Apple Git-...). If yours is older than 2.28, update Git before you go on (see the troubleshooting page).

Tip

You can copy a command with the Copy button on each box and paste it into the terminal. On Windows, paste into VS Code’s terminal with Ctrl+V; on Linux, with Ctrl+Shift+V; on a Mac, with Cmd+V. Typing the commands yourself helps you remember them, though.

If something went wrong

git: command not found, or “The term ‘git’ is not recognized”. The terminal does not know about Git yet. Close VS Code completely and open it again. On Windows, check that the terminal is Git Bash (it says MINGW64 in the prompt). If it still does not work, install Git again (Step 3).

Nothing happens when I press Enter, or I see a > prompt (dquote> on a Mac). You may have typed an opening quote " without a closing one. Press Ctrl+C (also Ctrl on a Mac) to cancel, and type the command again.

6

Step 5: Tell Git who you are

Every snapshot Git takes records who made it, with a name and an email address. Tell Git yours.

Your projects on GitHub will be public, and so will the email address inside every snapshot. GitHub gives you a private address to use instead, so your real address stays private:

On GitHub
  1. Click your profile picture in the upper-right corner, then Settings.
  2. In the sidebar, under “Access”, click Emails.
  3. Make sure Keep my email addresses private is ticked (tick it if it is not). The text under it shows your private address. It looks like 12345678+your-username@users.noreply.github.com, with your own number and username. Select it and copy it.

Now type these two commands yourself, with your own name and the address you copied. This box has no Copy button, because the commands must contain your details, not the examples. Keep the quotes. To put in the address, type the start of the command, up to and including the first ", paste the address (with the keys from the tip in Step 4), then type the closing " and press Enter.

Terminal
$ git config --global user.name "Your Name"$ git config --global user.email "12345678+your-username@users.noreply.github.com"

Neither command prints anything. In the terminal, no news is good news: a command that worked often says nothing at all.

git config changes Git’s settings. --global means “for every project on this computer”, so you only do this once.

Tip

Made a typo? Type the command again with the right value. The new value replaces the old one. To change part of a command before you press Enter, move the cursor with the ← and → keys: clicking does not move it.

7

Step 6: Three useful defaults

Three more settings save you trouble later. Type them exactly as shown:

Terminal
$ git config --global init.defaultBranch main$ git config --global core.editor "code --wait"$ git config --global pull.rebase false

What they do:

  • init.defaultBranch main names the main line of every new project main. That is the name GitHub uses, and the name the rest of this series uses.
  • core.editor "code --wait" tells Git to use VS Code when it needs you to write or check a message. You will see this in Lesson 5.
  • pull.rebase false chooses the simplest way for git pull to combine your work with work from GitHub. You will meet git pull in Lesson 9.
Good to know

On a Mac, one more setting. macOS leaves hidden files called .DS_Store in folders you open in Finder. They do not belong in your projects, so tell Git to ignore them in every project. Type these two commands; they print nothing:

Terminal
$ mkdir -p ~/.config/git$ echo .DS_Store >> ~/.config/git/ignore

The first makes a folder for Git’s settings; the second writes .DS_Store into Git’s list of files to ignore everywhere. Windows and Linux do not need this.

8

Step 7: Check your settings

Ask Git to list your settings:

Terminal
$ git config --global --listuser.name=Your Name
user.email=12345678+your-username@users.noreply.github.com
init.defaultbranch=main
core.editor=code --wait
pull.rebase=false

You should see your own name and email, and the three defaults. Check that the first two lines show your name and address. If they say Your Name or your-username, type the Step 5 commands again with your own details. Git shows defaultbranch in lower case; that is normal.

Good to know

If your computer’s language is not English, Git may print some of its messages in your language. They mean the same as the English ones shown in this series.

If something went wrong

I see more lines than these. Lines you did not type (for example filter.lfs... or credential...) come from programs you installed earlier. They are fine.

fatal: unable to read config file '.../.gitconfig': No such file or directory, or a line is missing. Some or all of your settings were not saved. Type the missing commands again from Step 5 or Step 6.

9

What you learned

  • GitHub is a website; Git is a program on your computer; VS Code is the editor and terminal we use for both.
  • A terminal takes typed commands. The prompt shows it is ready. In this series $ stands for the prompt: do not type it.
  • VS Code’s Auto Save saves your files as you type.
  • git config --global sets Git’s settings once for your whole computer.
  • Your commits will carry your name and your private GitHub email address.
Command What it does
git --version Shows which version of Git is installed
git config --global user.name "..." Sets the name recorded in your snapshots
git config --global user.email "..." Sets the email recorded in your snapshots
git config --global --list Lists your settings
10

Check yourself

1
What does the $ at the start of a command in this series mean?
The $ stands for your terminal’s prompt. Type the text after it, then press Enter.
2
You ran git config --global user.email "..." and nothing was printed. What happened?
In the terminal, no news is usually good news. Check with git config --global --list if you want to be sure.
3
Why use the ...@users.noreply.github.com address instead of your own email?
Anyone can read the email address inside a public project’s history. The noreply address still links your snapshots to your GitHub account.
