1

两个元模型与一种映射

组件模型描述端口与接线。普通图模型只需要节点和有向边。模型到模型转换（model-to-model transformation）在这两门语言之间翻译：源模型符合组件元模型，目标模型符合另一份图元模型。转换要决定保留什么、省略什么，以及怎样重新建立引用。

这里，每个 Architecture 转成 Graph，每个 Component 转成 Node，每个 Connector 转成 Edge。最简单的版本会丢掉端口名称。这是有意的：图算法可以在组件层面工作，不必知道组件语言中的端口细节。ETL（Epsilon Transformation Language）用规则定义这种映射。规则体沿用第 4 模块的 EOL 表达式。

2

编写 ETL 规则

第一个程序有三条规则。Architecture2Graph 创建根元素并填充其包含的节点与边；Component2Node 复制组件名称；Connector2Edge 把边接到源端口和目标端口所属组件对应的图节点上。

示例组件转换为图在 Playground 中打开 ↗
transform.etl
rule Architecture2Graph
  transform a : Source!Architecture
  to g : Target!Graph {
  g.name = a.name;
  g.nodes ::= a.components;
  g.edges ::= a.connectors;
}
rule Component2Node
  transform c : Source!Component
  to n : Target!Node {
  n.name = c.name;
}
rule Connector2Edge
  transform c : Source!Connector
  to e : Target!Edge {
  e.source ::= c.source.eContainer();
  e.target ::= c.target.eContainer();
}
graph.emf
@namespace(uri="graph", prefix="graph")
package graph;
class Graph {
  attr String name;
  val Node[*] nodes;
  val Edge[*] edges;
}
class Node { attr String name; }
class Edge {
  attr String label;
  ref Node source;
  ref Node target;
}

3

解析转换后的对应元素

ETL 保留一份转换轨迹（transformation trace），记录源元素及其产出的目标元素。equivalent() 取得某源元素经转换后的对应元素。下一个程序与第一个做相同映射，但在填充目标图和连接边的端点时，显式调用 equivalent()。

示例显式解析对应元素在 Playground 中打开 ↗
transform.etl
rule Architecture2Graph
  transform a : Source!Architecture
  to g : Target!Graph {
  g.name = a.name;
  for (c in a.components) { g.nodes.add(c.equivalent()); }
  for (wire in a.connectors) { g.edges.add(wire.equivalent()); }
}
rule Component2Node
  transform c : Source!Component
  to n : Target!Node { n.name = c.name; }
rule Connector2Edge
  transform c : Source!Connector
  to e : Target!Edge {
  e.source = c.source.eContainer().equivalent();
  e.target = c.target.eContainer().equivalent();
}

4

守卫条件与惰性规则

守卫条件（guard）限制规则转换哪些源元素。下一个源模型的第二条连接把数字输出接到模拟输入。带守卫条件的连接器规则只在两端端口类型相同的情况下生成边。三个组件仍都生成节点，但只有兼容的连接生成边。

示例跳过不兼容的连接在 Playground 中打开 ↗
transform.etl
rule Architecture2Graph
  transform a : Source!Architecture
  to g : Target!Graph {
  g.name = a.name;
  g.nodes ::= a.components;
  g.edges ::= a.connectors;
}
rule Component2Node
  transform c : Source!Component
  to n : Target!Node {
  n.name = c.name;
}
rule Connector2Edge
  transform c : Source!Connector
  to e : Target!Edge {
  guard: c.source.type = c.target.type
  e.source ::= c.source.eContainer();
  e.target ::= c.target.eContainer();
}

@namespace(uri="graph", prefix="graph")

  attr String name;
  val Node[*] nodes;
  val Edge[*] edges;
}
class Node { attr String name; }
class Edge {
  attr String label;
  ref Node source;
  ref Node target;
}

惰性规则（lazy rule）只有在请求对应元素时才运行。下一个示例不把组件、而把端口映射成图节点。Architecture2Graph 为每个端口请求 Port2Node。由于 Port 是抽象类、实例实际属于 InPort 或 OutPort，规则需要 @greedy，以匹配子类而非仅匹配完全相同的类型。

示例按需创建端口节点在 Playground 中打开 ↗
transform.etl
rule Architecture2Graph
  transform a : Source!Architecture
  to g : Target!Graph {
  g.name = a.name;
  for (p in Port.all) { g.nodes.add(p.equivalent("Port2Node")); }
}
@lazy
@greedy
rule Port2Node
  transform p : Source!Port
  to n : Target!Node {
  n.name = p.eContainer().name + "." + p.name;
}

5

主规则与转换轨迹

有时不止一条规则转换同一种源类型。下一个示例中，Component2Node 创建普通节点，Component2Audit 创建另一个审计节点。@primary 让普通节点在 equivalent() 选取单个对应元素时排在第一位。

示例选择主对应元素在 Playground 中打开 ↗
transform.etl
rule Architecture2Graph
  transform a : Source!Architecture
  to g : Target!Graph {
  g.name = a.name;
  for (c in a.components) { g.nodes.add(c.equivalent()); }
}
@primary
rule Component2Node
  transform c : Source!Component
  to n : Target!Node { n.name = c.name; }
rule Component2Audit
  transform c : Source!Component
  to n : Target!Node { n.name = "audit:" + c.name; }

6

检查目标模型

转换即便运行成功，也可能丢掉需要的信息。基本图省略端口名称和信号类型；带守卫条件的图省略一条不兼容的连接；主规则示例则有额外的、未被包含的审计节点。把目标元模型和实际输出的目标树放在一起看，才能知道转换后究竟有什么。

对于真实映射，应事先写明预期不变量：节点数、哪些连接器成为边、名称是否保持唯一，以及每条边的端点是否都属于目标图。如果映射依赖正确接线，应先验证源模型；完成转换后也要检查或验证目标模型。第 10 模块会把这套做法用于另一领域。

7

练习

练习 1★★★概念5 分钟

映射类型。 列出分别变成 Graph、Node 和 Edge 的源类型。基本目标模型省略了哪些源信息？

查看解答

Architecture 变成 Graph，Component 变成 Node，Connector 变成 Edge。基本目标模型省略端口、端口名称和信号类型，只保留组件名称及组件级连接。

练习 2★★★概念5 分钟

理解 ::=。 为什么 g.nodes ::= a.components 有意义，而把 a.components 直接赋给目标的 Node 包含引用是错误的？

查看解答

右侧是源模型中的 Component 元素。ETL 的 ::= 解析出它们转换后的 Node 对应元素，再填入 g.nodes。直接赋值会混用不兼容元模型中的元素。

练习 3★★★概念5 分钟

理解主规则。 在主规则示例中，图的 nodes 只有普通节点，为什么实际输出仍打印了审计节点？

查看解答

Component2Audit 不是惰性规则，因此仍为每个组件运行。@primary 只让普通节点成为 equivalent() 首选的对应元素，不会禁用审计规则。审计节点没有容器，便作为独立目标根元素出现。

保留边标签。 为目标 Edge 的 label 属性赋值，格式为“源端口 to 目标端口”。检查结果中是否有两条带标签的边。

transform.etl
rule Architecture2Graph
  transform a : Source!Architecture
  to g : Target!Graph {
  g.name = a.name;
  g.nodes ::= a.components;
  g.edges ::= a.connectors;
}
rule Component2Node
  transform c : Source!Component
  to n : Target!Node {
  n.name = c.name;
}
rule Connector2Edge
  transform c : Source!Connector
  to e : Target!Edge {
  guard: c.source.type = c.target.type
  e.source ::= c.source.eContainer();
  e.target ::= c.target.eContainer();
}

8

自测

1
ETL 转换产出什么？
ETL 把元素与关系映射到目标模型。
2
Source!Component 指什么？
带模型限定的类型区分源语言与目标语言。
3
这里的 ETL ::= 做什么？
特殊赋值经转换轨迹解析对应元素。
4
Connector2Edge 的守卫条件控制什么？
守卫条件为假时，这条规则跳过相应源元素。
5
惰性的 Port2Node 规则为什么使用 @greedy？
如果只匹配完全相同的类型，就会漏掉具体子类。
6
示例中的 @primary 保证什么？
主规则影响对应元素的顺序，不决定其他规则是否执行。
7
转换后应该检查什么？
运行成功仍可能丢失或错误映射数据。
9
