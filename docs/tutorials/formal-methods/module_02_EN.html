Module 2Propositional logic

Read and write formulas built with ¬, ∧, ∨, ⟶ and ⟷, decide with truth tables whether they are tautologies, equivalences or valid arguments, put them into normal forms, and use Isabelle to check requirements written as formulas.

1

Propositions and connectives

Module 1 wrote the specification of sorting with an “and” in the middle: sorted ys ∧ mset ys = mset xs. Requirements are full of such small words: not, and, or, if … then, only if, unless. Each builds a larger statement from smaller ones, and whether the larger one is true depends only on whether the smaller ones are. Propositional logic is the logic of these words. It is the simplest logic in this series, and already a useful one: SAT solvers, programs that decide questions of propositional logic, check hardware designs and software configurations every day. Every later logic, Isabelle’s included, contains it.

One example runs through this module: the controller of a server-room door, which reads a badge reader, a PIN pad, the fire alarm and a lockdown switch, and decides whether to unlock the door.

Definition 2.1Proposition

A proposition is a statement that is either true or false. An atomic proposition, or atom, is one that is not built from other propositions. In formulas, atoms are names such as A, B or fire. Propositional logic never looks inside an atom: all it uses is whether the atom is true or false.

For the door, “the fire alarm is on” and “a valid badge is shown” are atoms. A command such as “unlock the door” is not a proposition, and neither is “x > 3” until you know what x is; statements about variables are the subject of Module 3. Five connectives build larger propositions from smaller ones.

Definition 2.2Connectives
Formula Read it as Name True exactly when
¬A “not A” negation A is false
A ∧ B “A and B” conjunction A and B are both true
A ∨ B “A or B” disjunction at least one of A and B is true
A ⟶ B “A implies B”, “if A then B” implication A is false, or B is true
A ⟷ B “A if and only if B” equivalence A and B are both true, or both false

There are also two constants: True, which is always true, and False, which is always false. In A ⟶ B, A is the antecedent and B the consequent.

Section 2.3 makes the last column exact. In Isabelle/jEdit you type the symbols with the abbreviations from Module 1: ~ for ¬, & for ∧, | for ∨, --> for ⟶ and <--> for ⟷.

From English to formulas

English has many ways to express each connective:

English Formula
not A; it is not the case that A ¬A
A and B; A but B; A although B A ∧ B
A or B (or both) A ∨ B
either A or B, but not both ¬(A ⟷ B)
neither A nor B ¬A ∧ ¬B
if A then B; B if A; B whenever A; A only if B A ⟶ B
A is sufficient for B; B is necessary for A A ⟶ B
A unless B ¬B ⟶ A, which says the same as A ∨ B
A if and only if B; A exactly when B A ⟷ B

Two entries deserve a second look. Or is inclusive in logic: A ∨ B is true when both A and B are true, whereas the “or” of “tea or coffee?” means one but not both, which is exclusive or, ¬(A ⟷ B). And but adds a contrast that logic ignores: “the badge is valid but the door stays shut” is badge ∧ ¬ opens.

Watch out

“A only if B” is A ⟶ B, not B ⟶ A. “The door opens only if the badge is valid” says that whenever the door opens, the badge was valid: opens ⟶ badge. It does not say that a valid badge opens the door; that would be badge ⟶ opens, “the door opens if the badge is valid”. A requirement with “only if” limits what the system may do; it never forces the system to act.

Example 2.1Formalising an access rule

The security team’s first requirement reads: “The door opens only if a valid badge is shown and the correct PIN is entered, unless the fire alarm is on.” Choose an atom for each basic statement:

Atom Meaning
opens the door unlocks
badge a valid badge is shown
pin the correct PIN is entered
fire the fire alarm is on

“The door opens only if a valid badge is shown and the correct PIN is entered” is opens ⟶ badge ∧ pin, and “X unless F” is ¬F ⟶ X, so the requirement is

¬fire⟶(opens⟶badge∧pin)\lnot \mathit{fire} \imp (\mathit{opens} \imp \mathit{badge} \land \mathit{pin}) ¬fire⟶(opens⟶badge∧pin)

An equally natural reading is “the door may open only when there is a valid badge and the right PIN, or a fire”:

opens⟶badge∧pin∨fire\mathit{opens} \imp \mathit{badge} \land \mathit{pin} \lor \mathit{fire} opens⟶badge∧pin∨fire

The two formulas look different but say the same thing, as Exercise 2.3 shows. Notice what the requirement does not say: that a valid badge with the right PIN does open the door. “Only if” states a necessary condition, so another requirement must say when the door has to open.

2

The structure of formulas

To evaluate formulas, transform them or let a computer check them, you need to know exactly what counts as a formula and how each one is put together.

Formation rules

Definition 2.3Formula

The formulas of propositional logic are built by these rules, and only by them:

  1. Every atom is a formula, and so are True and False.
  2. If φ is a formula, then ¬φ is a formula.
  3. If φ and ψ are formulas, then (φ ∧ ψ), (φ ∨ ψ), (φ ⟶ ψ) and (φ ⟷ ψ) are formulas.

The Greek letters φ (“phi”) and ψ (“psi”) stand for any formulas, not only atoms. For example, A, B and C are formulas by rule 1, so ¬A is a formula by rule 2, (¬A ∧ B) by rule 3, and ((¬A ∧ B) ⟶ C) by rule 3 again. A ∧ ∨ B and A ¬ B are not formulas: no rule produces them. A definition of this shape, with basic cases and rules that build larger objects from smaller ones, is an inductive definition. In Module 5 such definitions support proofs by induction and become datatypes in Isabelle.

Every formula remembers how it was built. Draw the last rule used as the root of a tree and the parts it combined as its children, and repeat for the parts: the result is the formula’s parse tree (Figure 2.1).

Definition 2.4Sub-formula and main connective

The sub-formulas of a formula are the formulas at the nodes of its parse tree, the formula itself included. The main connective is the connective at the root. A formula is named after its main connective: ¬(A ∧ B) is a negation, while ¬A ∧ B is a conjunction.

In Figure 2.1 the main connective is ⟶, so the requirement is an implication. Its sub-formulas are the four atoms, badge ∧ pin, badge ∧ pin ∨ fire and the whole formula.

Priorities and grouping

Rule 3 puts parentheses around every binary connective, so that each formula has exactly one parse tree. But the parentheses make formulas hard to read: the door requirement would be (opens ⟶ ((badge ∧ pin) ∨ fire)). School algebra solves the same problem with a convention: × binds more tightly than +, so 2 + 3 × 4 means 2 + (3 × 4). Logic has the same kind of convention: each connective has a priority, and a higher priority binds more tightly. In Isabelle, the binary connectives also group to the right:

Connective Priority in Isabelle Grouping
¬ 40 (applies to what follows)
∧ 35 to the right
∨ 30 to the right
⟶ 25 to the right
⟷ 25 to the right

The numbers are Isabelle’s own. In the library theory HOL.thy, where the connectives are introduced, ∧ is declared infixr 35 (“infix, grouping to the right, priority 35”), ∨ infixr 30, ⟶ and ⟷ infixr 25, and ¬ has priority 40. So:

You write It means
¬A ∧ B (¬A) ∧ B
A ∧ B ∨ C (A ∧ B) ∨ C
A ∨ B ∧ C A ∨ (B ∧ C)
A ∧ B ⟶ C (A ∧ B) ⟶ C
A ⟶ B ⟶ C A ⟶ (B ⟶ C)
A ⟶ B ⟷ C A ⟶ (B ⟷ C)

Grouping to the right suits implication: A ⟶ (B ⟶ C) reads “if A, then if B, then C”, which says the same as “if A and B, then C”, while (A ⟶ B) ⟶ C is rarely what anyone means. For ∧ and ∨ the grouping changes the parse tree but not the meaning (Section 2.5).

Watch out
  • ¬A ∧ B is (¬A) ∧ B. To negate the whole conjunction, write ¬(A ∧ B).
  • ⟶ and ⟷ have the same priority, so A ⟶ B ⟷ C means A ⟶ (B ⟷ C). Books and tools differ here; some give ⟷ a lower priority than ⟶ and read the same text as (A ⟶ B) ⟷ C. Whenever you mix ⟶ and ⟷, write the parentheses.
Check it in Isabelle

Isabelle prints a formula with only the parentheses its priorities need, so it can show you how it read yours. value, which you met in Module 1, cannot compute a truth value for a formula with variables; for formulas like these, it prints the formula back. Put the cursor on each line in turn:

Isabelle
value "(¬ A) ∧ (B ⟶ C)"
value "A ⟶ (B ⟶ C)"
value "(A ⟶ B) ⟶ C"
Output
"¬ A ∧ (B ⟶ C)"
  :: "bool"

"A ⟶ B ⟶ C"
  :: "bool"

"(A ⟶ B) ⟶ C"
  :: "bool"

Isabelle dropped the parentheses that the priorities make unnecessary and kept those that change the meaning. The type bool in the output is the type of formulas: in Isabelle a formula is a term of type bool, whose only two values are True and False. One more example holds a surprise:

Isabelle
value "A ⟶ (B ⟷ C)"
Output
"A ⟶ B = C"
  :: "bool"

Isabelle prints ⟷ as =. For truth values, “if and only if” is equality: A ⟷ B holds exactly when A and B have the same value. The equals sign binds more tightly than every connective (its priority is 50), so A ⟶ B = C means A ⟶ (B ⟷ C). In Isabelle’s output, read = between two formulas as ⟷; Module 3 says more about the two.

Truth tables

The connectives table in Section 2.1 described each connective in words. Truth tables make the descriptions exact.

Definition 2.5Valuation

A valuation assigns a truth value, T (true) or F (false), to each atom. A valuation gives every formula a truth value: an atom gets its value from the valuation, True is T, False is F, and each connective combines the values of its parts according to its truth table below.

The tables on these pages are computed from their formulas when the page is built, so they contain no slips. They list the atoms in alphabetical order, start with the row in which every atom is T, and end with a line that classifies the last column; Section 2.4 explains the words.

The column for A ⟶ B surprises most people. An implication is false in exactly one row: when its antecedent is true and its consequent false. When A is false, A ⟶ B is true whatever B is; it is then said to be vacuously true.

Think of it like this

Think of A ⟶ B as a promise: “if you pass the exam, I will buy you dinner”. The promise is broken only if you pass and I do not buy dinner. If you fail the exam, I have kept my promise whether I buy dinner or not.

For specifications this is what you want. The rule “during a lockdown, the door stays shut”, lockdown ⟶ ¬ opens, constrains the door only during a lockdown; on an ordinary day it holds whatever the door does. Nor is implication about cause: “if 2 + 2 = 5, the door is open” is true, because its antecedent is false.

To find the value of a formula under a valuation, work up its parse tree from the atoms, applying the table of each connective on the way.

Example 2.2Evaluating the door requirement

Someone shows a valid badge, types the wrong PIN, there is no fire, and the door opens. The valuation is opens = T, badge = T, pin = F, fire = F. Work up the tree of Figure 2.1:

  1. badge ∧ pin is T ∧ F, which is F.
  2. badge ∧ pin ∨ fire is F ∨ F, which is F.
  3. opens ⟶ badge ∧ pin ∨ fire is T ⟶ F, which is F.

The requirement is false in this situation: the controller has broken it. The labels in Figure 2.1 show the same computation.

The truth table of a formula has one row for each valuation of its atoms and gives the formula’s value in each row. A formula with n atoms has 2n2^n2n rows, because each atom can be T or F independently of the others.

4

Tautologies, contradictions and satisfiable formulas

Some formulas are true in every row of their truth table, some in none. These two extremes, and the formulas between them, are the central ideas of propositional logic.

Definition 2.7Tautology, satisfiable, contradiction

Let φ be a formula.

  • φ is a tautology, or valid, if it is true under every valuation: every row of its truth table is T.
  • φ is satisfiable if it is true under at least one valuation. A valuation that makes φ true satisfies φ and is called a model of φ.
  • φ is a contradiction, or unsatisfiable, if it is true under no valuation.
  • φ is contingent if it is satisfiable but not a tautology. A valuation that makes φ false is a counterexample to φ.

The verdicts under the computed tables use these words, with “Satisfiable but not valid” for a contingent formula. The simplest tautology is the law of excluded middle: every proposition is true or false.

A¬AA ∨ ¬A

FTT

Tautology: true in every row.

Its opposite is the simplest contradiction:

A¬AA ∧ ¬A
TFF
FTF

Contradiction: false in every row.

The requirement of Example 2.3 is contingent: three rows are counterexamples and the others satisfy it. Figure 2.2 shows how the classes fit together.

Fact 2.1Negation and the three classes

For every formula φ:

  1. φ is a tautology if and only if ¬φ is a contradiction.
  2. φ is satisfiable if and only if ¬φ is not a tautology.

The reason is that ¬ flips every row of the truth table. Fact 2.1 turns one question into another: to show that φ is a tautology, show that ¬φ has no model; to find a model of φ, look for a counterexample to ¬φ. SAT solvers and Isabelle’s Nitpick both rely on it (Sections 2.8 and 2.9).

Example 2.4Peirce’s law

Is ((A ⟶ B) ⟶ A) ⟶ A a tautology? Looking at it does not tell you. The truth table does:

ABA ⟶ B(A ⟶ B) ⟶ A((A ⟶ B) ⟶ A) ⟶ A
TTTTT
TFFTT
FTTFT
FFTFT

Tautology: true in every row.

Every row is T. The formula is called Peirce’s law, after the logician Charles Sanders Peirce.

Check it in Isabelle

Tautologies are lemmas. When a lemma contains variables, Isabelle reads it as a claim about every value of the variables, as with xs in Module 1. In a formula, Isabelle infers from the connectives that the variables have type bool, so the claim is that the formula is true for every combination of True and False: proving the lemma shows that the formula is a tautology.

Isabelle
lemma "A ∨ ¬ A"
Output
proof (prove)
goal (1 subgoal):
 1. A ∨ ¬ A
Isabelle
  by simp

Three proof methods prove tautologies:

  • simp, the simplifier from Module 1, rewrites the goal with equations it knows until it becomes True.
  • blast searches for a proof: it takes the formula apart, considers cases and backtracks when a choice leads nowhere. It either proves the goal completely or fails.
  • auto combines the simplifier with logical steps of the kind blast takes, and leaves behind what it cannot prove.

Rewriting is not enough for every tautology. Peirce’s law defeats simp:

Isabellefails on purpose
lemma "((A ⟶ B) ⟶ A) ⟶ A"
  by simp
Output
Failed to apply initial proof method⌂:
goal (1 subgoal):
 1. ((A ⟶ B) ⟶ A) ⟶ A

“Failed to apply initial proof method” means that simp could not even start: none of its equations applies to the goal. blast proves it:

Isabelle
lemma "((A ⟶ B) ⟶ A) ⟶ A"
  by blast

So a failed proof does not mean that the formula is false. In this module, when simp fails, try blast or auto; Module 9 explains what each method can and cannot do.

What happens when the formula is not a tautology? Take A ⟶ B ⟶ A ∧ B ∧ C, which claims too much: from A and B it concludes not only A ∧ B but also C.

Check it in Isabelle

Every proof method fails, each in its own way. simp gets as far as it can and shows what is left:

Isabellefails on purpose
lemma "A ⟶ B ⟶ A ∧ B ∧ C"
  by simp
Output
Failed to finish proof⌂:
goal (1 subgoal):
 1. A ⟶ B ⟶ C

The remaining goal, A ⟶ B ⟶ C, shows what is missing: nothing says that C holds. blast fails with “Failed to apply initial proof method”, as above, because it never leaves a partial result. auto shows its remaining goal in a different notation:

Isabellefails on purpose
lemma "A ⟶ B ⟶ A ∧ B ∧ C"
  by auto
Output
Failed to finish proof⌂:
goal (1 subgoal):

Read ⟦A; B⟧ ⟹ C as “assuming A and B, show C”; Module 7 explains this notation.

A failed proof cannot tell you whether the formula is false. To find out, ask for a counterexample with one of Isabelle’s two tools for this, Quickcheck and Nitpick:

Isabelle
lemma "A ⟶ B ⟶ A ∧ B ∧ C"
  quickcheck
Output
Testing conjecture with Quickcheck-exhaustive...

Quickcheck found a counterexample:
  A = True
  B = True
  C = False
Isabelle
  nitpick
Output
Nitpicking formula...

  Free variables:
    A = True
    B = True
    C = False
Isabelle
  oops

Both found the same counterexample: A and B true, C false. In that row the formula is T ⟶ T ⟶ F, which is F. Quickcheck tests: it evaluates the formula for one valuation after another until one makes it false. Nitpick searches: it translates the question into a satisfiability problem for a SAT solver (Section 2.8). For propositional formulas both answer at once. On a tautology both come back empty-handed, with “Quickcheck found no counterexample.” and “Nitpick found no counterexample”. Isabelle/jEdit runs Quickcheck automatically on every new lemma, as you saw in Module 1; Nitpick runs only when you call it.

Key idea

A proof shows that a formula is a tautology; a counterexample shows that it is not. A failed proof shows neither, because the method may have been too weak, and “no counterexample found” is not a proof. In Isabelle a question is settled only when by … succeeds or a counterexample appears.

5

Logical equivalence and the laws

A ⟶ B and ¬A ∨ B look different, yet they have the same truth table. Programmers meet the same question whenever they rewrite a condition: is the new if test the same as the old one?

Definition 2.8Logical equivalence

Two formulas φ and ψ are logically equivalent, written φ ≡ ψ and read “φ is equivalent to ψ”, if they have the same truth value under every valuation.

The symbol ≡ is not a connective. φ ≡ ψ is a statement about two formulas, made outside the logic, like “these two programs compute the same function”; the connective ⟷ lives inside formulas. The two are linked:

Fact 2.2Equivalence and ⟷

φ ≡ ψ if and only if φ ⟷ ψ is a tautology.

This holds because φ ⟷ ψ is true in a row exactly when φ and ψ have the same value there. So a truth table with a column for each side checks an equivalence. Here is A ⟶ B ≡ ¬A ∨ B:

ABA ⟶ B¬A ∨ B(A ⟶ B) ⟷ ¬A ∨ B
TTTTT
TFFFT
FTTTT
FFTTT

Tautology: true in every row.

A small set of equivalences, the laws of propositional logic, does most of the everyday work. Each can be checked with a truth table like the one above.

Fact 2.3Laws of equivalence
Law Equivalences
Double negation ¬¬A ≡ A
De Morgan ¬(A ∧ B) ≡ ¬A ∨ ¬B; ¬(A ∨ B) ≡ ¬A ∧ ¬B
Commutativity A ∧ B ≡ B ∧ A; A ∨ B ≡ B ∨ A
Associativity (A ∧ B) ∧ C ≡ A ∧ (B ∧ C); (A ∨ B) ∨ C ≡ A ∨ (B ∨ C)
Distributivity A ∧ (B ∨ C) ≡ (A ∧ B) ∨ (A ∧ C); A ∨ (B ∧ C) ≡ (A ∨ B) ∧ (A ∨ C)
Idempotence A ∧ A ≡ A; A ∨ A ≡ A
Absorption A ∧ (A ∨ B) ≡ A; A ∨ (A ∧ B) ≡ A
Identity A ∧ True ≡ A; A ∨ False ≡ A
Domination A ∧ False ≡ False; A ∨ True ≡ True
Complement A ∧ ¬A ≡ False; A ∨ ¬A ≡ True
Implication A ⟶ B ≡ ¬A ∨ B
Contrapositive A ⟶ B ≡ ¬B ⟶ ¬A
Negated implication ¬(A ⟶ B) ≡ A ∧ ¬B
Exportation A ∧ B ⟶ C ≡ A ⟶ B ⟶ C
Equivalence A ⟷ B ≡ (A ⟶ B) ∧ (B ⟶ A)

The laws are stated with atoms, but they hold for all formulas, and they can be used inside larger formulas:

Fact 2.4Substitution and replacement
  1. Substitution. If a formula is a tautology, replacing an atom everywhere in it by the same formula gives a tautology. Each law of Fact 2.3, written with ⟷, is a tautology (Fact 2.2), so it holds with any formulas in place of A, B and C.
  2. Replacement. If φ ≡ ψ, replacing an occurrence of φ inside a formula by ψ gives an equivalent formula.

Substitution holds because a tautology is true whatever values its atoms take, and so whatever values the substituted formulas take. Replacement holds because the value of a formula depends only on the values of its parts.

Watch out

Three formulas look like A ⟶ B, and only one of them is equivalent to it:

Formula Name Equivalent to A ⟶ B?
¬B ⟶ ¬A contrapositive yes
B ⟶ A converse no

In the same way, ¬(A ∧ B) is equivalent to ¬A ∨ ¬B, not to ¬A ∧ ¬B: negation turns ∧ into ∨ and back.

Check it in Isabelle

In Isabelle, an equivalence is a lemma with ⟷. (Isabelle has a symbol ≡ too, but it uses it for definitions, as Module 7 explains.) blast proves the whole simplification of Example 2.5 in one step:

Isabelle
lemma "¬ (valid ∧ ¬ expired) ∨ expired ⟷ (valid ⟶ expired)"
  by blast

The parentheses around valid ⟶ expired are not needed, since ⟷ and ⟶ group to the right, but write them whenever you mix the two. A wrong law produces a counterexample. Here is the wrong version of De Morgan’s law:

Isabelle

Logical consequence and arguments

Reasoning about systems is full of arguments: if all tests pass, the release is built; the release was not built; so some test failed. An argument has premises and a conclusion, and the question is whether the conclusion must be true when the premises are.

Definition 2.9Logical consequence

A formula ψ is a logical consequence of formulas φ₁, …, φₙ, written

φ1,…,φn⊨ψ\varphi_1, \ldots, \varphi_n \models \psi φ1​,…,φn​⊨ψ

if every valuation that makes all of φ₁, …, φₙ true also makes ψ true. The φᵢ are the premises and ψ is the conclusion; read ⊨ as “entails”. An argument is valid if its conclusion is a logical consequence of its premises. With no premises, ⊨ ψ says that ψ is a tautology.

The symbol ⊨ is about truth. Module 6 introduces its partner ⊢, which is about proof: φ ⊢ ψ says that ψ can be derived from φ by the rules of a proof system. To check an argument with a truth table, look for a bad row: a row in which every premise is true and the conclusion is false. The argument is valid exactly when there is no bad row, which gives a second way to check it:

Fact 2.5Consequence as a tautology

φ₁, …, φₙ ⊨ ψ if and only if φ₁ ∧ … ∧ φₙ ⟶ ψ is a tautology.

The implication is false exactly in the bad rows. Six argument forms come up so often that they have names. Four are valid; the other two are mistakes common enough to be named too.

Name Premises Conclusion Valid?
Modus ponens A ⟶ B, A B yes
Modus tollens A ⟶ B, ¬B ¬A yes
Chaining (hypothetical syllogism) A ⟶ B, B ⟶ C A ⟶ C yes
Disjunctive syllogism A ∨ B, ¬A B yes
Affirming the consequent A ⟶ B, B A no
Denying the antecedent A ⟶ B, ¬A ¬B no

By substitution (Fact 2.4) the valid forms stay valid with any formulas in place of A, B and C.

  2. If all tests pass, the release is built. The release was built. So all tests passed. This is affirming the consequent, and it is invalid. The truth table finds the bad row:

The premises are the columns built and tests ⟶ built, and the conclusion is the column tests. In the row with built = T and tests = F, both premises are true and the conclusion is false: someone built the release by hand although a test failed. One bad row is enough to make an argument invalid.

Good to know

Validity is about the form of an argument, not about the facts. A valid argument with a false premise can have a false conclusion, and an invalid argument can have a true conclusion by luck. When you review a design argument, ask both questions: is the form valid, and are the premises true?

One special case matters a great deal for specifications.

Fact 2.6Inconsistent premises entail everything

If no valuation makes all of φ₁, …, φₙ true, then φ₁, …, φₙ ⊨ ψ for every formula ψ. In particular, A, ¬A ⊨ B.

There is no row in which the premises are all true, so there is no bad row, whatever ψ is. This is the principle of explosion, known by its Latin name ex falso quodlibet: from a falsehood, anything follows.

Key idea

Before you believe that a property follows from a set of requirements, check that the requirements are consistent. From inconsistent requirements every property follows, including its opposite, and every proof succeeds.

Normal forms

Equivalent formulas can look very different, which makes them hard to compare and hard for programs to process. A normal form is a standard shape that every formula can be brought into without changing its meaning. Three are in common use.

Definition 2.10Literal and clause

A literal is an atom or a negated atom, such as A or ¬A. A clause is a disjunction of literals, such as ¬A ∨ B ∨ ¬C; a single literal counts as a clause too.

Definition 2.11Normal forms
  • A formula is in negation normal form (NNF) if it uses only ¬, ∧ and ∨, and every ¬ stands directly in front of an atom.
  • A formula is in conjunctive normal form (CNF) if it is a conjunction of clauses, such as (A ∨ ¬B) ∧ (¬A ∨ C ∨ D) ∧ ¬C.
  • A formula is in disjunctive normal form (DNF) if it is a disjunction of conjunctions of literals, such as (A ∧ ¬B) ∨ (¬A ∧ C) ∨ D.

A CNF is a list of small rules that must all hold: the clause ¬A ∨ ¬B ∨ C says A ∧ B ⟶ C. SAT solvers take their input in CNF. A DNF lists the situations in which the formula is true, so its satisfiability can be read off: a DNF is satisfiable exactly when one of its conjunctions does not contain both an atom and its negation. NNF is the first step towards both.

Negation normal form

Three steps bring any formula into NNF:

  1. Replace each φ ⟷ ψ by (φ ⟶ ψ) ∧ (ψ ⟶ φ).
  2. Replace each φ ⟶ ψ by ¬φ ∨ ψ.
  3. Push each ¬ inwards: replace ¬¬φ by φ, ¬(φ ∧ ψ) by ¬φ ∨ ¬ψ, ¬(φ ∨ ψ) by ¬φ ∧ ¬ψ, ¬True by False and ¬False by True.

Each step replaces a sub-formula by an equivalent one, using the equivalence, implication, double negation and De Morgan laws, so by Fact 2.4 the result is equivalent to the formula you started with.

Conjunctive and disjunctive normal form

From NNF, the distributive laws do the rest:

  • For CNF, move ∨ inside ∧: replace φ ∨ (ψ ∧ χ) by (φ ∨ ψ) ∧ (φ ∨ χ), and (φ ∧ ψ) ∨ χ by (φ ∨ χ) ∧ (ψ ∨ χ), until no ∧ is inside an ∨.
  • For DNF, move ∧ inside ∨: replace φ ∧ (ψ ∨ χ) by (φ ∧ ψ) ∨ (φ ∧ χ), and (φ ∨ ψ) ∧ χ by (φ ∧ χ) ∨ (ψ ∧ χ), until no ∨ is inside an ∧.

Here χ (“chi”) is one more letter for an arbitrary formula. Figure 2.3 shows the whole route.

The door requirement opens ⟶ badge ∧ pin ∨ fire becomes ¬opens ∨ (badge ∧ pin) ∨ fire, which is already in DNF, and distributing gives the CNF (¬opens ∨ badge ∨ fire) ∧ (¬opens ∨ pin ∨ fire). Read back as rules, the two clauses say that when the door opens without a fire, there was a valid badge, and there was the right PIN.

Watch out

Distribution can make formulas explode. Bringing (A₁ ∧ B₁) ∨ (A₂ ∧ B₂) ∨ … ∨ (Aₙ ∧ Bₙ) into CNF by distribution gives 2n2^n2n clauses, one for each way of choosing Aᵢ or Bᵢ from every pair: 8 clauses for three pairs, more than a million for twenty. This is why Isabelle’s simplifier does not use the distributive laws by default. A comment in HOL.thy, next to the list of laws the simplifier does use, says that adding them “might cause exponential blow-up”.

Good to know

SAT solvers avoid the explosion with the Tseitin transformation, which gives each sub-formula a new atom as its name and adds a few clauses that define it. The resulting CNF grows only in proportion to the original formula. It is not equivalent to the original, because it has extra atoms, but it is equisatisfiable: satisfiable if and only if the original is, which is all a SAT solver needs.

Normal forms from truth tables

A truth table gives both normal forms directly.

  • DNF: for each row in which the formula is T, write the conjunction of literals that describes the row (A if A is T in the row, ¬A if A is F), and join these conjunctions with ∨.
  • CNF: for each row in which the formula is F, write the clause that rules the row out (¬A if A is T in the row, A if A is F), and join these clauses with ∧.

Satisfiability and SAT solvers

All the questions of this module come down to one problem.

Definition 2.12The satisfiability problem

The satisfiability problem, SAT for short, asks: given a propositional formula, usually in CNF, is it satisfiable? A SAT solver is a program that answers this question and, when the answer is yes, returns a satisfying valuation.

By Fact 2.1, φ is a tautology exactly when ¬φ is unsatisfiable. By Fact 2.5, φ₁, …, φₙ ⊨ ψ exactly when φ₁ ∧ … ∧ φₙ ∧ ¬ψ is unsatisfiable, because a model of that formula is a bad row. And requirements are consistent exactly when their conjunction is satisfiable. So one SAT solver answers every question of this module.

How hard is SAT? Checking a proposed valuation is quick: evaluate the formula once. Finding one is another matter, since a truth table has 2n2^n2n rows.

Fact 2.8Cook’s theorem

SAT is NP-complete (Stephen Cook, 1971).

NP is the class of yes-or-no problems in which a “yes” can be checked quickly once someone proposes a solution, that is, in a number of steps bounded by a polynomial in the size of the problem. SAT is one of them. So are these: Can the exams be timetabled without clashes? Can this Sudoku be completed? Can these versions of software packages be installed together? A problem is NP-complete if it is in NP and every problem in NP can be translated into it efficiently. SAT was the first problem shown to be NP-complete; Leonid Levin found the same result independently. So a fast (polynomial-time) algorithm for SAT would give fast algorithms for every problem in NP. Nobody knows whether one exists: this is the P versus NP question (P is the class of problems that can be solved in polynomial time), open since 1971 and one of the seven Millennium Prize Problems of the Clay Mathematics Institute.

Even so, SAT solving is one of the great practical successes of computer science. The worst case is exponential, but formulas from real problems have structure, and solvers exploit it. Most solvers descend from the DPLL procedure, named after Davis, Putnam, Logemann and Loveland, who described it in the early 1960s. It works on a CNF and repeats two steps:

  1. Unit propagation. If every literal of a clause but one is false, the remaining literal must be true: set it. Repeat while possible.
  2. Decision. Otherwise, choose an atom without a value and try a value for it.

When a clause becomes false (a conflict), the procedure goes back to its latest decision whose other value it has not tried yet, undoes everything it did after that decision, and tries the other value. If every clause becomes true, the formula is satisfiable; if a conflict leaves no decision to go back to, the formula is unsatisfiable.

Since the late 1990s, solvers have added conflict-driven clause learning (CDCL): after a conflict, the solver works out which decisions caused it and adds a clause that rules out that combination, so the search never makes the same mistake twice. Modern CDCL solvers often decide formulas from industry with hundreds of thousands of atoms and millions of clauses.

Example 2.9Unit propagation

Is this CNF satisfiable?

(A∨B)∧(¬A∨C)∧(¬B∨C)∧(¬C∨D)∧¬D(A \lor B) \land (\lnot A \lor C) \land (\lnot B \lor C) \land (\lnot C \lor D) \land \lnot D (A∨B)∧(¬A∨C)∧(¬B∨C)∧(¬C∨D)∧¬D

The last clause is a single literal, so D = F. Then the clause ¬C ∨ D forces C = F. Then ¬A ∨ C forces A = F, and ¬B ∨ C forces B = F. Now A ∨ B is false: a conflict, reached without a single decision. The formula is unsatisfiable, and the solver has shown it without writing the 16 rows of its truth table.

SAT solvers are at work wherever a problem can be phrased as many yes-or-no choices with constraints between them: checking that two circuits compute the same function, and searching a design for a run that breaks a property within a fixed number of steps (bounded model checking); deciding which software packages can be installed together (the Eclipse development environment resolves the dependencies of its plug-ins with the SAT solver Sat4j); timetables and rosters. SMT solvers, such as Z3 and cvc5 from Module 1, extend SAT solving with numbers, arrays and other data, and power program verifiers. And Isabelle’s Nitpick turns the search for a counterexample into a SAT problem.

Check it in Isabelle

Requirements as propositional constraints

Back to the server-room door. After some discussion, the security team agrees on four requirements:

Requirement Formula
R1 The door opens only if a valid badge is shown and the correct PIN is entered, or the fire alarm is on. opens ⟶ badge ∧ pin ∨ fire
R2 When the fire alarm is on, the door opens. fire ⟶ opens
R3 During a lockdown, the door stays shut. lockdown ⟶ ¬ opens
R4 A valid badge with the correct PIN opens the door. badge ∧ pin ⟶ opens

The atoms badge, pin, fire and lockdown describe the situation: the sensors report them, and the controller cannot choose them. opens is the controller’s decision. Three questions matter:

  1. Are the requirements consistent: can a controller meet them all at once?
  2. Can it meet them in every situation, whatever the sensors report?
  3. Do they guarantee the properties the team cares about?
Definition 2.13Consistent requirements

A set of requirements, written as formulas, is consistent if their conjunction is satisfiable: some valuation makes all of them true.

Consistency

Check it in Isabelle

Nitpick looks for counterexamples, and by Fact 2.1 a counterexample to ¬φ is a model of φ. So to find a model of the requirements, state their negation and ask Nitpick for a counterexample:

Isabelle
lemma "¬ ((opens ⟶ badge ∧ pin ∨ fire) ∧
         (fire ⟶ opens) ∧
         (lockdown ⟶ ¬ opens) ∧
         (badge ∧ pin ⟶ opens))"
  nitpick
  oops
Output
Nitpicking formula...

Nitpick found a counterexample:
  Free variables:
    badge = True
    fire = False
    lockdown = False
    opens = False
    pin = False

The counterexample to the negation is a model of the requirements: with a valid badge, the wrong PIN, no fire and no lockdown, a shut door meets all four. So the requirements are consistent.

Tip

Nitpick can also look for a model directly: nitpick [satisfy] on the requirements themselves (without the ¬) reports “Nitpick found a model”, followed by the valuation.

Situations that break the requirements

One model is not enough: the door must work in every situation, including rare ones. What happens during a lockdown when the fire alarm goes off? Add fire and lockdown to the requirements and ask whether the result is still satisfiable:

Isabelle
lemma "¬ ((opens ⟶ badge ∧ pin ∨ fire) ∧
         (fire ⟶ opens) ∧
         (lockdown ⟶ ¬ opens) ∧
         (badge ∧ pin ⟶ opens) ∧
         fire ∧ lockdown)"
  by blast

Isabelle proves that no valuation satisfies them. In a fire during a lockdown, R2 says that the door must open and R3 that it must stay shut, and no controller can do both. The same happens between R3 and R4 when someone shows a valid badge and the right PIN during a lockdown. Conflicts like these hide in combinations of rare events, which is exactly where testing seldom looks. And in these situations Fact 2.6 applies: from the requirements, Isabelle would prove anything, even that the door is both open and shut. Proofs about inconsistent requirements succeed, and mean nothing.

Repairing the requirements

The conflicts are not mistakes in logic but decisions nobody has made, and only the people who wrote the requirements can make them; this is validation, in the sense of Module 1. Suppose the team decides that people’s safety comes first: a fire overrides a lockdown, and a lockdown overrides badges. R3 and R4 become:

Requirement Formula
R3′ During a lockdown, the door stays shut unless the fire alarm is on. lockdown ∧ ¬ fire ⟶ ¬ opens
R4′ A valid badge with the correct PIN opens the door, except during a lockdown. badge ∧ pin ∧ ¬ lockdown ⟶ opens

Now a stronger check is possible. Together with R1 and R2, the new requirements fix the door’s behaviour completely: they force opens to have the same value as fire ∨ (badge ∧ pin ∧ ¬lockdown).

Isabelle
lemma door_determined:
  "(opens ⟶ badge ∧ pin ∨ fire) ∧
   (fire ⟶ opens) ∧
   (lockdown ∧ ¬ fire ⟶ ¬ opens) ∧
   (badge ∧ pin ∧ ¬ lockdown ⟶ opens)
   ⟶ (opens ⟷ fire ∨ badge ∧ pin ∧ ¬ lockdown)"
  by blast

Conversely, a controller that opens the door exactly when fire ∨ (badge ∧ pin ∧ ¬lockdown) meets all four requirements, whatever the sensors report:

Isabelle
lemma door_rule_ok:
  "(opens ⟷ fire ∨ badge ∧ pin ∧ ¬ lockdown) ⟶
   (opens ⟶ badge ∧ pin ∨ fire) ∧
   (fire ⟶ opens) ∧
   (lockdown ∧ ¬ fire ⟶ ¬ opens) ∧
   (badge ∧ pin ∧ ¬ lockdown ⟶ opens)"
  by blast

The lemma door_rule_ok is verification in miniature. The requirements are the specification, the rule for opens is the implementation, and the proof covers all sixteen situations of the four sensors at once. It also shows that the repaired requirements are consistent in every situation, since in each one the rule’s decision meets them all. The lemma door_determined adds that no other decision would: the requirements leave the controller no choice.

Properties that follow, and one that does not

Finally, the properties. The team wants to be sure that, outside a fire, nobody gets in without the right PIN: opens ∧ ¬ fire ⟶ pin. It follows from the requirements:

Isabelle

       (fire ⟶ opens) ∧
       (lockdown ∧ ¬ fire ⟶ ¬ opens) ∧
       (badge ∧ pin ∧ ¬ lockdown ⟶ opens)
       ⟶ (opens ∧ ¬ fire ⟶ pin)"
  by blast

Isabelle

       (fire ⟶ opens) ∧
       (lockdown ∧ ¬ fire ⟶ ¬ opens) ∧
       (badge ∧ pin ∧ ¬ lockdown ⟶ opens)
       ⟶ (lockdown ⟶ ¬ opens)"
  nitpick
  oops

Nitpick found a counterexample:
  Free variables:
    badge = False
    fire = True
    lockdown = True

The counterexample is a fire during a lockdown, with the door open: exactly the decision the team made. A counterexample is not always a bug. Here it documents a deliberate trade-off in one concrete situation, which is the best way to show it to the people who must accept it. If they did not expect it, the requirements are wrong, not the proof.

Key idea

To analyse requirements with propositional logic: choose atoms, separating what the environment decides from what the system decides; write each requirement as a formula; check that the requirements are consistent, also in the rare situations that matter; prove that the properties you need follow; and read every counterexample as a situation to discuss. Each of these checks is a satisfiability question.

Propositional logic has limits. It cannot say “the door locks again ten seconds after the alarm stops”, which is about time, or “every employee’s badge opens the doors of their own department”, which is about many objects at once. Predicate logic in Module 3 adds objects and quantifiers, and Module 13 models systems that change over time.

What you learned

  • A proposition is true or false. Formulas are built from atoms, True and False with ¬, ∧, ∨, ⟶ and ⟷, by an inductive definition, and each formula has a parse tree.
  • In Isabelle, ¬ binds most tightly, then ∧, then ∨, then ⟶ and ⟷, which share a priority; the binary connectives group to the right. Isabelle prints ⟷ as =. Mix ⟶ and ⟷ only with parentheses.
  • A valuation gives each atom a truth value, and a truth table lists all 2n2^n2n valuations. A ⟶ B is false only when A is true and B false.
  • A formula is a tautology (true in every row), contingent (true in some rows and false in others) or a contradiction (true in none); φ is a tautology exactly when ¬φ is unsatisfiable.
  • φ ≡ ψ when φ ⟷ ψ is a tautology. The laws (De Morgan, distributivity, contrapositive …) transform formulas without changing their meaning.
  • φ₁, …, φₙ ⊨ ψ when no row makes the premises true and ψ false. Modus ponens and modus tollens are valid; affirming the consequent and denying the antecedent are not. Inconsistent premises entail everything.
  • Every formula has an equivalent NNF, CNF and DNF. Distribution can make a CNF exponentially large; the Tseitin transformation avoids that.
  • SAT is NP-complete (Cook, 1971), yet CDCL solvers decide very large formulas in practice.
  • For requirements, consistency is satisfiability, a property follows when requirements ⟶ property is a tautology, and each counterexample is a situation to discuss.
  • In Isabelle, a lemma whose variables have type bool claims a tautology. simp, blast and auto prove tautologies (blast and auto more of them than simp); quickcheck and nitpick find counterexamples; a counterexample to ¬φ is a model of φ.

  1. (A ⟶ B) ∧ (A ⟶ C) ≡ A ⟶ B ∧ C
  2. A ⟶ (B ⟶ C) ≡ B ⟶ (A ⟶ C)

Show solution
  1. (A ⟶ B) ∧ (A ⟶ C) ≡ (¬A ∨ B) ∧ (¬A ∨ C) by implication, twice; ≡ ¬A ∨ (B ∧ C) by distributivity, read from right to left; ≡ A ⟶ B ∧ C by implication.

Exercise 2.5★★Normal forms

Bring each formula into NNF, then into CNF and DNF. Check your answers in Isabelle.

  1. A ⟷ B
  2. ¬(A ∨ B ⟶ C)
Show solution

  2. Find a situation in which they conflict, and prove the conflict in Isabelle. How would you repair the requirements?

Show solution

Exercise 2.7★★★Two connectives are enough
  1. Show that every formula is equivalent to one that uses only ⟶ and False: give such formulas for ¬A, A ∨ B, A ∧ B and A ⟷ B, and check them in Isabelle. Why does this cover every formula?
  2. Show that ∧ and ∨ alone are not enough: no formula built from atoms with ∧ and ∨ only (without ¬, ⟶, ⟷, True or False) is equivalent to ¬A. Hint: what is the value of such a formula when every atom is T?
Show solution
  1. ¬A ≡ A ⟶ False, as the truth tables show. Then A ∨ B ≡ ¬A ⟶ B ≡ (A ⟶ False) ⟶ B, and A ∧ B ≡ ¬(A ⟶ ¬B) ≡ (A ⟶ B ⟶ False) ⟶ False. For ⟷, use A ⟷ B ≡ (A ⟶ B) ∧ (B ⟶ A) and the formula for ∧: ((A ⟶ B) ⟶ (B ⟶ A) ⟶ False) ⟶ False.
Isabelle
lemma "¬ A ⟷ (A ⟶ False)"
  by blast

lemma "A ∨ B ⟷ ((A ⟶ False) ⟶ B)"
  by blast

lemma "A ∧ B ⟷ ((A ⟶ B ⟶ False) ⟶ False)"
  by blast

lemma "(A ⟷ B) ⟷ (((A ⟶ B) ⟶ (B ⟶ A) ⟶ False) ⟶ False)"
  by blast

This covers every formula: by substitution (Fact 2.4) the equivalences hold with any formulas in place of A and B, so you can replace the connectives one at a time, from the inside out, and by replacement each step gives an equivalent formula. True is equivalent to False ⟶ False.

  1. Every formula built from atoms with ∧ and ∨ only is T under the valuation that makes every atom T. Atoms are T under it; and if φ and ψ are T, so are φ ∧ ψ and φ ∨ ψ. Since the formulas are built by these rules and only by them (Definition 2.3), every such formula is T. But ¬A is F under that valuation, so none of them is equivalent to ¬A. Exercise 2.8★★★Knights and knaves

On an island, knights always tell the truth and knaves always lie. You meet two inhabitants, P and Q. P says: “Q is a knave.” Q says: “P and I are of the same kind.” Let p mean “P is a knight” and q “Q is a knight”.

  1. Explain why P’s statement gives the constraint p ⟷ ¬q, and write Q’s statement as a constraint.
  2. Use Nitpick to find out who is a knight and who a knave.
  3. Prove in Isabelle that this is the only solution.
Show solution
  1. If P is a knight, what P says is true; if P is a knave, it is false. So “P says S” means p ⟷ S. P says ¬q, which gives p ⟷ ¬q. Q says that P and Q are of the same kind, p ⟷ q, which gives q ⟷ (p ⟷ q).
  2. A counterexample to the negation of the constraints is a model of them:
Isabelle
lemma "¬ ((p ⟷ ¬ q) ∧ (q ⟷ (p ⟷ q)))"
  nitpick
  oops
Output
Nitpicking formula...

Nitpick found a counterexample:
  Free variables:
    p = True
    q = False

P is a knight and Q is a knave. Check: P truthfully says that Q is a knave, and Q falsely claims that the two are of the same kind.

  1. The constraints imply this solution:
Isabelle
lemma "(p ⟷ ¬ q) ∧ (q ⟷ (p ⟷ q)) ⟶ p ∧ ¬ q"
  by blast

Q’s constraint alone already forces p: q ⟷ (p ⟷ q) is equivalent to p. If p is true, p ⟷ q has the same value as q, so the constraint is true; if p is false, p ⟷ q has the opposite value to q, so the constraint is false. With p true, P’s constraint p ⟷ ¬q makes q false.

Check yourself

1
How does Isabelle read ¬A ∧ B ⟶ C?
¬ binds most tightly, then ∧, then ⟶. So ¬ applies to A alone, ∧ joins ¬A and B, and ⟶ is the main connective.
2
When is A ⟶ B false?
An implication is broken only when its antecedent holds and its consequent does not. When A is false, A ⟶ B is vacuously true.
3
A formula φ and its negation ¬φ are both satisfiable. What is φ?
φ satisfiable means some row makes φ true; ¬φ satisfiable means some row makes φ false. So φ is neither a tautology nor a contradiction.
4
Which argument form is invalid?
This is affirming the consequent. The row A = F, B = T makes both premises true and the conclusion false.
5
by simp fails on a lemma about a propositional formula. What do you know?
A failed proof is not a counterexample: simp fails on Peirce’s law, which is a tautology. Only a successful proof or a counterexample settles the question.
6
Nitpick finds a counterexample to ¬(R1 ∧ R2 ∧ R3). What does that show?
A counterexample to ¬(R1 ∧ R2 ∧ R3) makes that negation false, so it makes R1 ∧ R2 ∧ R3 true. It is a model of the requirements, which shows that they can all hold at once.
