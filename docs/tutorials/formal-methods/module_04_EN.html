Module 4Sets, relations and functions

Describe collections with sets, connect their elements with relations, find the states a system can reach, compare the sizes of sets with functions, and see why some infinite sets are larger than others, with examples and proofs checked in Isabelle.

Sets

Specifications talk about collections all the time: the users who may read a file, the states a system can reach, the messages in transit. Mathematics has one notion for all of them, the set, and many specification languages are built on it: Z and B on set theory, Alloy on relations, TLA+ on sets and functions. This module builds the vocabulary in layers: sets, then relations, which connect elements, then functions, and finally the sizes of sets. Everything rests on the logic of Modules 2 and 3; you will see that the laws of sets are laws of logic in disguise. For more practice with the mathematics, see “Sets, relations, and discrete structures” in Mathematical Foundations.

Elements and set-builder notation

A set is a collection of things, called its elements, determined entirely by which things belong to it. x∈Ax \in Ax∈A reads “x is an element of A”, or “x is in A”; x∉Ax \notin Ax∈/A reads “x is not in A” and abbreviates ¬(x∈A)\lnot (x \in A)¬(x∈A)⁠.

There are two ways to describe a set. A listing names its elements between braces: {2,3,5,7}\{2, 3, 5, 7\}{2,3,5,7}⁠. Set-builder notation describes them by a property: {x.  P x}\{x.\; P\,x\}{x.Px} reads “the set of all x such that P x”. The primes below 10 form the set {x.  x is prime∧x<10}\{x.\; x \text{ is prime} \land x < 10\}{x.x is prime∧x<10}⁠, which is {2,3,5,7}\{2, 3, 5, 7\}{2,3,5,7} again. Many books write {x∣P(x)}\{x \mid P(x)\}{x∣P(x)}⁠; this series writes {x.  P x}\{x.\; P\,x\}{x.Px}⁠, as Isabelle does. A common variant takes the elements from a given set: {x∈A.  P x}\{x \in A.\; P\,x\}{x∈A.Px} means {x.  x∈A∧P x}\{x.\; x \in A \land P\,x\}{x.x∈A∧Px}⁠.

Set-builder notation connects sets with the predicates of Module 3. Something belongs to {x.  P x}\{x.\; P\,x\}{x.Px} exactly when it has the property PPP⁠:

a∈{x.  P x}⟷P aa \in \{x.\; P\,x\} \iff P\,a a∈{x.Px}⟷Pa

So a set and a predicate carry the same information. In Isabelle/HOL, a set of elements of some type is, in effect, a predicate on that type.

Definition 4.1Set

A set is a collection of elements; x∈Ax \in Ax∈A means that xxx is an element of AAA⁠. A set can be given by a listing such as {1,2,3}\{1, 2, 3\}{1,2,3}⁠, or by set-builder notation {x.  P x}\{x.\; P\,x\}{x.Px}⁠, the set of all xxx for which P xP\,xPx holds. In Isabelle/HOL every set has an element type: a set of natural numbers has type nat set, and all its elements are natural numbers.

When are two sets equal? When they have the same elements. Nothing else counts: not the order in which you list them, not how you describe them.

Definition 4.2Extensionality

Two sets are equal when they have the same elements:

A=B⟷(∀x.  x∈A⟷x∈B)A = B \iff (\forall x.\; x \in A \iff x \in B) A=B⟷(∀x.x∈A⟷x∈B)

So {1,2,3}={3,1,2}={1,1,2,3}\{1, 2, 3\} = \{3, 1, 2\} = \{1, 1, 2, 3\}{1,2,3}={3,1,2}={1,1,2,3}⁠, and {x.  x∈Z∧x2=1}={−1,1}\{x.\; x \in \Z \land x^2 = 1\} = \{-1, 1\}{x.x∈Z∧x2=1}={−1,1}⁠.

Definition 4.3Subset, empty set, universe

AAA is a subset of BBB⁠, written A⊆BA \subseteq BA⊆B⁠, when every element of AAA is an element of BBB⁠: ∀x.  x∈A⟶x∈B\forall x.\; x \in A \imp x \in B∀x.x∈A⟶x∈B⁠. It is a proper subset, A⊂BA \subset BA⊂B⁠, when also A≠BA \neq BA=B⁠. The empty set ∅\emptyset∅ has no elements; Isabelle writes it {}. The universe contains every element of the type; Isabelle calls it UNIV.

Fact 4.1Subsets and equality

For all sets AAA and BBB⁠:

  1. ∅⊆A\emptyset \subseteq A∅⊆A and A⊆AA \subseteq AA⊆A⁠.
  2. A=B⟷A⊆B∧B⊆AA = B \iff A \subseteq B \land B \subseteq AA=B⟷A⊆B∧B⊆A⁠.

For the first, x∈∅x \in \emptysetx∈∅ is false for every xxx⁠, so x∈∅⟶x∈Ax \in \emptyset \imp x \in Ax∈∅⟶x∈A is vacuously true (Module 2); vacuous truth will come back in this module. And x∈A⟶x∈Ax \in A \imp x \in Ax∈A⟶x∈A holds whatever xxx is. The second combines extensionality with the law (p⟷q)⟷(p⟶q)∧(q⟶p)(p \iff q) \iff (p \imp q) \land (q \imp p)(p⟷q)⟷(p⟶q)∧(q⟶p)⁠. It is also how you usually prove two sets equal: show that each is a subset of the other.

Because HOL is typed (Module 3), a universe is always the universe of one type: UNIV :: bool set is {True,False}\{\mathit{True}, \mathit{False}\}{True,False}⁠, and UNIV :: nat set contains all natural numbers. There is no set of absolutely everything, and Section 4.7 shows why that is a good thing.

Example 4.1Who may do what

A file server has the users alice, bob, carol and dave. Those who may read a certain file form the set R={alice,bob,carol}R = \{\mathit{alice}, \mathit{bob}, \mathit{carol}\}R={alice,bob,carol}⁠, those who may write it W={bob,dave}W = \{\mathit{bob}, \mathit{dave}\}W={bob,dave}⁠, and the administrators D={bob}D = \{\mathit{bob}\}D={bob}⁠. Then D⊆WD \subseteq WD⊆W holds: every administrator may write. The policy “writers must be able to read” is the statement W⊆RW \subseteq RW⊆R⁠, and it is violated, with dave as the witness: dave∈W\mathit{dave} \in Wdave∈W but dave∉R\mathit{dave} \notin Rdave∈/R⁠.

Watch out

Keep ∈\in∈ and ⊆\subseteq⊆ apart. 1∈{1,2}1 \in \{1, 2\}1∈{1,2} is about an element, {1}⊆{1,2}\{1\} \subseteq \{1, 2\}{1}⊆{1,2} about a set, and both are true. In HOL, {1}∈{1,2}\{1\} \in \{1, 2\}{1}∈{1,2} is not even false: it is a type error, because the elements of {1,2}\{1, 2\}{1,2} are numbers and {1}\{1\}{1} is a set. In the same way, ∅\emptyset∅ and {∅}\{\emptyset\}{∅} differ: the first has no elements, the second has one.

Definition 4.5Power set

The power set P(A)\pow(A)P(A) of a set AAA is the set of all its subsets: P(A)={B.  B⊆A}\pow(A) = \{B.\; B \subseteq A\}P(A)={B.B⊆A}⁠. Isabelle writes Pow A.

Fact 4.2Set laws from propositional laws

Translate an equation between sets built with ∪\cup∪⁠, ∩\cap∩⁠, −-− and complement into propositional logic: replace each set AAA by a proposition pAp_ApA​ that stands for “x∈Ax \in Ax∈A”, ∪\cup∪ by ∨\lor∨⁠, ∩\cap∩ by ∧\land∧⁠, A−BA - BA−B by pA∧¬pBp_A \land \lnot p_BpA​∧¬pB​⁠, complement by ¬\lnot¬⁠, ∅\emptyset∅ by False\mathit{False}False and UNIV\mathit{UNIV}UNIV by True\mathit{True}True⁠. The equation holds for all sets exactly when the two formulas are equivalent, that is, when their biconditional is a tautology.

If the formulas are equivalent, every xxx is in the left set exactly when it is in the right one, and extensionality makes the sets equal. If they are not, the truth table has a row where they differ: put a single element xxx into exactly those sets whose propositions are true in that row, and xxx is in one side but not the other. So a falsifying row is a counterexample with one element.

Isabelle
  by auto

auto does what the paper proof did: it applies extensionality, replaces each membership by its definition and finishes with propositional reasoning. blast works as well; on sets these two are the usual tools.

Relations

A set says which things there are. A relation says how they are connected: which user has which role, which function calls which, which state of a system can follow which.

Pairs and products

An ordered pair (a,b)(a, b)(a,b) has a first component aaa and a second component bbb⁠. Unlike a set, a pair has an order: (1,2)≠(2,1)(1, 2) \neq (2, 1)(1,2)=(2,1)⁠, although {1,2}={2,1}\{1, 2\} = \{2, 1\}{1,2}={2,1}⁠. Two pairs are equal when their components are: (a,b)=(c,d)⟷a=c∧b=d(a, b) = (c, d) \iff a = c \land b = d(a,b)=(c,d)⟷a=c∧b=d⁠. In Isabelle a pair (a, b) has a type such as nat × string, read “nat times string”.

Definition 4.6Cartesian product

The Cartesian product of AAA and BBB is the set of all pairs whose first component is in AAA and whose second component is in BBB⁠:

A×B={(a,b).  a∈A∧b∈B}A \times B = \{(a, b).\; a \in A \land b \in B\} A×B={(a,b).a∈A∧b∈B}

For example, {1,2}×{x,y}={(1,x),(1,y),(2,x),(2,y)}\{1, 2\} \times \{x, y\} = \{(1, x), (1, y), (2, x), (2, y)\}{1,2}×{x,y}={(1,x),(1,y),(2,x),(2,y)}⁠. A product of finite sets has ∣A∣⋅∣B∣|A| \cdot |B|∣A∣⋅∣B∣ elements, where ∣A∣|A|∣A∣ is the number of elements of AAA⁠. A database table with the columns name and age is a subset of Names×Ages\mathit{Names} \times \mathit{Ages}Names×Ages⁠.

Relations as sets of pairs

Definition 4.7Relation

A (binary) relation from AAA to BBB is a subset R⊆A×BR \subseteq A \times BR⊆A×B⁠; a relation on AAA is a subset of A×AA \times AA×A⁠. Instead of (x,y)∈R(x, y) \in R(x,y)∈R one also writes xRyx \mathrel{R} yxRy⁠, “x is related to y by R”. In Isabelle a relation on a type 'a has the type 'a rel, short for ('a × 'a) set.

Equivalence relations and partitions

Specifications often care about things only up to some detail: two account numbers may belong to the same customer, two inputs may have to be treated alike, two times may show the same position on a clock. “Has the same … as” relations share three properties.

Definition 4.10Equivalence relation and class

Definition 4.11Partition

A partition of AAA is a set of non-empty subsets of AAA⁠, its blocks, such that every element of AAA is in exactly one block: the blocks are pairwise disjoint and their union is AAA⁠.

Fact 4.4Equivalence relations and partitions

The equivalence classes of an equivalence relation on AAA form a partition of AAA⁠. Conversely, every partition of AAA defines an equivalence relation, “is in the same block as”, whose classes are the blocks.

Here is the proof of the first half. The classes are subsets of AAA⁠, because RRR is a relation on AAA⁠. Reflexivity puts every xxx into its own class, so the classes are non-empty and cover AAA⁠. It remains to show that two classes that meet are equal. Suppose zzz is in [x][x][x] and in [y][y][y]⁠, so (x,z)∈R(x, z) \in R(x,z)∈R and (y,z)∈R(y, z) \in R(y,z)∈R⁠. By symmetry (z,y)∈R(z, y) \in R(z,y)∈R⁠, and by transitivity (x,y)∈R(x, y) \in R(x,y)∈R⁠. Now for any w∈[y]w \in [y]w∈[y]⁠, transitivity turns (x,y)(x, y)(x,y) and (y,w)(y, w)(y,w) into (x,w)(x, w)(x,w)⁠, so w∈[x]w \in [x]w∈[x]⁠. Hence [y]⊆[x][y] \subseteq [x][y]⊆[x]⁠; the same argument with xxx and yyy swapped gives [x]⊆[y][x] \subseteq [y][x]⊆[y]⁠, and Fact 4.1 gives [x]=[y][x] = [y][x]=[y]⁠. For the second half: every element is in some block (reflexive), the wording is symmetric, and two blocks that share an element are the same block (transitive).

Equivalence relations appear wherever software ignores a detail. Equivalence partitioning, a standard way of designing tests, splits the inputs into classes that the program should treat alike (parcels up to 1 kg, up to 5 kg, heavier) and tests one representative of each, plus the boundaries. Orders and well-foundedness

Orders compare things: version numbers, priorities, deadlines, “must happen before” in a schedule. Some compare any two elements; many do not.

Partial and total orders

Definition 4.12Partial, total and strict orders

A partial order on AAA is a relation on AAA that is reflexive on AAA⁠, antisymmetric and transitive. A total order (or linear order) is a partial order that is also total on AAA⁠. A strict order is a relation that is irreflexive and transitive.

Partial orders are usually written ≤\le≤ and strict orders <<<⁠, and each gives the other: x<y⟷x≤y∧x≠yx < y \iff x \le y \land x \neq yx<y⟷x≤y∧x=y⁠, and x≤y⟷x<y∨x=yx \le y \iff x < y \lor x = yx≤y⟷x<y∨x=y⁠. A strict order is asymmetric: x<yx < yx<y and y<xy < xy<x would give x<xx < xx<x by transitivity, which irreflexivity forbids.

Example 4.7Orders, total and partial
  • ≤\le≤ on numbers is a total order.
  • ⊆\subseteq⊆ on P(A)\pow(A)P(A) is a partial order. If AAA contains two different elements, it is not total: for example, when 1,2∈A1, 2 \in A1,2∈A⁠, {1}\{1\}{1} and {2}\{2\}{2} are incomparable, as neither is a subset of the other. If AAA has at most one element, its subsets do form a total order.
  • Divisibility on the positive integers, a∣ba \mid ba∣b when b=k⋅ab = k \cdot ab=k⋅a for some integer kkk⁠, is a partial order, and 2 and 3 are incomparable.

Hasse diagrams

The graph of a partial order has many arrows: a loop at every node, and a shortcut for every path. A Hasse diagram of a partial order on a finite set leaves out what the properties imply. It puts smaller elements lower, draws no loops and no arrowheads, and draws a line from xxx up to yyy only when yyy covers xxx⁠: x<yx < yx<y with nothing strictly between them. Then x≤yx \le yx≤y exactly when an upward path leads from xxx to yyy⁠, allowing a path of zero edges when x=yx = yx=y⁠.

In a partial order, mmm is minimal when no element is strictly below it, and least when it is below every element; maximal and greatest are the same notions upside down. In Figure 4.2, ∅\emptyset∅ and 1 are least, {1,2,3}\{1, 2, 3\}{1,2,3} and 12 greatest. A partial order can have several minimal elements and no least one: in {2,3,4,6}\{2, 3, 4, 6\}{2,3,4,6} ordered by divisibility, 2 and 3 are minimal, 4 and 6 maximal. In a project plan with no cyclic dependencies, “is a prerequisite of” is a strict order; adding equality gives a partial order. Its minimal tasks have no unfinished prerequisites. Listing tasks in an order that respects the dependencies, a topological sort, gives a valid dependency order; durations and resource constraints are further scheduling questions.

Well-founded relations

On the natural numbers, every descending chain n>m>k>…n > m > k > \dotsn>m>k>… stops after at most nnn steps. On the integers, 0>−1>−2>…0 > -1 > -2 > \dots0>−1>−2>… never stops. This difference is what makes induction and termination proofs work.

Definition 4.13Well-founded relation

Read (y,x)∈R(y, x) \in R(y,x)∈R as “yyy is smaller than xxx”. RRR is well-founded when there is no infinite descending chain: no infinite sequence x0,x1,x2,…x_0, x_1, x_2, \dotsx0​,x1​,x2​,… with (xi+1,xi)∈R(x_{i+1}, x_i) \in R(xi+1​,xi​)∈R for every iii⁠.

Equivalently, a fact this series uses without proof, every non-empty set SSS has an RRR-minimal element: some m∈Sm \in Sm∈S such that no y∈Sy \in Sy∈S has (y,m)∈R(y, m) \in R(y,m)∈R⁠.

  • <<< on N\NN is well-founded. <<< on Z\ZZ is not, nor is <<< on the non-negative fractions: 1>12>14>…1 > \tfrac{1}{2} > \tfrac{1}{4} > \dots1>21​>41​>… never stops.
  • A well-founded relation is irreflexive, since (x,x)∈R(x, x) \in R(x,x)∈R gives the chain x,x,x,…x, x, x, \dotsx,x,x,…⁠. So <<< on N\NN is well-founded and ≤\le≤ is not.
  • A relation on a finite set is well-founded exactly when it has no cycle. (The library proves this as wf_iff_acyclic_if_finite.)
Key idea

Well-founded relations are why programs terminate and why induction is sound.

  • Termination. If each iteration of a loop, or each recursive call, moves to a smaller value in a well-founded relation, the computation stops: an infinite computation would be an infinite descending chain, provided the work between decreases also terminates. Euclid’s algorithm returns mmm when n=0n = 0n=0⁠; otherwise it makes the recursive call gcd n (m mod n). Its second argument decreases because m mod n<nm \bmod n < nmmodn<n whenever n>0n > 0n>0⁠. When you define a function with fun, Isabelle looks for such a relation; that is the “termination order” it reported in Module 1.
  • Induction. To prove P xP\,xPx for all xxx⁠, it suffices to prove P xP\,xPx assuming that PPP holds for everything smaller than xxx (this proof is the induction step). If PPP failed somewhere, the counterexamples would have a minimal element mmm⁠; PPP holds below mmm⁠, so the induction step proves P mP\,mPm⁠, a contradiction.

A relation often lacks a property you need. “calls” is not transitive, but “can call, directly or indirectly” is; “can move in one step” is not, but “can reach” is. A closure adds the pairs that are missing, and nothing else.

Reachability in a state machine

Module 1 described model checkers, which explore every reachable state of a system. Reachability is the reflexive-transitive closure.

Definition 4.15State machine and reachability

A state machine consists of a set of states, a set III of initial states, and a transition relation TTT⁠: (s,t)∈T(s, t) \in T(s,t)∈T when the system can move from sss to ttt in one step. The reachable states are those ttt with (s,t)∈T∗(s, t) \in T^*(s,t)∈T∗ for some s∈Is \in Is∈I⁠, that is, the image T∗[I]T^*[I]T∗[I]⁠. A safety property says that no reachable state is bad.

Example 4.9A door with a lock

A door is open or closed, and its bolt locked or unlocked: four states, CL (closed and locked), CU (closed, unlocked), OU (open, unlocked) and OL (open and locked). OL is bad: the bolt sticks out of an open door and will damage the frame. The transitions are unlock (CL to CU), lock (CU to CL), open (CU to OU) and close (OU to CU), and the door starts in CL.

From CL the door can only go to CU, from CU to CL or OU, and from OU back to CU. So the reachable states are CL, CU and OU, and the safety property “the door is never open and locked” holds. Now suppose a designer makes the lock button work in every state. That adds a transition from OU to OL, and OL becomes reachable along CL, CU, OU, OL: a counterexample trace, the kind of answer a model checker gives when a property fails.

Real systems have billions of states, or infinitely many, which is why model checkers compute reachability by machine and why Module 13 proves safety properties with invariants instead.

Functions

Mathematically, a function is a relation in which every input has exactly one output.

Functions as relations

Definition 4.16Function

A function fff from AAA to BBB⁠, written f:A→Bf : A \to Bf:A→B⁠, is a relation f⊆A×Bf \subseteq A \times Bf⊆A×B in which every a∈Aa \in Aa∈A is related to exactly one b∈Bb \in Bb∈B⁠, written f a=bf\,a = bfa=b⁠. AAA is the domain of fff and BBB its codomain. The image of a set S⊆AS \subseteq AS⊆A is f[S]={f a.  a∈S}f[S] = \{f\,a.\; a \in S\}f[S]={fa.a∈S}⁠, and the image of the whole domain is the range of fff⁠.

The codomain says where the values may lie, the range where they do lie: for squaring on N\NN⁠, the codomain is N\NN and the range is {0,1,4,9,… }\{0, 1, 4, 9, \dots\}{0,1,4,9,…}⁠.

In HOL, functions are not sets of pairs: nat ⇒ nat is a type of its own (Module 1), and its elements are written with λ\lambdaλ⁠. λn. 2 * n is the function that takes n to 2 * n, written n↦2nn \mapsto 2nn↦2n in mathematics (type \lambda or %). Every HOL function is total: it has a value for every element of its argument type. (This sense of “total” has nothing to do with the total relations of Section 4.2.) A relation in which every input has at most one output is a partial function, such as the input-output relation of a deterministic program that may not return a result. A mathematical partial function can be represented in HOL by a total function returning the type option of Module 8: either a value or None. This representation records undefinedness; it does not make a potentially non-terminating program executable as a terminating HOL function. Isabelle writes the image of a set as f ` A (one backquote) and the range as range f.

Injective, surjective, bijective

Definition 4.17Injective, surjective, bijective

A function f:A→Bf : A \to Bf:A→B is

  • injective (one-to-one) when different inputs give different outputs: ∀x∈A.  ∀y∈A.  f x=f y⟶x=y\forall x \in A.\; \forall y \in A.\; f\,x = f\,y \imp x = y∀x∈A.∀y∈A.fx=fy⟶x=y⁠;
  • surjective (onto BBB⁠) when every element of BBB is an output: ∀b∈B.  ∃a∈A.  f a=b\forall b \in B.\; \exists a \in A.\; f\,a = b∀b∈B.∃a∈A.fa=b⁠, that is, f[A]=Bf[A] = Bf[A]=B⁠;
  • bijective when it is both: it pairs the elements of AAA and BBB one to one.
Example 4.10Four functions on numbers
  • n↦2nn \mapsto 2nn↦2n on N\NN is injective, since 2x=2y2x = 2y2x=2y implies x=yx = yx=y⁠, but not surjective: 1 is not an output.
  • n↦ndiv⁡2n \mapsto n \operatorname{div} 2n↦ndiv2 on N\NN (division rounding down) is surjective but not injective: 0 and 1 both give 0.
  • n↦n+1n \mapsto n + 1n↦n+1 on N\NN is injective but not surjective: 0 is not an output.
  • n↦n+1n \mapsto n + 1n↦n+1 on Z\ZZ is bijective: every integer mmm is the output for exactly one input, m−1m - 1m−1⁠.

The last two have the same formula and different properties: surjectivity depends on the domain and codomain. In software, injectivity means “no collisions”. For example, for a fixed key, deterministic encryption with exact decryption must map different plaintexts to different ciphertexts; otherwise decryption could not recover both messages correctly.

Inverses and composition

Definition 4.18Composition and inverse

The composition of f:A→Bf : A \to Bf:A→B and g:B→Cg : B \to Cg:B→C is g∘f:A→Cg \circ f : A \to Cg∘f:A→C⁠, with (g∘f) x=g (f x)(g \circ f)\,x = g\,(f\,x)(g∘f)x=g(fx)⁠: first fff⁠, then ggg⁠, read “g after f”. A function g:B→Ag : B \to Ag:B→A is an inverse of fff when g (f a)=ag\,(f\,a) = ag(fa)=a for all a∈Aa \in Aa∈A and f (g b)=bf\,(g\,b) = bf(gb)=b for all b∈Bb \in Bb∈B⁠.

Fact 4.5Composition and inverses
  1. If fff and ggg are injective, so is g∘fg \circ fg∘f⁠; if they are surjective, so is g∘fg \circ fg∘f⁠. So the composition of two bijections is a bijection.
  2. A function has an inverse exactly when it is bijective. The inverse is then unique, written f−1f^{-1}f−1⁠, and its graph is the converse of the graph of fff⁠.
  3. For bijections, (g∘f)−1=f−1∘g−1(g \circ f)^{-1} = f^{-1} \circ g^{-1}(g∘f)−1=f−1∘g−1⁠.

For injectivity in the first part: if g (f x)=g (f y)g\,(f\,x) = g\,(f\,y)g(fx)=g(fy)⁠, then f x=f yf\,x = f\,yfx=fy because ggg is injective, and x=yx = yx=y because fff is. The third part is the socks-and-shoes rule: socks go on first and come off last. A message that was compressed and then encrypted is decrypted first.

Counting: cardinality and Cantor’s theorem

For finite sets you count. For infinite sets you cannot, but you can still compare sizes with functions, and the comparison holds a surprise.

Finite sets

Definition 4.19Cardinality

The cardinality ∣A∣|A|∣A∣ of a finite set AAA is its number of elements. Isabelle writes card A, and finite A for “A is finite”.

Fact 4.6Counting rules

For finite sets AAA and BBB⁠:

  1. ∣A∪B∣=∣A∣+∣B∣−∣A∩B∣|A \cup B| = |A| + |B| - |A \cap B|∣A∪B∣=∣A∣+∣B∣−∣A∩B∣⁠, so ∣A∪B∣=∣A∣+∣B∣|A \cup B| = |A| + |B|∣A∪B∣=∣A∣+∣B∣ when AAA and BBB are disjoint.
  2. ∣A×B∣=∣A∣⋅∣B∣|A \times B| = |A| \cdot |B|∣A×B∣=∣A∣⋅∣B∣ and ∣P(A)∣=2∣A∣|\pow(A)| = 2^{|A|}∣P(A)∣=2∣A∣⁠.
  3. If there is an injective function from AAA to BBB⁠, then ∣A∣≤∣B∣|A| \le |B|∣A∣≤∣B∣⁠; if there is a bijection, then ∣A∣=∣B∣|A| = |B|∣A∣=∣B∣⁠.

The first rule is inclusion–exclusion: ∣A∣+∣B∣|A| + |B|∣A∣+∣B∣ counts the elements of A∩BA \cap BA∩B twice. On the file server, ∣R∪W∣=3+2−1=4|R \cup W| = 3 + 2 - 1 = 4∣R∪W∣=3+2−1=4⁠. The third rule compares sizes without counting, by pairing off elements, and that idea still works for infinite sets.

The pigeonhole principle

Fact 4.7The pigeonhole principle

If AAA and BBB are finite and ∣A∣>∣B∣|A| > |B|∣A∣>∣B∣⁠, then no function f:A→Bf : A \to Bf:A→B is injective: two different elements of AAA have the same image. When BBB is non-empty, every function f:A→Bf : A \to Bf:A→B maps at least ⌈∣A∣/∣B∣⌉\lceil |A| / |B| \rceil⌈∣A∣/∣B∣⌉ elements of AAA to some one element of BBB⁠. If BBB is empty and AAA is not, there is no function A→BA \to BA→B at all.

If more pigeons than holes fly into the holes, some hole holds two pigeons. Among any 13 people, two were born in the same month. A hash table with 1000 keys and 256 buckets has a bucket with at least ⌈1000/256⌉=4\lceil 1000/256 \rceil = 4⌈1000/256⌉=4 keys, whatever the hash function. And no lossless compression program makes every file shorter: there are 2n2^n2n files of nnn bits but only 20+21+⋯+2n−1=2n−12^0 + 2^1 + \dots + 2^{n-1} = 2^n - 120+21+⋯+2n−1=2n−1 shorter ones, so two files would get the same compressed form.

Countable sets

For infinite sets, take the third counting rule as the definition: two sets have the same cardinality when there is a bijection between them. Strange things happen at once: n↦2nn \mapsto 2nn↦2n is a bijection from N\NN to the even numbers, so a proper subset of N\NN is as large as N\NN itself.

Definition 4.20Countable set

A set AAA is countable when there is an injective function from AAA to N\NN⁠. Equivalently, AAA is finite or its elements can be listed as a0,a1,a2,…a_0, a_1, a_2, \dotsa0​,a1​,a2​,…⁠, each appearing somewhere in the list.

The integers are countable: list them as 0,1,−1,2,−2,…0, 1, -1, 2, -2, \dots0,1,−1,2,−2,…⁠. So are the pairs of natural numbers, listed diagonal by diagonal: (0,0)(0, 0)(0,0)⁠, (0,1)(0, 1)(0,1)⁠, (1,0)(1, 0)(1,0)⁠, (0,2)(0, 2)(0,2)⁠, (1,1)(1, 1)(1,1)⁠, (2,0)(2, 0)(2,0)⁠, … . So are the finite strings over a finite alphabet, listed by length and then alphabetically; in particular, the programs of any programming language form a countable set. Is every set countable, then? No, and the proof is one of the most famous in mathematics.

Cantor’s theorem

Fact 4.8Cantor’s theorem

For every set AAA⁠, no function f:A→P(A)f : A \to \pow(A)f:A→P(A) is surjective.

Since a↦{a}a \mapsto \{a\}a↦{a} is injective, P(A)\pow(A)P(A) is at least as large as AAA⁠; Cantor’s theorem says it is strictly larger. Georg Cantor published the proof, the diagonal argument, in 1891.

Take any f:A→P(A)f : A \to \pow(A)f:A→P(A)⁠. Each f xf\,xfx is a set that may or may not contain xxx itself. Collect the elements that are not in their own set:

D={x∈A.  x∉f x}D = \{x \in A.\; x \notin f\,x\} D={x∈A.x∈/fx}

D⊆AD \subseteq AD⊆A⁠, so D∈P(A)D \in \pow(A)D∈P(A)⁠. Suppose fff were surjective. Then D=f dD = f\,dD=fd for some d∈Ad \in Ad∈A⁠. Is ddd in DDD⁠? The first step below is the definition of DDD (it applies because d∈Ad \in Ad∈A⁠); the second replaces f df\,dfd by DDD⁠, which is equal to it:

So d∈D⟷d∉Dd \in D \iff d \notin Dd∈D⟷d∈/D⁠, and a proposition equivalent to its own negation is impossible:

The assumption that fff is surjective has led to a contradiction, so it is false: no ddd has f d=Df\,d = Dfd=D⁠, and fff is not surjective. Figure 4.4 shows where the name comes from.

A subset of N\NN describes a decision problem, such as “is this number prime?”. A program decides such a set only if it halts with the correct yes-or-no answer on every input. There are countably many programs, so at most countably many decidable sets, while P(N)\pow(\N)P(N) is uncountable. Thus undecidable problems must exist. This is a counting argument: it does not give an algorithm that lists exactly the programs which halt on every input. Turing’s proof that the halting problem is undecidable (Module 1) is a diagonal argument too.

Good to know

Bertrand Russell found in 1901 that the same trick breaks naive set theory, which lets every property define a set: then R={x.  x∉x}R = \{x.\; x \notin x\}R={x.x∈/x}⁠, the set of all sets that are not elements of themselves, would be a set, and R∈R⟷R∉RR \in R \iff R \notin RR∈R⟷R∈/R⁠. HOL avoids the paradox with types: x ∈ x is a type error, because a set and its elements have different types, and for the same reason there is no set of everything (Section 4.1).

What you learned

  • A set is determined by its elements (extensionality), and a∈{x.  P x}⟷P aa \in \{x.\; P\,x\} \iff P\,aa∈{x.Px}⟷Pa⁠. In HOL every set has an element type.
  • Union, intersection, difference and complement are ∨\lor∨⁠, ∧\land∧⁠, “and not” and ¬\lnot¬ applied to membership, so set laws are propositional laws, which Isabelle proves with auto.
  • A relation is a set of pairs. It can be reflexive, irreflexive, symmetric, antisymmetric, transitive or total; a property fails exactly when a witness exists. Converse and composition build new relations.
  • Equivalence relations correspond to partitions. Partial orders are drawn as Hasse diagrams. Well-founded relations have no infinite descending chains, which is why programs terminate and induction works.
  • The closures R+R^+R+ and R∗R^*R∗ (r⇧+, r⇧*) add the pairs joined by paths, and the reachable states of a state machine are the image of its initial states under T∗T^*T∗⁠.
  • A function can be injective, surjective, both (bijective), or neither. It has a two-sided inverse exactly when it is bijective. Isabelle’s inv is defined more generally; inverse laws require the appropriate assumptions (inj, surj, bij).
  • Cardinality counts finite sets (card, finite). The pigeonhole principle forbids injections into smaller sets, and Cantor’s diagonal argument shows that no set can be mapped onto its power set: some sets are uncountable, and some problems have no program.
