## 后训练的用途 {#s1}

基座模型预测文本的下一个 token。它可以续写熟悉的工程解释、重复表头，或模仿问答。这些能力并未规定助手应如何行动。模型还需要学习哪个轮次属于自己、请求如何约束回答、何时结束，以及所需证据缺失时该怎么办。这些行为正是**后训练（post-training）**的对象。

起始检查点很重要。基座模型、指令模型和经过继续预训练的模型，即使架构相同，也是不同的起点。指令版本已经接受过对话和偏好训练。基础检查点未必见过分词器预留的聊天标记。在领域文本上继续预训练，也不会自动教会角色边界或指令遵循策略。贯穿案例的起点选择见[第 14 节](#s14)。

### 三类训练信号

**监督微调（supervised fine-tuning，SFT）**提供助手本应写出的回答。一个示范确定完整回答的格式、内容和结束位置。训练提高该回答的条件似然。这仍是普通语言模型训练，只是精心选择了哪些位置作为目标。

**偏好优化（preference optimisation）**提供比较。同一提示有两个回答，标签指出哪个更好。标签不必描述理想答案；它可以判断清晰度、相关性或拒绝是否恰当，而这些判断通常比写出示范容易。学习得到的奖励模型将比较转换为评分；DPO 则直接用比较对拟合策略。

**强化学习（reinforcement learning）**提供给生成回答评分的方法。模型采样回答、获得奖励，再更新策略。任务结果可检查时，可以用确定性验证器代替学习得到的奖励。训练信号的质量取决于验证器实际检查的内容。有效 JSON 不一定包含正确论证；通过测试的程序也不一定在测试未覆盖的输入上正确。

| 阶段 | 数据单位 | 信号 | 典型用途 | 示例规模 | 主要成本 |
|---|---|---|---|---|---|
| SFT | 含助手目标的对话 | token 对数似然 | 轮次、格式与任务表述 | 数千至数百万个示例 | 训练 token 遍数与目标准备 |
| 偏好 | 提示、选中回答、拒选回答 | 比较似然 | 相对判断 | 数万至数百万个比较对 | 生成与标注比较对 |
| RL | 提示与奖励过程 | 采样回报 | 改进模型自身输出上的行为 | 数千至数十万个提示 | 生成、评分与更新 |

这些范围描述可能的工作量，并非数据充足的门槛。每个阶段都可以更新完整权重或适配器。有些任务只需 SFT；另一些需要反复收集偏好或进行 RL。后续阶段并不一定改善所有指标。是否晋升仍取决于对实际部署行为的评估。

::: figure id=fig-09-1
训练信号与评估门槛。示范训练 SFT；比较数据进入奖励模型加 PPO 或 DPO 路径；验证器可以直接给生成回答评分。通过验证的样本可经拒绝采样回到 SFT。任何训练阶段都可以更新完整权重或适配器。这是流程示意，并非每个任务都必须依次执行的方案。
:::

### 改变行为可能比训练基座模型便宜

[InstructGPT](https://arxiv.org/abs/2203.02155) 表明，在其提示分布上，人工评估者可能更喜欢经过后训练的 1.3B 模型，而不是 175B 的 GPT-3 基座模型。[LIMA](https://arxiv.org/abs/2305.11206) 用 1,000 个精心筛选的示例微调 65B 基座模型，展示了明显的指令遵循能力。这些结果支持用优质示范调动基座模型已有的能力，但并不说明 1,000 个示例能补齐任意领域知识，也不说明一次偏好研究衡量了所有任务的能力。

区分行为与知识很有用，但并非绝对。微调可以教会新信息，RL 也可以改进模型使用计算的方式。工程上要问的是：具体训练信号是否在留出行为上带来稳健改进。格式可能改善，而算术没有改善。[实验 6](#lab6) 中，135M 指令检查点能生成助手式回答，却仍未通过本套件要求只输出数字的单位换算题。流畅的回答不能证明底层计算正确。

::: worked title="假设 SFT 阶段的规模"
案例采用 5,000 万个 SFT token。相对于[模块 08](module_08_ZH.html#s1) 中示例性的 2 万亿 token 预训练计划，其比例为 $50\times10^6/(2\times10^{12})=2.5\times10^{-5}$，即 $0.0025\%$。相对于团队自己的 20 亿 token 继续预训练阶段，比例为 $50\times10^6/(2\times10^9)=0.025$，即 $2.5\%$。

这些是数据量之比，不是运行时间之比。RL 样本生成、标注和候选评估可能占据小型后训练任务的大部分成本。即使使用适配器训练，冻结权重也占内存。
:::

已发表的流程体现不同选择，并非统一配方。InstructGPT 使用示范、奖励模型与 PPO。Llama 2-Chat 将 SFT、拒绝采样和 PPO 结合。Tülu 3 使用 SFT、DPO 和可验证奖励强化学习。DeepSeek-R1 使用冷启动、推理 RL、拒绝采样 SFT，以及另一轮 RL。它们的目标、数据和评估条件不同；照搬顺序不会复现结果。

### 贯穿案例

假设助手为反应堆容器泄压系统起草并检查安全论证。其标准模型有 9,550,729,216 个参数，与模块 07、08 的配置相同。本模块从假定已通过模块 08 领域门槛的继续预训练检查点开始。它需要学习对话边界、论证模式、受约束编辑，以及诚实处理证据缺失。结构检查器能验证引用和环路，却不能证明真实泄压系统足够安全。本教程的晋升门槛针对助手行为，并明确保留这一限制。

::: check
模型能续写工程教材段落，为什么不代表它能可靠回答工程师的请求并停止？
:::

::: answer
文本续写并未规定角色、回答格式、不确定性策略或结束轮次的动作。这些需要训练示例，以及实际对话格式下的评估。已有知识可能有帮助，却不会自行建立这些行为。
:::

## 监督微调：数据 {#s2}

**SFT 示例**包含对话及其中作为目标的助手轮次。常见存储形式是含 `role`、`content` 字段的消息列表，角色可能包括 system、user、assistant、tool。独立清单记录对话来源、处理步骤和所属数据划分。渲染和损失掩码应在组装表示之后应用，并保留这些来源信息。

```python norun
messages = [
    {"role": "system", "content": "Reply with the answer and its unit only."},
    {"role": "user", "content": "Convert 2.5 MPa to kPa."},
    {"role": "assistant", "content": "2500 kPa"},
]
manifest = {"source": "synthetic unit conversion", "split": "train",
            "generator_seed": 1, "schema_version": 1}
```


有用的数据单位是示例体现的行为，而非 token 数量。一万条近乎相同的换算题，可能完全没有训练不确定性处理、多轮纠错或受约束编辑。先建立覆盖表：任务、语种、输入条件、目标行为及目标检查方法。这样可以在大型生成器继续堆积简单例子前发现缺口。

### 四种示范来源

**人工示范（human demonstration）**可以体现难以用代码定义的判断。领域专家能区分有证据支持的主张与看似合理却无依据的主张，并写出恰当的补充证据请求。这类示例成本高，因为正确性和一致性都需要审核。LIMA 的结果支持投入精力改进目标质量，却不能证明小数据集总胜过大数据集。小集合的覆盖也有限，还可能过度体现某一作者的风格。

**蒸馏（distillation）**让更强模型回答预期提示，再由学生学习选出的回答。教师输出只是候选目标，不能仅凭来源就成为标准答案。解析它、运行任务检查器、抽查样本，并记录拒绝原因。教师可能格式无可挑剔，却编造证据。清单应记录教师和生成设置；在将输出视为可复用训练数据前，确认相关来源与模型条款允许预期用途。

**过滤后的自生成数据**使用当前模型自己的样本。保留通过验证器的回答并训练，这是[第 8 节](#s8) 的仅学习成功样本方法。它不需要独立教师，却无法为模型从不解决的提示提供成功示范。成功率很低时，生成样本可能远比后续 SFT 昂贵。过滤器也决定学生学习优化什么。

**合成编辑**适用于可由精确变换生成目标的行为。例如，仅重命名论证中的指定证据标识符，其余字段保持不变。原始文档、编辑请求和脚本结果构成完整示例。脚本可以比较变更路径、确认引用更新，并拒绝意外修改。这样获得精确的编辑约束示范，不必依赖评判模型对“看起来差不多”的印象。

::: figure id=fig-09-2
对话角色、目标轮次与四类示范来源。人工写作、蒸馏、经验证的自生成数据和脚本编辑，提供不同覆盖，也有不同失败模式。成本与质量标签是定性描述，图中未杜撰测量值。
:::

### 过滤改变分布

过滤器也是选择策略。完全重复的示例浪费预算，还可能赋予某个目标过大影响。近似重复即使哈希不同，也可能跨越训练和测试划分。语种检查、长度限制和解析规则能阻止明显不匹配，但都不能证明事实正确。若覆盖检查器只检查危害标识符是否出现，就可能保留提到危害却未处理危害的回答。

训练前，针对每套评估数据去污染，包括生成蒸馏回答所用的提示。划分前将相关源文档与模板家族归组。否则，留出提示可能只是教师训练数据中某一提示的重命名版本。按来源、任务、语种报告保留数，按原因报告删除数。单一总数掩盖了过滤器删掉哪些类别。

::: worked title="蒸馏产量与缺失的困难案例"
假设 20,000 个提示各获得一个教师样本，$62\%$ 通过检查器，则保留集有 $20{,}000\times0.62=12{,}400$ 个示例。

若每个提示在同样成功率下独立采样四次，至少成功一次的概率为 $1-(1-0.62)^4=1-0.38^4=0.97915$，约覆盖 19,583 个提示。独立假设很强：提示难度不同，重复输出还可能共享误解。应按提示测量覆盖，不能将独立采样计算当作实际预测。

保留所有通过样本，会反复加重简单提示的权重。每个提示最多保留一个，可限制不平衡，却仍排除没有成功样本的提示。这些缺失案例需要单独分析、专家示范或调整任务；它们并未从部署工作量中消失。
:::

### 匹配实际服务的对话

分布匹配包括系统提示词、工具、语种、长度，以及真实请求的不完整与错误。只用整洁英文简报训练，可能无法处理中文请求、混合标识符和不完整编辑要求。应主动设计覆盖，而不是期待教师碰巧生成这些情形。双语任务中，译文目标必须保留检查器读取的证据标识符、单位和模式值。

多轮数据既应有成功回答，也应有纠正和未解决的请求。用户补充缺失证据后，助手的结论应改变；仅重复无依据主张时则不应改变。这些示例教会上下文与行为的关系，单轮答案列表无法提供这种关系。工具错误也需要改变路径的示范，而非只有成功调用。

目标本身应说明信息何时不可用。若每份训练简报都包含全部证据，模型就学不到部署时证据缺失的情况。在系统消息中加入“不要产生幻觉”，没有为该情况提供训练目标。应包含具体的不完整简报，以及明确指出缺失依据的回答。

### 专门化时保留通用行为

狭窄数据集可能改善一项任务，却削弱其他能力。混入通用指令示例是一种缓解办法，不是固定比例的保证。选择初始配比、测量通用评估集，并在候选未通过预先声明的门槛时调整占比。适配器限制哪些权重变化，却不能防止这些权重所计算函数的遗忘。部署输出仍依赖适配后的投影。

最后，给数据生成器和检查器分别建立版本。任一变化都会改变学习问题。记录数量、种子、来源版本和精确测试划分，才能复现改进。仅有模型检查点，无法说明新行为来自新目标、不同过滤器还是优化器变化。

::: check
过滤蒸馏回答时只保留成功样本，哪些部署提示最容易在 SFT 集合中缺失？
:::

::: answer
教师觉得困难或持续误解的提示。缺失是选择偏差，不是工作量已解决的证据。跟踪未覆盖提示，并限制重复成功样本，避免简单案例主导训练。
:::

## 模板、掩码、打包与 SFT 的限制 {#s3}

对话只有经**对话模板（chat template）**渲染角色和边界后，才成为序列。ChatML 示例中，一个轮次为 `<|im_start|>role\ncontent<|im_end|>\n`。请求助手回答时，生成提示以 `<|im_start|>assistant\n` 结束。其他模型家族使用不同标记。角色名称不是权重的通用接口；模型实际接收的是渲染后的 token 序列。

[Transformers 对话模板文档](https://huggingface.co/docs/transformers/chat_templating) 说明消息渲染与助手生成前缀的添加方式。训练完整助手轮次，与提示一个尚未完成的轮次，是不同操作。训练序列已经包含目标回答，不应在回答后再添第二个生成头。

### 渲染约定

训练和服务应将同一测试对话渲染为完全相同的 token ID。还应比较渲染字节，因为分词设置可能掩盖两个函数在何处不同。仅一侧插入默认系统消息、额外起始 token 或少一个换行，都会改变条件上下文。先渲染文本，再开启自动特殊 token 分词，可能重复添加标记。

这里使用的基础 SmolLM2 检查点没有对话模板，因此实验显式定义模板，并将系统消息放入数据。实验 6 对基础与指令检查点使用同一显式提示，避免其中一个分词器插入不同默认消息。这控制了比较条件，但不表示手写模板对所有发布模型都最优。

预留 token ID 需要单独检查。在固定的基础检查点中，两个聊天标记嵌入行的余弦相似度为 $0.99976$，最近邻还包含其他预留行。这符合标记未在预训练中学会不同角色的情况。仅凭相似度不能证明每个 token 的训练历史；这里，它为一个普通文本训练未建立聊天行为的检查点提供了停止行为对照实验的依据。

实验 1 按嵌入表逐维均值与标准差，用固定种子采样替换这两行，结果余弦为 $0.39968$。这是先显式修改起始检查点，再进行 SFT，不能代替训练：典型且不同的行仍需学习角色。冻结绑定嵌入与输出头的 LoRA 尤其需要初始化或可训练行增量，因为适配器无法直接更新 token 行。

### 条件似然

将完整训练序列记为 $z_1,\ldots,z_T$。助手目标 token（含结束轮次标记）取 $m_t=1$，其他位置为零。batch 的 token 平均 SFT 损失为

$$
\mathcal{L}_{\mathrm{SFT}}(\theta)
=-\frac{1}{\sum_{b,t}m_{b,t}}
\sum_{b,t}m_{b,t}\log p_\theta(z_{b,t}\mid z_{b,<t}).
$$

对单个提示 $x$ 和回答 $y=(y_1,\ldots,y_L)$，链式法则给出

$$
p_\theta(y\mid x)=\prod_{t=1}^{L}p_\theta(y_t\mid x,y_{<t}),
\qquad
\log p_\theta(y\mid x)=\sum_{t=1}^{L}\log p_\theta(y_t\mid x,y_{<t}).
$$

因此，训练助手部分就是条件极大似然。提示仍在输入中，并通过影响后续隐藏状态接收梯度。屏蔽提示的*目标*，不会把提示移出注意力、分离其表示或冻结输入嵌入；它仅移除要求模型预测系统和用户轮次的损失项。

输入位置 $t$ 的 logits 预测 token $t+1$，因此将 `logits[:, :-1]` 与 `labels[:, 1:]` 对齐。助手回答之外的标签设为 `-100`，供 PyTorch 交叉熵忽略。掩码看起来正确，却可能对应错误的 logits 位移。应检查 token 表中的首个和最后一个训练预测，而非仅统计 1 的数量。

```python norun
logits = model(input_ids, attention_mask=attention_mask).logits
loss_sum = F.cross_entropy(
    logits[:, :-1].reshape(-1, logits.size(-1)),
    labels[:, 1:].reshape(-1), ignore_index=-100, reduction="sum",
)
target_count = (labels[:, 1:] != -100).sum()
loss = loss_sum / target_count
```


本实验中，助手头属于条件上下文；回答与 `<|im_end|>` 是目标。训练结束标记，就是目标告诉模型何时停止的方式。若每个目标都缺少该标记，目标就没有直接教模型输出它。模型仍可能凭检查点已有行为停止，但这不同于本次训练教会停止。

::: figure id=fig-09-3
输入 token、下一 token 目标与助手损失掩码。提示和助手头仍作为可见上下文，回答及其结束标记承担损失。简化示例突出 logits 输入位置与预测 token 的位移；填充位置不提供目标。
:::

### 统计目标，而非填充位置

token 平均损失中，长回答提供更多项。先按对话平均，再按 batch 平均，则赋予每个对话相同权重。两种目标不同，都可以有意选择，但应与数据配比一起说明归一化方式。

::: worked title="梯度累积中的权重错误"
一个微批量有 10 个目标 token，损失和为 20；另一个有 90 个目标 token，损失和为 90。合并后的 token 平均损失是 $(20+90)/(10+90)=1.10$。

若平均两个微批量的均值，则得到 $(2.0+1.0)/2=1.50$，高估短而高损失的微批量权重。按 token 加权累积时，应将损失求和，再除以整个更新中目标总数。分布式训练也需跨工作进程做同样核算，并考虑框架的梯度平均方式。
:::

QUICK 训练集中，位移后位置的 $9.929\%$ 承担助手损失，其他位置仍消耗前向计算。因此，仅按回答 token 做预算，可能严重低估 SFT 工作量。实验 1 打印完整 token 表，便于复现这一比例。

填充和打包处理另一类浪费。三段对话长度分别为 700、900、400，每段填充到 2,048 后，2,000 个真实 token 使用 $3\times2{,}048=6{,}144$ 个位置，其中 $67.4\%$ 是填充。把三段打包进一行，只用 2,048 个位置，空余 48 个。若要保持独立对话训练，应跨边界屏蔽注意力，并为每段重置位置 ID。简单拼接后使用单一因果掩码，会允许后面使用前面对话作上下文，改变实验。

1,000 段平均 300 token 的对话，理想打包下界为 $\lceil300{,}000/2{,}048\rceil=147$ 行，而单独填充需 1,000 行。这个计算假设打包能达到总量下界；实际分箱、长度上限和不拆分对话的要求会留下更多空位。应测量处理的位置数，不能把下界当成已实现的吞吐提升。

### 优化并评估行为

学习率、周期、batch 和上下文长度取决于起点与数据。完整权重更新的 $10^{-5}$，或适配器的 $10^{-4}$，只是初始实验选择，并非通用设置。实验 1 对小检查点与短合成任务采用更高的完整权重学习率。9,600 段对话、batch 为 64、训练三个周期，共有 450 次更新；$3\%$ 预热约占 14 次。15 步玩具训练中的预热取整属于另一种尺度。

即使对照实验在所有对话 token 上训练，留出损失也应求和后除以留出助手目标数量。同时跟踪停止、精确答案、解析率和任务检查器。QUICK 将留出助手损失从约 7.26 降至 0.19 纳特/token，停止率达到 $100\%$，但精确答案仅为 $66\%$。抽取类的十个留出项全部通过；阈值检查类只通过五个。良好的总体损失仍可能隐藏集中于某种计算的失败。

### 目标不能保证什么

SFT 使用**教师强制（teacher forcing）**：每个目标 token 都以正确的前序回答 token 为条件。生成时，错误会进入下一前缀。[模块 04](module_04_ZH.html#s10) 解释了这种差别。后续阶段在模型自身样本上训练，会暴露另一种分布，却不会消除所有累积错误。

示范中的事实也可能被记住，却无法在不同表述中可靠使用。狭窄微调可能鼓励无依据的具体说法，并削弱通用行为。应分别评估知识、弃权和通用任务。问题是缺失信息时，优先考虑检索或继续预训练；问题是如何使用已有信息时，优先考虑示范。这是需要验证的设计区分，不是说梯度只能改变风格。

::: check
屏蔽用户 token 标签，会阻止梯度经过用户提示的表示吗？
:::

::: answer
不会。提示仍为每个助手预测提供条件。提示的目标项被忽略，但助手损失仍可经提示对模型的影响反向传播。损失掩码选择预测项，既不是注意力掩码，也不是梯度截断。

## LoRA 与 QLoRA {#s4}

完整权重微调存储的不只是模型权重。按[模块 08](module_08_ZH.html#s8) 的混合精度核算，每个训练参数有 2 字节 bf16 权重、2 字节梯度、4 字节 fp32 主权重，以及两个各 4 字节的 Adam 矩，共 16 字节，尚未计入激活、临时工作区和输出 logits。案例模型的 $16\times9{,}550{,}729{,}216=152.812$ GB 模型状态无法装入单张 80 GB 加速卡。

这里采用十进制 GB，即 $10^9$ 字节。容量和可用内存应读取实际设备与分配器；产品标签并不规定精确的可用字节预算，某些标称 GB 对应 GiB。计算小计不是框架峰值内存的测量。

### 学习低秩变化

对冻结投影 $\mathbf{W}\in\mathbb{R}^{d\times k}$，**LoRA** 学习两个因子 $\mathbf{A}\in\mathbb{R}^{r\times k}$ 和 $\mathbf{B}\in\mathbb{R}^{d\times r}$，其中 $r$ 远小于 $d$ 或 $k$：

$$
\mathbf{W}'=\mathbf{W}+s\mathbf{B}\mathbf{A},\qquad s=\frac{\alpha}{r},
\qquad
\mathbf{h}=\mathbf{W}\mathbf{x}+s\mathbf{B}(\mathbf{A}\mathbf{x}).
$$

更新的秩至多为 $r$。训练时计算窄中间量 $\mathbf{A}\mathbf{x}$，再应用 $\mathbf{B}$；不必为每次前向先形成大矩阵乘积。优化器仅跟踪因子。低秩更新限制的是可训练变化，并不表示完整适配矩阵低秩。

[Hu 等](https://arxiv.org/abs/2106.09685) 提出该参数化并研究大语言模型的低秩适配。他们的 GPT-3 比较，在特定适配器配置下报告了可训练参数与内存的大幅减少。本模块的缩减比例来自下面实际适配的投影，而非借用不同模型的论文比例。

随机初始化 $\mathbf{A}$，并令 $\mathbf{B}=\mathbf{0}$，新增路径因此为零，适配器从冻结函数精确起步。令 $\mathbf{g}=\partial\mathcal{L}/\partial\mathbf{h}$，两个梯度为

$$
\frac{\partial\mathcal{L}}{\partial\mathbf{B}}
=s\mathbf{g}(\mathbf{A}\mathbf{x})^\top,
\qquad
\frac{\partial\mathcal{L}}{\partial\mathbf{A}}
=s\mathbf{B}^\top\mathbf{g}\mathbf{x}^\top.
$$

初始化时，第二个为零，第一个则可更新 $\mathbf{B}$。更新后，$\mathbf{A}$ 也可收到梯度。若*两个*因子都设为零，两者梯度会一直为零。仅将 $\mathbf{A}$ 设为零、令 $\mathbf{B}$ 随机，则交换先学习的因子。这里的初始化是惯例，并非零更新起点的唯一方法。

缩放 $\alpha/r$ 是超参数约定，不保证不同秩下更新大小、优化动态或学习率相同。秩稳定 LoRA 改用 $\alpha/\sqrt r$。比较秩时应说明缩放规则并评估结果。若同时改变秩、缩放与学习率，就无法将改进归因于秩。

::: figure id=fig-09-5
冻结投影与可训练低秩路径相加，得到适配输出。训练时窄因子依次作用于输入；发布时可将其乘积加入基础权重，合并后的线性层无需独立适配器路径。
:::

### 计算真正训练的参数

一个投影增加 $r(d+k)$ 个参数。$4{,}096\times4{,}096$ 矩阵采用秩 64 时，增加 $64(4{,}096+4{,}096)=524{,}288$，相对于 16,777,216 个冻结权重为 $3.125\%$。矩形键/值和 FFN 投影的计数不同。因此，适配全部七个块投影时，必须按实际输入、输出维度求和。

::: worked title="9.5B 案例的全部七个投影"
每层查询与输出各贡献 $8{,}192r$，键和值各贡献 $5{,}120r$，三个 SwiGLU 项各贡献 $19{,}456r$，总和为

$$
r\left(2\times8{,}192+2\times5{,}120+3\times19{,}456\right)=84{,}992r.
$$

36 层、秩 64 时，适配器有 $36\times84{,}992\times64=195{,}821{,}568$ 个参数，约为 9,550,729,216 参数基座模型的 $2.05\%$。按每参数 16 字节计算，训练状态为 3.133 GB。仅注意力适配器与包含 FFN 的适配器是不同实验；参数数和结果都应说明采用哪种。
:::

实验 2 在 135M 检查点中包装 210 个投影，训练 2,442,240 个适配器参数。打印的总数 136,957,248 **包含**新增适配器；冻结基座模型有 134,515,008 个参数。因子的两个 fp32 Adam 矩占 19.54 MB，完整基座模型则占 1,076.12 MB。这些仅是优化器矩；权重、梯度和激活另计。

冻结嵌入需单独处理。若对话模板行需要训练，普通的投影 LoRA 不会改变它们。可以在冻结前初始化不同的行，加入显式可训练行增量，或使用模板 token 已训练的检查点。绑定嵌入与输出头时，行更新必须同时影响查表和输出投影。案例采用*不绑定*的表，所以必须分别处理两组行。

### 内存节省不会消除冻结部分的计算

回顾[模块 06 的 FLOP 约定](module_06_ZH.html#s11)。$N_{\mathrm{matmul}}=N-Vd$ 排除无需算术的输入查表；案例值为 8,927,875,072。前向矩阵工作每 token 为 $2N_{\mathrm{matmul}}$ FLOP。因果序列长度为 $T$ 时，本系列注意力约定给每个前向 token 平均增加 $2LTd$。完整训练为 $6N_{\mathrm{matmul}}+6LTd$；投影 LoRA 省去冻结权重的梯度矩阵乘法，约为 $4N_{\mathrm{matmul}}+6LTd$，尚未计入较小的适配器开销。

$T=8{,}192$ 时，两者分别为每 token $6.08\times10^{10}$ 与 $4.30\times10^{10}$ FLOP。LoRA 节省约 $29\%$ 算术，而非 $98\%$。输入激活仍需经冻结投影传播梯度，注意力也保留反向计算。估计假设相关冻结路径需要激活梯度；若输入嵌入也冻结，可以省去最早的一次输入梯度计算。秩开销、融合内核和重计算还会影响实际单步时间。

完整激活检查点使案例一条 8,192-token 序列的激活小计为 3.61 GB，包括保存的层输入与按模块 08 公式重算的一层。若实体化完整 fp32 词表 logits 张量，还需 $8{,}192\times152{,}064\times4=4.983$ GB。分块计算损失可避免同时持有整个张量；依赖分块的内存估计必须明确说明。

::: worked title="同一激活假设下的三种内存预算"
完整微调在额外缓冲前需要 $152.812+3.607=156.419$ GB。秩 64 LoRA 配 bf16 冻结基座模型需要 $19.101+3.133+3.607=25.841$ GB。对应 QLoRA 基座模型估计为 6.776 GB，因此总计 $6.776+3.133+3.607=13.516$ GB。这些估计假设分块损失和单条序列，并非测得峰值或某款 GPU 的容纳保证。
:::

::: figure id=fig-09-6
同一单序列、完整激活检查点假设下，完整微调、秩 64 LoRA 与 QLoRA 的计算内存小计。模型状态与激活分开显示。容量线为参考标签；临时缓冲、分配器影响和完整词表 logits 张量未计入。

### 量化冻结基座模型，训练适配器

**QLoRA** 在保持基座模型量化的同时，训练高精度适配器。[Dettmers 等](https://arxiv.org/abs/2305.14314) 结合 4 位 NormalFloat（NF4）、尺度元数据量化和分页优化器，在该配置下展示了单张 48 GB GPU 微调 65B 模型。适配器梯度仍是普通浮点梯度。基座模型为矩阵计算反量化，并非通过离散 4 位编码的梯度来训练。

NF4 使用 16 个非均匀量化级，面向近似正态权重分布。每个块有绝对最大值尺度：除以尺度、选最近量化级，再乘回尺度，得到近似权重。量化尺度可减少元数据开销。案例估计中，双重量化后每个块权重约 4.127 位。大型嵌入与输出表保持 bf16；把所有参数都按恰好四位计数，会得到不同且没有依据的内存小计。

一个尺度为 0.031 的小块中，权重 $-0.027$ 归一化后约为 $-0.871$。附近 NF4 级包含约 $-1$ 和 $-0.696$，因此最近表示约为 $-0.031$。对这个值，非均匀量化可能比均匀网格更差。其分布动机不意味着每个块都获胜。[模块 10](module_10_ZH.html) 进一步讨论量化及误差评估。

### 合并后再次测试

训练后，将 $s\mathbf{B}\mathbf{A}$ 加入浮点基础矩阵。所得线性层在实数算术中表示相同函数。实验 2 最大探测 logit 差约为 $1.04\times10^{-4}$，因为合并和未合并计算的舍入不同。50 个评估解码回答全部一致。实数算术中的精确合并，不能保证所有浮点提示的输出相同。

多个行为共享基座模型时，可保留独立适配器；需要单一产物时则合并。若基座模型已量化，反量化、相加、再量化会引入额外近似。优先合并到正确浮点检查点，再量化发布并重新评估。冻结基座模型的版本是适配器身份的一部分：应用于不同基座模型，不再是原训练模型。

完整微调、LoRA、QLoRA 对内存、优化自由度和算术开销有不同取舍。小秩可能无法拟合较大变化，大秩也仍可能遗忘。主实验的秩 8 训练在自身合成留出集上达到 $58\%$ 精确匹配和 $100\%$ 停止率。其数据与更新预算不同于 QUICK 完整 SFT，两者数字不能公平排名。应匹配数据、预算并重复种子后再比较。

为什么可训练参数仅占很小比例，LoRA 单步时间却可能只略有减少？
