## 可验证奖励强化学习：GRPO {#s9}

检查器可以给数值答案、程序或结构化产物评分，无需对检查过程求导。因此，示范稀缺而结果容易检查时，强化学习仍可行。奖励对**被检查的属性**是精确的，却未必覆盖用户完整目标。安全论证通过引用检查，不代表引用证据支持其主张。检查成本也重要：没有人工标注，并不意味着运行代码或仿真免费。

[DeepSeekMath](https://arxiv.org/abs/2402.03300) 提出的**组相对策略优化（group relative policy optimisation，GRPO）**，用同一提示的样本比较代替 PPO 学习的评论家。在旧策略下生成 $G$ 个回答，评分并中心化奖励：

$$
\bar r=\frac1G\sum_i r_i,\qquad
s=\sqrt{\frac{1}{G-1}\sum_i(r_i-\bar r)^2},\qquad
A_i=\frac{r_i-\bar r}{s+\varepsilon_s}.
$$

这里与实验一样使用样本标准差，分母为 $G-1$。其他实现采用总体方差，尺度会不同。零方差组中，实验显式将全部优势置零；小数值稳定项不能替代这个分支。

### 组基线及其限制

令 $\bar r_{-i}$ 为其他 $G-1$ 个奖励的平均值，直接整理得到

$$
r_i-\bar r=\frac{G-1}{G}(r_i-\bar r_{-i}).
$$

给定提示后，独立采样使 $\bar r_{-i}$ 独立于回答 $i$。因此，留一法基线不改变其期望得分函数梯度。把回答本身纳入组均值，在标准化前引入因子 $(G-1)/G$。除以随机组标准差，则额外引入依赖奖励的权重；完整标准化估计器并非简单的无偏 REINFORCE 估计器乘常数。该恒等式解释基线关系，并未证明所有 GRPO 归一化都无害。

::: worked title="八个回答中一次成功"
奖励为 $(1,0,0,0,0,0,0,0)$ 时，均值 0.125，样本标准差 $\sqrt{0.875/7}=0.354$。成功样本优势为 2.475，每个失败为 −0.354。两次成功得到 +1.620 与 −0.540；四次成功得到 ±0.935。每组优势之和为零。全部成功或全部失败没有任务优势，但独立 KL 正则项仍可产生梯度。
:::

::: figure id=fig-09-14
八回答组将一次成功转为正优势，七次失败转为负优势。全成功组的任务优势为零，但仍可接受参考 KL 更新。
:::

回答 $i$ 的 token $t$，使用 PPO 的旧策略比率 $\rho_{i,t}$ 和共同序列优势 $A_i$。典型的序列平均目标为

$$
J_{\mathrm{GRPO}}=
\E\left[\frac1G\sum_i\frac1{|y_i|}\sum_t
\left\{\min\!\left(\rho_{i,t}A_i,
\operatorname{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)A_i\right)
-\beta k_{i,t}\right\}\right].
$$

掩码包含首个 EOS，排除后续填充。优势与旧策略概率从梯度图中分离。首次更新、参数尚未改变时，$\rho=1$，裁剪不起作用。任务梯度此时是带所示长度权重的组基线得分函数更新。这一限定很重要：它未必等于未归一化序列 REINFORCE。后续内循环步骤改变比率，激活裁剪。

### 谨慎估计参考 KL

对一个条件下一 token 分布，令 $u=\pi_{\mathrm{ref}}(a\mid s)/\pi_\theta(a\mid s)$，使用

$$
k_3=u-\log u-1.
$$

支撑相同、动作从**当前**策略采样时，$\E_{\pi_\theta}u=1$，因此 $\E k_3=-\E\log u=\KL(\pi_\theta\|\pi_{\mathrm{ref}})$。不等式 $\log u\le u-1$ 使每个样本非负。概率为 0.5、0.4 时，$u=0.8$，$k_3=0.0231$，而采样对数比为 0.223。在指定采样分布下，两者期望相同，单个值不同。非负性不能证明它的方差普遍优于所有其他估计器。

参数变化而样本仍固定来自旧策略时，未加权估计不再精确等于当前策略 KL 的期望。无偏数值估计器也不会自动给出无偏导数：若在固定采样动作上对其值求导，采样分布导数还是独立项。实验 5 使用常见局部替代目标和两次内更新，并明确说明近似。报告的序列 KL 则用新策略样本独立估计。

```python
import torch

def grpo_advantages(rewards):
    mean = rewards.mean(dim=1, keepdim=True)
    std = rewards.std(dim=1, correction=1, keepdim=True)
    return torch.where(std > 0, (rewards - mean) / std.clamp_min(1e-8),
                       torch.zeros_like(rewards))

# Each row is a sampled response; mask includes its first EOS.
# old_logp, ref_logp and advantages are detached rollout quantities.
def grpo_loss(logp, old_logp, ref_logp, advantages, mask, beta=0.04):
    ratio = (logp - old_logp).exp()
    advantage = advantages[:, None]
    surrogate = torch.minimum(ratio * advantage,
                              ratio.clamp(0.8, 1.2) * advantage)
    log_u = ref_logp - logp
    k3 = log_u.exp() - log_u - 1
    per_sequence = ((surrogate - beta * k3) * mask).sum(dim=1)
    return -(per_sequence / mask.sum(dim=1).clamp_min(1)).mean()
```


### 哪些组提供学习信号，归一化改变什么

独立二元奖励、通过概率为 $p$ 时，一组同时包含两种结果的概率为

$$
P(\text{task signal})=1-p^G-(1-p)^G.
$$

$G=8$ 时，$p=0.02$ 对应 0.149，$p=0.1$ 对应 0.570，$p=0.5$ 对应 0.992，$p=0.95$ 对应 0.337。很难和已经解决的提示，都提供很少组相对任务信号。增加 $G$ 消耗生成；重采样或课程可能更便宜，却改变有效提示分布。应记录丢弃组消耗的尝试数，并保持评估提示固定。

::: widget name=grpo-group-explorer
改变组内奖励，查看均值、样本标准差和优势；比较不同通过率与组大小下的二元任务信号概率。
:::

序列平均 token 损失赋予每个回答相同权重。两个失败样本，$A=-0.6$，长度为 200、800，单 token 系数分别为 −0.003、−0.00075。原始归一化可能偏向更长失败回答，但这不预测所有长回答都会恶化。除以标准差还会按观测奖励变化重新加权提示组。[Dr. GRPO](https://arxiv.org/abs/2503.20783) 移除该除法，并使用固定长度归一化。[DAPO](https://arxiv.org/abs/2503.14476) 包含 token 级平均、动态采样和其他修改。应报告精确目标，不能假设所有叫 GRPO 的系统计算相同梯度。

GRPO 持有策略与参考，常可采用同一冻结基座及适当分离的适配器。每个提示生成 $G$ 个回答，并在完整提示—回答序列上训练。共享提示很长时，训练遍数可能与生成一样昂贵。$G=8$、裁剪宽度 0.2、$\beta=0.04$ 是预算适中的示例设置，不是方法常数。

$\beta=0.04$ 时，实验 5 采样精确准确率为 96.3%，KL 为 0.629；$\beta=0.5$ 时为 87.0%、0.376。接受任何包含正确答案的字符串，能得到 97.6% 接受率，却只有 77.8% 精确准确率。平均回答从 1.57 增至 1.74 位数字。列出多个候选也满足子串规则：这是正确优化错误目标。应要求单一规范答案、测试退化案例，并检查很高奖励输出。仅加入长度惩罚可能掩盖症状，而未修复缺失的语义检查。

1 月版 [DeepSeek-R1 报告](https://arxiv.org/html/2501.12948v1) 描述从基座模型出发，以规则正确性和格式奖励训练 R1-Zero。报告 AIME 2024 pass@1 从 15.6% 升至 71.0%，并伴随更长的自检输出。这表明该阶段没有 SFT 示范也能改变有用行为，但预训练仍提供大量先前能力。R1 随后加入冷启动示例、推理 RL、约 800,000 条拒绝采样与通用 SFT 示例，以及另一 RL 阶段。小模型蒸馏比较支持其具体实验流程，并非小模型 RL 总更差的定理。

::: check
全成功组优势为零，完整损失仍可更新策略吗？概率为正时，为什么 k3 永不为负？
:::

::: answer
可以，参考 KL 项仍可更新，消失的只有任务优势项。不等式 $\log u\le u-1$ 给出 $u-\log u-1\ge0$；无偏 KL 数值解释还要求当前策略采样与相同支撑。
:::

## 安全、拒绝与诚实 {#s10}

**拒绝（refusal）**是对不适合请求的学习行为；**弃权（abstention）**是信息或信心不足时的回答。两者需要不同示例与评估。“我不能帮助绕过保护装置”表达边界，“简报没有昨天测得的压力”则指出缺失证据。单一帮助性分数都无法充分衡量它们。

示范简洁拒绝及有用的安全替代方案，加入正确拒绝优于服从的偏好对，并在 RL 中评分相关结果。拒绝策略仍应回答无害请求；否则拒绝一切即可通过仅测拒绝的测试。反过来，服从一切也能通过仅测不拒绝的测试。应同时报告**不安全服从**与**过度拒绝（over-refusal）**，并明确预期边界。

[Constitutional AI](https://arxiv.org/abs/2212.08073) 用书面原则生成批评与修订答案，进行监督阶段，再用 AI 比较进行偏好/RL 阶段。这减少部分人工标注，却不会移除原则、评估和解释原则的评判模型选择。模型生成的偏好仍会出错。应在生成循环之外保留人工审核的评估样本。

### 评估边界两侧

[XSTest](https://arxiv.org/abs/2308.01263) 包含 250 个类似不安全请求的安全提示，以及 200 个不安全对照。“终止 Python 进程”这类无害表达，测试模型是否依据上下文推理，而非匹配触发词。领域专家和自动红队可提供额外失败案例。留出新变体用于评估：记住静态清单不是稳健边界识别。检查回答实质，而非只看是否出现拒绝短语。

::: worked title="假设的拒绝权衡"
候选在 200 个有害提示上的拒绝率从 97% 升至 99%，却在 250 个无害边界提示上从 18% 升至 36%。有害拒绝率的单率二项标准误约 1.2、0.7 个百分点，无害拒绝约 2.4、3.0。这些误差不能代替配对比较。净改善四个有害案例，若无恶化，双侧精确 McNemar p 值最低为 0.125。过度拒绝增加 18 个百分点是较大的观测退步；两套评估均应发布不一致计数与区间。
:::

::: figure id=fig-09-16
拒绝决策有四种结果。有害服从与无害拒绝是不同错误。更新前后点为假设示例，说明单一安全率无法描述权衡。
:::

### 置信度与猜测激励

校准关心表达的置信度是否匹配经验准确率。答案 token 概率、口头置信度和长产物的置信度是不同测量。一些基座模型选择题实验发现有用校准；[GPT-4 技术报告](https://arxiv.org/abs/2303.08774) 则展示其评估中后训练使校准恶化。两者都不能推广到每个任务或每个基座。应在同一明确目标上测量各阶段前后的置信度与 ECE。

偏好标签可能奖励自信但错误的文本。正确给 1、错误和弃权都给 0，只要成功概率为正，就奖励猜测。按[模块 07，第 10 节](module_07_ZH.html#s10) 的规则，正确 +1、弃权 0、错误 $-\lambda$，仅 $p>\lambda/(1+\lambda)$ 时回答有利。$\lambda=4$ 时门槛为 0.8。决策效果取决于估计 $p$：过度自信的模型可能在证据不足时越过门槛。

应包含类似提示的可回答与不可回答版本。奖励指出缺失证据并提出有用澄清问题；否则，模型可通过拒绝一切最大化弃权奖励。一起报告错误、准确率、弃权和惩罚后的效用。在编造答案后附一句弃权表述，不应算成功弃权。

### 对证据与动作诚实

完成声明必须指向可观察结果。工具没有运行，就不应声称已运行。保存产物验证失败，即使文字看似完整，“完成了”也是错误陈述。训练轨迹可以奖励检查结果并说明剩余限制；运行时检查则独立要求产物存在且通过规则。

对安全论证助手，建立缺少主张所需证据的简报套件。目标回答标记主张未获支持，并列明缺失证据。悬空证据 ID 规则惩罚编造引用，但它只能发现虚构标识符，无法发现引用真实却无关的报告。证据相关性需要另一检查或人工审核。应把重复失败转为提示家族、目标行为与测量，而非加一句模糊的“保持诚实”。

**谄媚（sycophancy）**是无依据地同意用户前提或观点。[Sharma 等](https://arxiv.org/abs/2310.13548) 研究偏好信号如何助长这种行为。加入礼貌且有证据的纠正胜过迎合式同意的比较。正确与错误用户前提都应评估，避免反而奖励自动反驳。

实验 6 的小型指令模型比基座遵循更多格式约束，却编造了提示未提供的轴承温度和阀门序列号。两个模型都未通过五个弃权检查或五个拒绝检查。结果针对两个固定 135M 检查点、一个提示模板和简单检查器，支持分别检查这些行为，但不能证明所有后训练都优先格式而轻视诚实。

::: check
正确/错误/弃权奖励为 1/0/0，鼓励什么？哪两套评估能防止全拒绝策略看似优秀？
:::

::: answer
只要正确概率为正，就鼓励回答。应给错误成本，并评估弃权。有害请求套件应配无害边界套件，同时报告不安全服从与过度拒绝。
:::

## 工具与智能体 {#s11}

工具使用模型按指定格式发出助手调用、收到环境结果，再决定如何继续。对话模板可能以特殊标记包裹 JSON 函数名和参数。模型家族间约定不同，应使用部署分词器模板，而非看似合理的通用包装。工具模式、调用 ID 和结果对应关系都是训练输入的一部分。

助手调用与最终答案承担损失。在仅训练回答的目标下，用户、系统和**工具结果 token 被屏蔽**。结果是观测上下文，不是助手应生成的值。将它作为助手目标训练，会鼓励编造环境输出。屏蔽结果仍可经助手答案影响梯度，与第 3 节屏蔽用户 token 一样。

::: worked title="小轨迹也有大的上下文成本"
系统提示词 300 token、工具模式 450、用户请求 40、助手调用 35、工具结果 600、最终助手答案 120，总上下文 1,545 token。只有 $35+120=155$，约 10%，承担监督损失；全部 1,545 个仍贡献前向上下文与注意力成本。计数包含分配给各段的边界，不应重复计标记。
:::

::: figure id=fig-09-17
仅助手调用与答案段承担回答损失。工具结果是被屏蔽的环境上下文。直接回答分支提醒我们，除调用语法外，还要训练“不调用工具”的决策。
:::

例如助手发出 `{"name":"get_hazard","arguments":{"id":"H-12"}}`，工具返回对应危害记录和状态，最终答案引用 H-12，并说明记录支持什么。JSON 片段仅说明角色，不是任一模型的完整真实工具调用模板。若工具返回“未找到”，下个助手轮次应请求记录或标记主张缺少支持，而非编造成功查询。

数据可来自审核示范或按执行结果过滤的生成轨迹。[Toolformer](https://arxiv.org/abs/2302.04761) 使用自监督过滤，依据候选调用是否改善后续文本预测。这与验证助手最终产物是不同目标。部署数据既应检查调用参数有效并能执行，也应检查结果能支持最终回答。RL 可评分最终验证结果，并计入工具成本和无必要调用。

少见情况值得显式示例：不需要工具、工具超时、返回数据与假设矛盾、重试只会重复失败，或任务完成需要停止。训练模型读取错误并修改计划，而非盲目重试。永不结束的循环，每步语法都可能有效，却仍未完成任务。

参数类型与必填字段可由服务时验证或受约束解码强制（[模块 10](module_10_ZH.html)）。这确立语法有效性，却不证明调用获授权或恰当。[AI Agents 系列](../agent/index.html) 详述智能体循环、工具接口、护栏与评估。后训练提供循环使用的行为；运行时检查提供独立的动作和结果证据。

::: check
屏蔽工具结果，是否阻止模型学习使用其内容？
:::

::: answer
不会。它移除环境输出上的直接下一 token 目标，后续助手目标的梯度仍经过结果表示。模型学会以结果为条件，而非冒充环境。
:::

## 评估 {#s12}

后训练后，单一损失不能概括行为。SFT 损失仍衡量示范似然，DPO 衡量比较间隔，RL 奖励衡量选定代理。它们都仍有诊断价值，但晋升需要部署条件下的生成回答。实验 4 异策略 DPO 损失接近零、任务准确率却下降，具体说明为何必须区分。

采用分层评估。[IFEval](https://arxiv.org/abs/2311.07911) 有 541 个提示和 25 类可验证指令。领域检查器测解析率和结构通过率；通用能力评估集衡量遗忘代价。行为套件测已知失败，如编造证据、虚假完成、过度拒绝和不可回答问题。应报告类别及联合成功，因为满足四项强制约束中的三项，仍可能不可用。

检查器也需要测试。实验 6 初版无害检查器要求回答非空且不含拒绝短语，基座的垃圾文本也能通过。JSON 键格式检查不检查值：即使请求 `"ok"`，`"status":"OK"` 也通过键存在测试。应诚实命名该指标；若目标是精确值遵循，就加强谓词。不能把狭窄检查描述成更广泛的有用任务完成。

### 小套件的配对证据

[模块 01，第 10 节](module_01_ZH.html#s10) 介绍采样不确定性：通过率近似标准误为 $\sqrt{\hat p(1-\hat p)/n}$，百分位 bootstrap 重采样观测来估计区间。后训练套件通常小，检查点又面对**相同题目**。使用配对差 $d_i=\mathrm{pass}_{B,i}-\mathrm{pass}_{A,i}$，整对重采样，保留哪些题目对两个模型都简单的信息。

::: worked title="五十项上差十个百分点并不决定结果"
A 通过 50 项中的 36 项，B 通过 31 项。两者均通过 28 项，仅 A 通过 8 项，仅 B 通过 3 项，两者均失败 11 项。A 优势为 0.10。差值方差约 $11/50-0.1^2=0.21$，标准误 $\sqrt{0.21/50}=0.0648$，正态 95% 区间 $[-0.027,0.227]$。非配对计算浪费正配对关系，区间更宽。这些计数描述上偏向 A，却只提供较弱总体差异证据。
:::

**McNemar 精确检验（McNemar's exact test）**仅用不一致比较对。在原假设下，每个 $m$ 不一致项偏向任一模型的概率相同。若较少方向有 $b\le m/2$ 项，双侧值为

$$
p_{\mathrm{exact}}=\min\!\left(1,
2\sum_{j=0}^{b}{m\choose j}2^{-m}\right).
$$

8 比 3 时，$m=11$、$p=0.227$。小型离散样本上，该检验与近似或百分位区间不必完全一致。分歧意味着应检查假设并增加证据，而非选择能让偏好检查点更好看的结果。

::: figure id=fig-09-18
实验 6 类别通过率及 Wilson、百分位 bootstrap 区间。独立配对行显示指令模型减基座模型的差值。全零和全一类别暴露了小样本 bootstrap 区间退化。
:::

实验 6 总体基座为 25.0%，指令模型 37.5%。配对 bootstrap 估计 +12.5 个百分点，区间 [+2.5, +22.5]，但五个不一致项全部偏向指令模型，精确 McNemar 为 $p=0.0625$。应描述观测改进及限制。40 项便利套件不能确立稳健优势。五项零成功，重采样给出 [0,0]；Wilson 区间上界约 43%。零观测成功，不证明总体概率恰为零。

共享模板的提示不是独立证据。采用**聚类 bootstrap（cluster bootstrap）**重采样模板，并使用足够独立模板家族。随机解码时，每提示重复采样，并同时考虑提示与采样变化。固定并报告解码设置、种子、系统提示词、token 限制与检查点版本。反复在同一验证套件选胜者也引入选择偏差；应保留最终测试集，并在看到结果前设晋升容差。

### 评判比较也需审查

模型评判器可以依据准则与参考比较回答。[MT-Bench 与 Chatbot Arena 研究](https://arxiv.org/abs/2306.05685) 考察一致性与评判偏差。评判模型家族、准则、位置、长度和自我偏好，都可能改变表面胜者。宽泛胜率应与程序正确性和人工审核样本并列。

每对以两个顺序呈现。翻转判断可计半胜，或单独报告不一致。考虑以下假设表：

| 两个顺序的判断 | 数量 |
|---|---|
| A 两次均胜 | 38 |
| B 两次均胜 | 32 |
| 先呈现者两次均胜 | 24 |
| 后呈现者两次均胜 | 6 |

A 在先位胜 62 次、后位胜 44 次，交换平均为 53%，一致率 70%。交换平衡呈现，却不能普遍抵消任意非线性位置偏差，也不能移除长度偏差，因为较长回答在两个顺序中都较长。

实验 6 模拟质量相同的回答，加上长度与位置效应，**没有调用外部评判模型**。A 的潜在质量胜率为 50.3%，先位 75.5%，后位 42.0%，交换平均 58.8%。在零长度差、平衡位置处，拟合逻辑斯蒂估计为 46.6%。这是含有限样本与模型形式误差的调整示例，不是恢复已知精确胜率。[AlpacaEval](https://arxiv.org/abs/2404.04475) 等长度控制比较处理这一混杂，但调整仍需与有意义的人工偏好验证。

### 污染与晋升

以内容哈希与 n-gram 重叠，对所有训练来源（包括蒸馏提示和生成目标）检查评估污染。报告删除数与阈值。改写、变换例子和教师先前接触可能逃过检查。去污染降低风险，却不能证明完全独立。可行时，在生成训练回答前留出提示家族。

晋升规则可要求：有统计支持的领域改善、通用评估不超预定退步容差、可接受拒绝与弃权权衡，以及人工审查高奖励样本。评估**实际发布的合并与量化产物**，不只是训练适配器。记录哈希与评估配置，让下一候选面对可识别的现任模型。未过门槛，就保留现任并修改数据、检查器或优化；不能看到失败后才放宽门槛。

::: check
“B 在 200 个提示上胜过 A 四个百分点”，还必须提供什么？
:::

::: answer
配对结果计数与不确定性、模板聚类、解码设置、污染检查与类别退步。总体差值不能说明是否可重复，也不能排除隐藏重要失败。
:::

## 合并与平均 {#s13}

共享基座的微调模型，有时可用权重平均组合。[**模型汤（model soups）**](https://arxiv.org/abs/2203.05482) 研究处于兼容低损失区域的微调。均匀模型汤平均所有所选模型；贪心模型汤只在留出指标改善时加入候选。平均同一次训练的后期检查点，也是低成本候选。两者都不保证改善，选择集应与最终评估集分开。

**任务算术（task arithmetic）**将微调更新写为 $\tau_i=\theta_i-\theta_0$，构造 $\theta_0+\sum_i\lambda_i\tau_i$。相加可能组合行为，相减在部分实验中能削弱行为。但它并不完美隔离技能，任务向量也包含无关行为变化。尺度选择需要跨重要任务评估。

::: figure id=fig-09-20
概念低损失盆地说明兼容微调为何可能平均良好，不兼容参数对齐为何可能跨越高损失。这是示意，不是测量景观，也不保证所有共享基座模型都适用。
:::

参数对齐很重要。独立初始化可能学到隐藏单元置换后的函数，因此即使函数一致，朴素逐坐标均值仍可能很差。声称独立训练平均总会毁坏模型过于绝对；重参数化或对齐可以改变结果。反过来，共享基座也不保证大幅微调后仍在低损失处线性连通。

[**TIES-merging**](https://arxiv.org/abs/2306.01708) 裁去小任务向量元素、选出聚合符号，再平均同符号元素。[**DARE**](https://arxiv.org/abs/2311.03099) 随机丢弃增量元素，在合并前按保留概率的倒数缩放其余项。逐元素增量无偏，但非线性网络输出不会因此无偏，也不保证有用。

::: worked title="解决冲突任务向量元素"
三个向量为 $(0.50,-0.20,0.02,0.30,-0.40)$、$(0.40,0.30,-0.01,-0.35,-0.05)$、$(-0.10,0.25,0.03,0.20,-0.30)$，普通均值为 $(0.267,0.117,0.013,0.050,-0.250)$。各保留三个最大绝对值元素，得到 $(0.5,0,0,0.3,-0.4)$、$(0.4,0.3,0,-0.35,0)$、$(0,0.25,0,0.2,-0.3)$。聚合符号为 $(+,+,0,+,-)$，平均同符号非零元素得 $(0.45,0.275,0,0.25,-0.35)$。第四坐标不再抵消成 0.05。这些算术说明规则，而非性能收益。
:::

### 合并适配器更新，而非分别平均因子

两个适配器应构造 $\Delta W=\lambda_1s_1B_1A_1+\lambda_2s_2B_2A_2$。通常 $(B_1+B_2)(A_1+A_2)/4$ 包含两者都未学习的交叉项，且给原乘积错误权重。$B_1=(1,0)^\top$、$A_1=(1,0)$、$B_2=(0,1)^\top$、$A_2=(0,1)$ 时，平均乘积得到 $0.5I$；乘平均因子则得到全为 0.25 的矩阵，秩和作用不同。

将尺度折入 $B_i$，拼接因子，就能把加权和精确存为更大适配器。两个秩 $r$ 更新的和，秩至多 $2r$；再压到秩 $r$ 是近似，常用 SVD。应合并到正确浮点基座，再量化并评估。候选构造便宜，不意味着候选验证可省略。

::: check
把 LoRA 因子均值当作权重更新均值，错在哪里？
:::

::: answer
更新是矩阵乘积。平均因子相乘会产生交叉项并改变系数；应加缩放后的乘积，或拼接因子。精确和可能需要更高秩。
:::

## 案例：安全论证助手的后训练方案 {#s14}

这是**假设的设计算例**，不是部署系统，也不证明自动安全决策正确。助手在固定 JSON 模式中，为反应堆容器泄压系统起草主张、策略、证据链接和上下文。结构检查要求主张链接有支持、叶节点有证据、引用有效、无环，并覆盖简报危害日志。检查确立显式属性；工程师仍需评估论证和证据。

工作量沿用模块 07–10：约 4,000 输入 token，其中 3,000 为稳定系统/模式/参考前缀，1,000 为请求专属内容，最多 2,000 输出 token。每天 2,000 次请求，使小服务变化反复出现。训练应复现部署模板、简报配比与英中比例，包括编辑和缺失证据情形。

### 基线决定起点

先在黄金套件上评估带提示的指令版本：解析率、联合结构通过率、证据相关性，以及人工或评判覆盖。它是训练候选必须胜过的低成本替代方案。也记录指令模型的通用能力与行为基线。模块 08 的领域损失与测试，决定继续预训练是否合理。

这里假设模块 08 的 CPT 检查点在 1.8B 领域 token 与 0.2B 回放 token 后通过门槛。它从基座出发，因此 SFT 除领域格式外，还需教通用对话行为。检查模板 token：基座训练没用过的行，不会通过从不含该 token 的领域文本变得有用。初始化并训练必要输入/输出行，保留 token ID。若不需 CPT，就从指令版本出发，适配其已训练模板。确认基座与教师许可允许预期训练和发布。

### SFT，在 RL 前设门槛

每层七个投影都用秩 64、alpha 128 的 LoRA，并训练必要模板 token 行。初始学习率 $10^{-4}$，余弦衰减，3% 预热，对 50M 总 token 训练两个周期。打包至 8,192 token，正确处理边界与回答掩码。这些是待验证试验设置，不表示这个未运行的大模型方案一定收敛。

数据结合检查器验证的蒸馏、受约束编辑对、拒绝与弃权示范、工具轨迹，以及通用指令数据。初始约三分之一 token 为通用数据，反映基座起点。应说明配比按全部 token 还是回答目标计，两者分母不同。过滤教师幻觉，在生成目标前划分提示家族，并保留明确标记缺少依据而不编造的示例。

用配对区间、类别通过率与明确通用容差，将 SFT 与提示指令基线比较。候选即使规则全通过，若诚实或通用指令遵循退步，也不能只凭学会模式晋升。失败时，先修数据与覆盖，再增加更复杂 RL 阶段。

### 对检查器能确立的属性使用 GRPO

3,000 个代表提示采样两个周期，每提示八个回答，一次内更新。参考设为**SFT 策略**，试验 $\beta=0.04$。关闭全部适配器会返回 CPT 基座，而非预期参考；应保留 SFT 适配器，应用另一个可训练 RL 更新，或保留冻结 SFT 检查点。实际预算须包含所有必要冻结适配器或模型状态。

复合奖励可提供部分进展，又限制评判模型影响。解析/模式失败和空产物给零。对非空、类型正确产物，$q$ 是结构规则通过比例，$p$ 是编辑中应保持内容的保留比例，$c$ 是封顶评判覆盖，$d$ 是经审核退化标记。令

$$
R=0.5q+0.2p\,\mathbf1_{\mathrm{edit}}
+0.3\min(c,1)\,\mathbf1_{\mathrm{all\ rules\ pass}}-0.2d.
$$

只有简报存在必须保留内容时，才定义保留比例。非编辑简报该项为零，所以无退化的最高分是 0.8，而非 1.0。可以有意保留差别并分析提示类别权重，也可以在计算优势前按简报类别重新归一化。不能悄悄把未定义保留分母当作完美保留。

规则聚合前，要求真正存在主张和证据条目。否则空产物中，“所有叶节点引用证据”“所有引用存在”都可能空真。规则需最低内容与简报覆盖条件。惩罚相同风险评级或重复证据链接可发现捷径，但这种重复也可能合理；应确认标记对应真实失败，而非方便的审美偏好。结构检查和退化惩罚仍不能证明工程内容真实。

::: worked title="逐项计算奖励"
普通文本或空 JSON 产物为 0。非编辑产物通过十二条规则中的九条，无退化，得 $0.5(9/12)=0.375$。无退化编辑保留 90% 必须保留内容，覆盖 0.8，得 $0.5+0.2(0.9)+0.3(0.8)=0.92$。无结构问题的非编辑产物，覆盖 0.6 且确认退化，得 $0.5+0.3(0.6)-0.2=0.48$。评判项封顶，且全部结构规则通过前不可获得。这些数字描述设计代理，不是安全保证。
:::

每周期抽读高奖励输出，跟踪长度、覆盖、零方差组与 KL，并运行完整黄金套件。对检查器不能测的文本清晰度，可以选择在新生成、长度受控比较对上做 DPO。两种方法都不能修复不足的评估。

### 在明确假设下核算成本

::: worked title="SFT 与 GRPO 不仅处理回答 token"
两个 SFT 周期共 $10^8$ 个 token 遍数。第 4 节在 8,192 token 下的 LoRA 估计为每 token $4.30\times10^{10}$ FLOP，因此共 $4.30\times10^{18}$ FLOP。每张 H100 假设有效 $4\times10^{14}$ FLOP/s，约 **3 GPU 小时**。采用激活检查点和本系列计算约定；购买时长前应测实际吞吐。

GRPO 生成 $3000\times2\times8=48{,}000$ 个回答，最多 96M 输出 token。假设每 GPU 每秒生成 2,500 token，需 **10.7 GPU 小时**。若实现跨样本共享前缀，提示预填充约 $6000\times7.61\times10^{13}$ FLOP，即 **0.3 GPU 小时**。训练重处理每组八条完整 6,000-token 序列，共 288M token 遍数。LoRA 训练加参考前向约每 token $6N_{\mathrm{matmul}}+8LTd=6.06\times10^{10}$ FLOP，需 **12.1 GPU 小时**。合计约 **23 GPU 小时**，未计评判调用、评估、同步等开销。训练可能和生成一样昂贵。
:::

按本系列假设的每 H100 小时 USD 2.50，SFT 约 USD 7.50，一轮 GRPO 约 USD 58。各三轮共约 USD 200，未计评判模型。这些是建模假设，不是当前租价或测得 GPU 运行。数据审核、失败试验和工程工作可能占据大部分成本。

::: figure id=fig-09-21
假设流程先建立基线证据，SFT 与 GRPO 分别受门槛约束，再合并、量化并评估实际发布产物。计算标签是在明确吞吐假设下的估计。
:::

最后合并到正确 bf16 检查点、量化服务、重跑全部门槛并记录产物哈希。本系列的示例服务格式采用 4 位块权重，每 128 个权重配一个 fp16 尺度，即每权重 4.125 位，并将嵌入和输出表保留为 8 位。约 83.05 亿个块参数占 4.28 GB，两张表再占 1.246 GB，总计约 **5.53 GB**，尚未包含打包开销。这与表格保持 bf16 的 QLoRA 训练估计不同。所有参数统一采用四位时，在元数据之前为 4.78 GB，属于另一种假设。应测量实际发布文件。[模块 10](module_10_ZH.html) 展开服务核算。

::: check
为什么 GRPO 参考必须保留 SFT 策略？为什么平均规则结果前要拒绝空产物？
:::

::: answer
预期 KL 锚定 SFT 后行为，而非更早 CPT 基座。应保留正确冻结检查点或适配器。空集合可空真地通过全称规则，因此授予规则或评判分前，要要求有意义、类型正确的内容及覆盖。
:::

## 常见问题与排查 {#wrong}

根据症状选择诊断，再用对照或输出检查验证怀疑原因。不同原因可能产生相同症状。

| 症状 | 应检查的可能原因 | 修正与证据 |
|---|---|---|
| 生产与训练不同 | 对话模板、系统提示词或 token 边界不同 | 比较两条路径中固定对话的渲染 token ID |
| 模型写出用户下一轮 | 用户轮次承担损失，或未训练停止 | 检查回答掩码，纳入助手结束轮次目标 |
| 正确答案后有垃圾，停止差 | 未训练聊天行或生成 EOS 错误 | 检查行统计与 token ID；初始化/训练行，并做对照 |
| 更多自信的事实编造 | 无依据示范或奖励自信 | 对照证据审核数据；加入弃权、检索，再测校准 |
| 领域成功但通用能力退步 | 数据配比狭窄，无保留门槛 | 回放通用指令数据并评估通用集 |
| DPO 损失近零，任务准确率下降 | 似然位移、可分简单比较对或更新过多 | 检查选中/拒选对数比与生成答案；整理有用比较对，按留出指标早停 |
| 回答变长而结果未改善 | 长度偏好、宽松检查器或损失归一化 | 按长度跟踪成功，修检查器并测试目标修改 |
| 奖励升高，独立质量下降 | 代理被利用 | 检查高奖励样本，增加对抗检查器案例 |
| 多数 GRPO 组任务优势为零 | 提示近乎不可能或已经解决 | 测通过率与采样成本，测试课程或重采样 |
| 多样性坍缩 | 过度优化或反复自过滤 | 监控 KL/多样性，验证更强锚定或新数据 |
| 拒绝无害请求 | 边界示例或评估只覆盖拒绝 | 配对有害与无害套件，加入上下文反例 |
| 评估好得不合理 | 训练/测试重叠、教师接触或谓词薄弱 | 审核提示来源、哈希、n-gram 和检查器语义 |
| 小提升重复后消失 | 套件或解码噪声，模板聚类 | 用配对/聚类分析、独立家族与重复采样 |
| 评判模型偏好每个新候选 | 位置、长度、家族偏差或准则泄漏 | 交换顺序、报告一致率、审核人工一致性并控制长度 |

适配器仍会遗忘，同策略偏好仍会造成似然位移，正 KL 权重也不能让不完整验证器变完整。这些诊断是待检验假设，不是方法名称提供的保证。
