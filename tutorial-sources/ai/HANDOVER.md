# Handover: the AI series

How to continue the tutorial series **From Machine Learning to Large Language Models** from where
it stands. Read this first, then `PLAN.md`.

## 1. What the series is

Ten modules, each a self-study unit of about ten hours, expanding ten concise tutorials kept in the
author's private repository (`docs/AI_Tutorials/`; ask the author for access). Each module has concept sections with
derivations and worked examples, runnable labs whose printed outputs come from real runs, 15 graded
exercises with full solutions, a 12-question quiz, guided paper reading, figures and two interactive
widgets. Every module is published in English and Simplified Chinese.

The pages will be published at `docs/tutorials/ai/` of this site (built HTML, in the same visual
style as the SysML v2, MBSE and AI Agents series), with a card on `docs/tutorials/index.md`. This
folder (`tutorial-sources/ai/`) holds the sources and the tools; it is outside `docs/`, so MkDocs
does not publish it.

## 4. Setting up

All commands run from this folder (`tutorial-sources/ai`) in a bash shell (Git Bash on Windows).

```bash
# Node 18 or later: the build, checks and rendering tools
(cd tools && npm install)

# Python 3.11 or later: the labs and the figure generators, CPU only
python -m venv .venv
.venv/Scripts/pip install torch --index-url https://download.pytorch.org/whl/cpu   # .venv/bin/pip on macOS/Linux
.venv/Scripts/pip install -r tools/requirements-labs.txt
```

`tools/labpy.sh` runs Python in that environment (or in `$AIS_PYTHON`) with the settings the labs
assume (non-interactive plots, four threads, the Hugging Face cache in `.hf/`). Rendering checks need
Chrome or Edge; set `CHROME_PATH` if it is not found. Local outputs (`out/`, `shots/`, `.venv/`,
`.hf/`, `tools/node_modules/`) are git-ignored.

This repository is public, so names from the author's private source repository never go into it.
`tools/check.mjs` blocks them in the published text using `notes/private-terms.txt`, a git-ignored
list (one regular expression per line). Ask the author for that file; without it the checker still
applies its generic rules.

## 5. How a module is produced

For each module, in this order. Each step names the guide that governs it.

1. **Prepare.** Read `BRIEF.md`, `SPEC.md`, `notes/CANONICAL.md`, the outline `plan/module_NN.json`
   and, if you have access, the source tutorial in the author's private repository (the outline
   captures its content, so the module can be written from the outline alone). `python tools/slice.py` writes a small
   per-part outline to `plan/slices/` if you split the writing between people or agents.
2. **Write** the seven part files of `src/en/module_NN/` (`notes/split.json` says which sections go
   where): `10-, 11-, 12-concepts-*.md` (concept sections, then "What goes wrong"), `20-, 21-labs-*.md`,
   `30-exercises.md`, `40-practice.md` (quiz, guided reading, summary, references). Follow `SPEC.md`.
3. **Run every lab**; the runner writes the real outputs into the page and captures plots:
   `tools/labpy.sh tools/labrun.py --module N --lab lab1 --update --add-missing`.
   Then make the prose agree with the real outputs.
4. **Check**: `node tools/check.mjs --module N --lang en --words` must report 0 errors. It validates
   every maths expression, the quiz syntax, section ids, study-plan links, internal links and the
   public-site rules, and prints word counts against the targets.
5. **Edit the module as a whole**: continuity across parts, one symbol per quantity, every item of the
   outline present, at most 18 figures, and the outline's display fields (lead, outcomes, study-plan
   text) polished, because the build puts them on the page.
6. **Figures** (`FIGURES.md`): draw `src/figures/en/fig-NN-k.svg` for every `::: figure` in the text,
   data plots through `figstyle.py` with a generator in `src/figures/en/_gen/`; render each with
   `node tools/shot.mjs src/figures/en/fig-NN-k.svg --out shots/fig-NN-k` and look at it; then make
   the Chinese copy in `src/figures/zh/`.
7. **Widgets** (`WIDGETS.md`): `node tools/widget-test.mjs <name> --lang en` (and `zh`) drives every
   control and screenshots it; `node tools/widget-probe.mjs <name> --set "0=0.5"` reads back the
   numbers so they can be checked against an independent calculation.
8. **Technical review**: recompute every derivation, worked example and quiz answer; check citations,
   dated claims and the case study's canonical numbers (`notes/CANONICAL.md`).
9. **Build and look**: `node tools/build.mjs --module N` writes `out/ai/module_NN_EN.html` (and
   `_ZH`); `node tools/shot.mjs out/ai/module_NN_EN.html --out shots/mNN --pages 8` must report no
   console, KaTeX, image or widget errors; look at the screenshots.
10. **Translate** (`TRANSLATION.md`, `GLOSSARY.md`): `src/zh/module_NN/<part>.md` for each part and
    `src/zh/module_NN.meta.json`; check each part with `node tools/check.mjs --module N --part <part>`.
    Code, outputs, maths and section ids stay identical to the English.
11. **Chinese check**: `node tools/check.mjs --module N` (both languages and their parity), then build
    and render the Chinese page.

## 6. Publishing

1. Translate `src/en/index.md` into `src/zh/index.md`.
2. Build into the site: `node tools/build.mjs --out ../../docs/tutorials/ai --modules 1,2,3,4` with
   the finished modules. `--modules` builds those modules in both languages, lists only them on the
   index pages, links each page's previous/next to the nearest published module, and turns links
   into unpublished modules into plain text, so no page links to a missing file. Without
   `--modules` it builds every module that has parts.
3. Add the card to `docs/tutorials/index.md`, next to the AI Agents series:

   ```markdown
   ## AI: From Machine Learning to Large Language Models

   A 10-module tutorial series, about ten hours per module, from machine learning foundations
   through neural networks, CNNs, RNNs and the transformer to large language models: pretraining,
   post-training and serving. Derivations, runnable labs, graded exercises with solutions and a
   quiz in every module. English and Chinese.

   [:octicons-arrow-right-24: Go to AI Tutorials](ai/index.html)
   ```

4. Check with the real site build from the repository root: `pip install -r requirements.txt` then
   `mkdocs build`, and open `site/tutorials/ai/index.html`.
5. Commit and push.

## 7. Open issues and decisions

1. **Length.** Finished modules have about 37,000–39,000 words of English prose each (concept text
   about 20,000 words against the outline's 15,000; exercises with full solutions about 10,000). That
   is realistically 12–15 hours of study, not 10. Decide whether to trim, or to describe the modules
   as about 12 hours (the page header and study-plan text say "about ten hours").
2. **Figure numbers** (fixed). Pages number figures by order of appearance, and the build rewrites
   each "Figure N.k" in the text (k is the figure id's number) to the number shown, so cutting or
   reordering figures leaves no gaps and ids never change (`SPEC.md`, section on figures).
   `check.mjs` warns about a reference whose figure is not on the page; Module 06 cites Figures
   6.19, 6.23 and 6.24 from sections not yet written.
3. **Unverified files**: `src/en/module_05/20-labs-a.md` was written but never run through
   `labrun.py`; the partial Module 06 lab files need finishing and running.
4. **Paper details** (checked). The guided-reading notes and the concept text's pointers into papers
   were checked against the papers; eleven statements were corrected (`notes/task-reports/paper-check.json`).
   Four sources were not reachable and were checked against preprints or secondary sources only:
   Domingos 2012, Rumelhart et al. 1986, and the journal versions of Kapoor and Narayanan and of
   Raissi et al. (`notes/PAPER-CHECK.md`). When writing new guided readings, name parts of a paper by
   topic or check the numbers against the version cited.
5. **Effort.** With Claude Code agents, finishing a module (write, edit, figures, widgets, labs,
   review, QA, translation) took about 25 agent tasks and several million tokens. Running many
   agents at once hit both the 5-hour and the weekly usage limits, so pace the work (a few agents at a
   time) and record completed tasks so a stopped run can resume.

## 8. Continuing with Claude Code

`tools/workflows/ai-series-build.js` is the workflow script that produced Modules 01–05. It runs,
per module and at a capped concurrency: the missing writer parts, the editor, then figures, widgets,
lab verification and a technical review in parallel, then English QA, translation and Chinese QA.
Each task records a completion marker in `done/<task-key>.json` (for example `m05-edit`), so a
stopped run resumes without repeating finished tasks. To reuse it, set `WS` in the script to this
folder, copy `notes/task-reports/*.json` into `done/`, and pass the remaining modules as arguments
(the `missing` parts per module, as in section 3).
