Lesson 1What are Git and GitHub?

What Git does, what GitHub adds, the handful of words you will meet, and what you will have built by the end of this series. No commands yet.

⏱ 15 minYou need: Nothing. Start here

In this lesson you will

  • Know what problem Git solves, and what GitHub adds to it
  • Know the difference between Git and GitHub
  • Recognise the words repository, commit, branch, remote, push, pull and pull request
  • Know what you will build in this series, and how the lessons work
1

The problem

You have probably seen a folder like this, or made one:

Copies like report-final-2-really-final.docx answer none of the questions you will have later:

  • Which version is the newest?
  • What exactly changed between two versions, and why?
  • How do I get back the paragraph I deleted last Tuesday?
  • My colleague edited the same file. How do we put our changes together?

Git answers all of them.

2

What Git does

Git is a program that looks after a folder for you. Whenever you like, you tell Git to take a snapshot of the files in the folder, with a short message saying what you did: “Add a contact page”, “Fix the spelling of the title”. Git keeps every snapshot you save, so you can always go back to it.

With those snapshots you can:

  • see the whole history of your project: what changed, when, who changed it, and why;
  • compare any two versions, line by line;
  • go back to any earlier version of a file, or of the whole project;
  • try out an idea on the side, and keep it or drop it without touching your working version;
  • combine your work with other people’s work.
Think of it like this

Think of the save points in a video game. You save before the difficult part. If it goes wrong, you go back to the save point and try again. Git gives you save points for your work, as many as you like, each with a note saying what you did.

Git runs on your own computer and works without the internet. It works with any kind of file, but it is best with text: web pages, program code, notes, data, LaTeX papers. Word files, images and PDFs can be kept too, but Git cannot show you what changed inside them. Most software in the world is kept in Git.

3

What GitHub adds

GitHub is a website, github.com, that keeps a copy of your Git projects on the internet. That gives you:

  • a backup: if your laptop breaks, your work and its history are safe;
  • the same work on several computers, kept in step;
  • working with other people: they can see your project, suggest changes, and you review them before they go in;
  • a free website for your project, with GitHub Pages.
Key idea

Git is the tool; GitHub is a website built around it. You can use Git without GitHub. GitHub is one of several such websites (GitLab and Bitbucket are others). The Git you learn here works with all of them; only their websites look different.

The words you will meet

How the lessons work

Each lesson takes 15 to 45 minutes. Do them in order: each one starts where the last one ended.

Type every command yourself, in a terminal: a window where you give the computer instructions by typing them. Lesson 2 shows you how to open one. Commands appear in dark boxes like this one, after a $, followed by what the computer answers:

Terminal
$ git statusOn branch main
nothing to commit, working tree clean

The $ is not part of the command: type only what comes after it, then press Enter (Return on a Mac). There is nothing to type yet: this box is only an example.

Compare your answer with the one shown. Every answer in this series was produced by actually running the commands, so yours should look the same, except for a few things that are different on every computer: the long codes called hashes (like c50e3a0), dates and times, the path to your home folder, version numbers, and sizes and speeds. Everything else should match. If it does not, look for the If something went wrong box below the step, or the troubleshooting page.

Where Windows, macOS and Linux differ, the lesson has a tab for each system, and opens yours first. You will also see these boxes:

7

What you learned

  • Git keeps the history of a project folder as a series of snapshots called commits, on your own computer.
  • GitHub is a website that keeps a copy online, so you can back it up, share it, work with others and publish it.
  • You will build a small web page, step by step, and put it online in Lesson 8.
  • Type every command yourself, without the $, and compare what you see with the lesson.
8

Check yourself

1
What is the difference between Git and GitHub?
You can use Git on its own, offline. GitHub adds backup, sharing, collaboration and web pages.
2
What is a commit?
Every commit records what changed, who made the change, when, and why.
3
Do you need an internet connection to use Git?
Git keeps everything on your computer. You need the internet only to push to GitHub and pull from it.
