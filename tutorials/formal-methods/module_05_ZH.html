模块 5归纳与递归

递归地定义数、列表和树上的函数，并逐步计算它们的结果。在纸上和 Isabelle 中用归纳法证明一般命题，理解为什么 Isabelle 的 fun 需要终止性证明。

递归定义

循环描述重复性工作，其可能终止也可能不终止。一个递归定义通过函数自身来描述函数。本模块中的定义在某种意义上对更小的参数调用函数，从而保证终止。“和 0 + 1 + ⋯ + n 是直到 n − 1 的和加上 n”便是此类定义。递归定义简短且精确，且可与之进行计算。它们配有相应的证明方法，归纳，该方法一次性证明针对无穷多输入中每一个的命题。

递归和归纳是 Isabelle/HOL 的核心。你在本系列中定义的函数几乎都是递归的，关于这些函数的证明也几乎都要用到归纳。本模块讲授这两者，先在纸上讲，再到 Isabelle 中做。

从零构造自然数

从 0 出发，反复加 1 足够多次，就能到达任何一个自然数：3 就是 0 + 1 + 1 + 1。朱塞佩·皮亚诺（Giuseppe Peano）在 1889 年把这一观察作为算术的基础，它也是本模块所有内容的基础。

定义 5.1自然数

自然数（natural numbers）N={0,1,2,… }\N = \{0, 1, 2, \dots\}N={0,1,2,…} 由两个构造子（constructor）构造而成：000 是自然数；如果 nnn 是自然数，那么它的后继（successor）Suc n\mathit{Suc}\ nSuc n（读作“n 的后继”）也是自然数，也就是 n+1n + 1n+1⁠。除此之外没有别的自然数。不同的构造方式给出不同的数：0≠Suc n0 \neq \mathit{Suc}\ n0=Suc n⁠，并且只有当 m=nm = nm=n 时才有 Suc m=Suc n\mathit{Suc}\ m = \mathit{Suc}\ nSuc m=Suc n⁠。

所以每个自然数要么是 0，要么是 Suc m，而且这样的 m 恰好只有一个：3 就是 Suc (Suc (Suc 0))。Isabelle 的类型 nat 正是这样构造的。它把数打印成通常的数字，但 3 和 Suc (Suc (Suc 0)) 是同一个值：

Isabelle
value "Suc (Suc (Suc 0))"
输出
"3"
  :: "nat"

正因为每个数要么是 0，要么是某个数的后继，递归定义才行得通。要在整个 N\NN 上定义一个函数，只需说明它在 0 处做什么，再借助它在 nnn 处做的事，说明它在 n+1n + 1n+1 处做什么。

数上的四个函数

下面是和 0+1+⋯+n0 + 1 + \dots + n0+1+⋯+n 的递归定义，我们把它叫做 sum_upto\mathit{sum\_upto}sum_upto⁠：

sum_upto(0)=0sum_upto(n+1)=sum_upto(n)+(n+1)\begin{aligned} \mathit{sum\_upto}(0) &= 0\\ \mathit{sum\_upto}(n+1) &= \mathit{sum\_upto}(n) + (n+1) \end{aligned} sum_upto(0)sum_upto(n+1)​=0=sum_upto(n)+(n+1)​

第一个等式是基础情形（base case）。第二个等式是递归情形（recursive case），它用到 nnn 为止的和来定义到 n+1n + 1n+1 为止的和，而前者正是同一个问题的一个更小的实例。由于每个数要么是 0，要么对某个 nnn 等于 n+1n + 1n+1⁠，这两个等式覆盖了每一个数，而且每个数恰好只被覆盖一次。

定义 5.2递归定义

递归定义使用的等式允许右边再次出现所定义的函数。本节定义的都是全函数，因此这些等式覆盖所有实参，在匹配范围重叠时给出的结果一致，而且递归调用的实参在某个良基关系下逐步减小。基本情形不调用函数本身，递归情形则会再次调用它。

另外三个函数也遵循同样的模式：阶乘 n!=1⋅2⋅…⋅nn! = 1 \cdot 2 \cdot \ldots \cdot nn!=1⋅2⋅…⋅n⁠，这里叫做 fac\mathit{fac}fac⁠；幂 xnx^nxn⁠，叫做 pow\mathit{pow}pow⁠；以及斐波那契数 0、1、1、2、3、5、8、13……，其中每个数都是它前面两个数之和。

在 Isabelle 中检验

在 Isabelle 中，fun 用这样的等式来定义函数，等式之间用 | 分隔。纸上写 n+1n + 1n+1 的地方，模式（pattern）中写的是 Suc n：

Isabelle
fun sum_upto :: "nat ⇒ nat" where
  "sum_upto 0 = 0"
| "sum_upto (Suc n) = sum_upto n + Suc n"
输出
consts
  sum_upto :: "nat ⇒ nat"

Found termination order: "size <*mlex*> {}"

Isabelle 报告了新常量和它的类型，并说它找到了一个“终止序”（termination order）；第 5.7 节会解释这是什么意思。另外三个函数是：

Isabelle
fun fac :: "nat ⇒ nat" where
  "fac 0 = 1"
| "fac (Suc n) = fac n * Suc n"

fun pow :: "nat ⇒ nat ⇒ nat" where
  "pow x 0 = 1"
| "pow x (Suc n) = pow x n * x"

fun fib :: "nat ⇒ nat" where
  "fib 0 = 0"
| "fib (Suc 0) = 1"
| "fib (Suc (Suc n)) = fib n + fib (Suc n)"

模式 Suc 0 只匹配数 1，而 Suc (Suc n) 匹配从 2 开始的每个数，这时 n 比这个数小 2。现在来计算几个值：

Isabelle
value "[sum_upto 3, fac 5, pow 2 10, fib 10]"
输出
"[6, 120, 1024, 55]"
  :: "nat list"

求值就是重写

怎样根据这些等式计算 sum_upto(3)\mathit{sum\_upto}(3)sum_upto(3)⁠？把每个等式从左往右读，当作一条重写规则（rewrite rule）：只要某个项与等式的左边匹配，就可以把它替换成等式的右边。由于 3=2+13 = 2 + 13=2+1⁠，递归情形在 n=2n = 2n=2 时适用，依此类推，一直到 0：

sum_upto(3)=sum_upto(2)+3=(sum_upto(1)+2)+3=((sum_upto(0)+1)+2)+3=((0+1)+2)+3=6\begin{aligned} \mathit{sum\_upto}(3) &= \mathit{sum\_upto}(2) + 3\\ &= (\mathit{sum\_upto}(1) + 2) + 3\\ &= ((\mathit{sum\_upto}(0) + 1) + 2) + 3\\ &= ((0 + 1) + 2) + 3\\ &= 6 \end{aligned} sum_upto(3)​=sum_upto(2)+3=(sum_upto(1)+2)+3=((sum_upto(0)+1)+2)+3=((0+1)+2)+3=6​

其中三步用的是递归情形，一步用的是基础情形，最后一步做算术。每一步都有一个等式作为依据，所以这一串等式同时也是 sum_upto(3)=6\mathit{sum\_upto}(3) = 6sum_upto(3)=6 的一个证明。

定义 5.3通过重写求值

为了评估通过重写项，反复选择匹配方程左侧的项部分，并用方程右侧替换它，其中方程的变量被替换为它们匹配的部分。没有适用重写的项处于正规形式对于这些规则。对于这里的封闭表达式和完整定义，评估达到一个值，例如数字或列表。带有自由变元的表达式可能停在符号结果；正规形式不一定是具体值。

一个项中常常有好几个部分都可以重写。本模块的做法和大多数编程语言一样：先对调用的参数求值，再执行调用本身，这叫做传值调用（call by value）。也就是说，它总是重写最左边的、参数都已经是值的那个调用或算术运算。对本模块的函数来说，重写的顺序会改变你中途看到的项，但从不改变最终的值。

须知

对于封闭的可执行表达式，Isabelle 的 value 通常将方程转化为程序并运行，它不显示上述重写序列。带有自由变元的表达式可以进行符号求值，如下面的列表示例所示。化简器 simp 执行产生证明的重写：它使用用 fun 定义的每个函数的定义方程作为重写规则，正如您在第 5.4 节中将要看到的那样。

列表与树

数由 0 和 Suc 构造而成。列表和树也以同样的方式由少数几个构造子构造而成，在它们上面的递归和在数上的递归完全一样。

列表

你在模块 1 中见过 Isabelle 的列表。列表有两个构造子：[] 是空列表（empty list），x # xs（读作“x cons xs”）把元素 x 放在列表 xs 的前面。列表 [1, 2, 3] 是 1 # (2 # (3 # [])) 的简写，又因为 # 向右结合，你也可以把它写成 1 # 2 # 3 # []。一个列表的所有元素都具有相同的类型：nat list 是自然数列表的类型，'a list（读作“alpha list”）是元素属于某个类型 'a 的列表的类型。

定义 5.4列表

每个列表要么是空列表[]，要么是 x # xs：把一个头部（head）x 放在一个尾部（tail）xs 的前面。除此之外没有别的列表，而且以不同方式构造的列表是不同的：x # xs ≠ []，并且只有当 x = y 且 xs = ys 时才有 x # xs = y # ys。

Isabelle
value "1 # 2 # [3 :: nat]"
输出
"[1, 2, 3]"
  :: "nat list"

Isabelle 以简记法打印结果。列表上的直接结构定义处理 [] 和 x # xs。以下是四个：列表长度、两个列表的连接、列表反转以及数字列表的求和。

Isabelle
fun len :: "'a list ⇒ nat" where
  "len [] = 0"
| "len (x # xs) = len xs + 1"

fun app :: "'a list ⇒ 'a list ⇒ 'a list" where
  "app [] ys = ys"
| "app (x # xs) ys = x # app xs ys"

fun reverse :: "'a list ⇒ 'a list" where
  "reverse [] = []"
| "reverse (x # xs) = app (reverse xs) [x]"

fun lsum :: "nat list ⇒ nat" where
  "lsum [] = 0"
| "lsum (x # xs) = x + lsum xs"

app 的第二个等式可以这样读：要把 x # xs 放到 ys 前面，先把 xs 放到 ys 前面，再把 x 放到结果的前面。reverse 的第二个等式说：先反转尾部，再把头部接到末尾。本模块用函数名加编号来指称等式：app.2 是 app 的第二个等式。Isabelle 把它叫做 app.simps(2)。

库中已经有这四个函数，名字分别是 length、@（你在模块 1 中见过）、rev 和 sum_list。库中的理论 List.thy 正是用这些等式来定义 @ 和 rev 的，例如 [] @ ys = ys 和 (x # xs) @ ys = x # xs @ ys；length 和 sum_list 的定义方式不同，但满足同样的等式。这里你自己定义它们的版本，一是为了看清它们是怎样工作的，二是因为这样一来，关于它们的每一个事实，Isabelle 都必须在你的帮助下从头证明。

value 不仅能处理数，也能处理变量：

Isabelle
value "reverse [a, b, c]"
输出
"[c, b, a]"
  :: "'a list"

二叉树：你的第一个数据类型

列表是数据类型（datatype）的一个例子：数据类型的值由构造子构造而成。你也可以定义自己的数据类型。一棵二叉树（binary tree）要么是空树，要么是一个结点，结点中存放一个元素和两棵更小的树，即它的左子树和右子树：

Isabelle
datatype 'a tree2 = Tip | Node "'a tree2" 'a "'a tree2"

这样读：元素类型为 'a 的树，要么是空树 Tip，要么是 Node l x r，其中有左子树 l、元素 x 和右子树 r。Node 的各个参数的类型写在它的名字后面；凡是不只是单个名字或类型变元的类型，都要放在引号里。Isabelle 自带一个关于树的库理论，其中的类型叫做 tree（它不属于 Main），所以这里的类型叫做 tree2，以便把两者区分开。

定义 5.5数据类型

数据类型是一种类型，它的值由构造子构造而成。每个值都是通过有限次应用构造子得到的，而以不同方式构造的值是不同的。命令 datatype 引入一个新类型及其构造子，Isabelle 会自动证明：不同的构造子给出不同的值，并且每个构造子都是单射。

图 5.1 左边的树有 4 个结点和 5 个 Tip。下面是树上的三个函数：mirror 在每一处交换左右，nodes 数结点的个数，tips 数 Tip 的个数。

Isabelle
fun mirror :: "'a tree2 ⇒ 'a tree2" where
  "mirror Tip = Tip"
| "mirror (Node l x r) = Node (mirror r) x (mirror l)"

fun nodes :: "'a tree2 ⇒ nat" where
  "nodes Tip = 0"
| "nodes (Node l x r) = nodes l + nodes r + 1"

fun tips :: "'a tree2 ⇒ nat" where
  "tips Tip = 1"
| "tips (Node l x r) = tips l + tips r"

每个递归案例调用函数两次，分别针对每个子树。两个子树均小于原树，因此递归调用在结构大小上递减。方程也覆盖了两个构造器且无冲突。

Isabelle
value "mirror (Node (Node Tip 1 Tip) 2 (Node (Node Tip 3 Tip) 4 Tip) :: nat tree2)"
输出
"Node (Node Tip 4 (Node Tip 3 Tip)) 2 (Node Tip 1 Tip)"
  :: "nat tree2"

标注 :: nat tree2 说明元素是自然数，就像模块 1 中的 :: nat 对数所起的作用一样。

作为定义，fib 是合理的：它精确地说明了斐波那契数的含义。作为程序，它运行缓慢。一个保留最后两个值的程序以与 n 成正比的加法次数计算 fib n，尽管递增整数的加法成本不是常数。证明此类更快的程序计算与清晰定义相同的函数是一个典型的验证任务，Modules 11 和 12 执行了此类证明。

数学归纳法

对任何一个具体的 nnn⁠，value 都能算出 sum_upto(n)\mathit{sum\_upto}(n)sum_upto(n)⁠，测试也能做到。但像“对每个 nnn⁠，2⋅sum_upto(n)=n⋅(n+1)2 \cdot \mathit{sum\_upto}(n) = n \cdot (n+1)2⋅sum_upto(n)=n⋅(n+1)⁠”这样的断言涉及无穷多个数，而正如模块 1 所说，再多的测试也覆盖不了所有的数。你需要一个对所有的 nnn 一次性成立的论证。数学归纳法（mathematical induction）就是这样一种论证。

原理

假设你已经证明了两件事：断言对 0 成立；并且只要它对某个数 nnn 成立，它就对 n+1n + 1n+1 也成立。那么它对 0 成立，因而对 1 成立，因而对 2 成立，依此类推。从 0 出发，经过有限次 +1+1+1 就能到达每一个自然数，所以断言能一直传递到每一个数。图 5.3 给出了常用的比喻：一排多米诺骨牌。

事实 5.1数学归纳法

设 P(n)P(n)P(n) 是关于自然数 nnn 的一个陈述。如果

  1. 基础情形：P(0)P(0)P(0) 成立，并且
  2. 归纳步骤（induction step）：对每个 nnn⁠，P(n)P(n)P(n) 蕴涵 P(n+1)P(n+1)P(n+1)⁠，

那么 P(n)P(n)P(n) 对每个自然数 nnn 都成立。在归纳步骤中，假设 P(n)P(n)P(n) 称为归纳假设（induction hypothesis，常简写为 IH）。

在 Modules 2 和 3 的应用符号中：P 0∧(∀n. P n⟶P (n+1))⟶(∀n. P n)P\ 0 \land (\forall n.\ P\ n \imp P\ (n+1)) \imp (\forall n.\ P\ n)P 0∧(∀n. P n⟶P (n+1))⟶(∀n. P n)⁠. 将其读作“若 P 0 成立，且对所有 n，P n 蕴含 P (n + 1)，则对所有 n，P n 成立”。

为什么这是一种正确的证明方式？除了多米诺骨牌之外，这里还有第二个论证。假设 PPP 对某个数不成立。在所有使它不成立的数中，取最小的一个，记为 mmm⁠。mmm 不是 0，因为 P(0)P(0)P(0) 成立。所以对某个 kkk 有 m=k+1m = k + 1m=k+1⁠，并且 P(k)P(k)P(k) 成立，因为 k<mk < mk<m⁠，而 mmm 是使 PPP 不成立的最小的数。但这样一来，归纳步骤就给出了 P(k+1)P(k + 1)P(k+1)⁠，也就是 P(m)P(m)P(m)⁠：矛盾。这个论证用到了 N\NN 的一个性质：自然数的每个非空集合都有最小元素。用模块 4 的话说，N\NN 上的序 <<< 是良基的（well-founded）：不存在无穷递降链 n0>n1>n2>⋯n_0 > n_1 > n_2 > \cdotsn0​>n1​>n2​>⋯⁠。第 5.6 节和第 5.7 节都建立在这一点之上。

归纳不一定从 0 开始。要证明 P(n)P(n)P(n) 对每个 n≥kn \ge kn≥k 都成立，只需证明 P(k)P(k)P(k)⁠，并证明对每个 n≥kn \ge kn≥k⁠，P(n)P(n)P(n) 蕴涵 P(n+1)P(n + 1)P(n+1)⁠。

怎样写归纳证明

提示

一个归纳证明由五个部分组成。每次都把它们全部写出来。

  1. 说明你对哪个变量做归纳，并准确地陈述 P(n)P(n)P(n)⁠。
  2. 基础情形：证明 P(0)P(0)P(0)⁠。
  3. 归纳步骤：取任意一个 nnn⁠，写下归纳假设 P(n)P(n)P(n)⁠。
  4. 写下目标 P(n+1)P(n + 1)P(n+1) 并证明它。标出用到归纳假设的那一步。如果你根本没有用到归纳假设，那么要么证明有错，要么这个证明本来就不需要归纳。
  5. 下结论：由归纳法，P(n)P(n)P(n) 对每个 nnn 都成立。

第二个例子证明一个不等式。不等式的证明不像等式那样完全机械，因为你得决定要估计什么。

例 5.22 的幂比 n 增长得快

断言：对每个自然数 nnn⁠，n<pow(2,n)n < \mathit{pow}(2, n)n<pow(2,n)⁠。

证明：对 nnn 做归纳。

基础情形：由 pow.1，0<1=pow(2,0)0 < 1 = \mathit{pow}(2, 0)0<1=pow(2,0)⁠。

归纳步骤：设归纳假设 n<pow(2,n)n < \mathit{pow}(2, n)n<pow(2,n) 成立，要证明 n+1<pow(2,n+1)n + 1 < \mathit{pow}(2, n+1)n+1<pow(2,n+1)⁠。在自然数上，n<pow(2,n)n < \mathit{pow}(2, n)n<pow(2,n) 意味着 pow(2,n)≥n+1\mathit{pow}(2, n) \ge n + 1pow(2,n)≥n+1⁠，特别地，pow(2,n)≥1\mathit{pow}(2, n) \ge 1pow(2,n)≥1⁠。所以

pow(2,n+1)=pow(2,n)⋅2=pow(2,n)+pow(2,n)  ≥  (n+1)+1  >  n+1,\mathit{pow}(2, n+1) = \mathit{pow}(2, n) \cdot 2 = \mathit{pow}(2, n) + \mathit{pow}(2, n) \;\ge\; (n + 1) + 1 \;>\; n + 1, pow(2,n+1)=pow(2,n)⋅2=pow(2,n)+pow(2,n)≥(n+1)+1>n+1,

这里先用了 pow.2，然后对两个加数都用了归纳假设。由归纳法，断言对每个 nnn 都成立。

注意

两个部分缺一不可。取 P(n)P(n)P(n) 为“n=n+1n = n + 1n=n+1⁠”。归纳步骤是成立的：如果 n=n+1n = n + 1n=n+1⁠，两边同时加 1 就得到 n+1=n+2n + 1 = n + 2n+1=n+2⁠。但基础情形 0=10 = 10=1 是假的，这个断言也是假的。没有基础情形，归纳步骤什么也证明不了。

归纳步骤必须对每个 nnn 都成立，包括最小的那个。有一个著名的错误证明，声称在任何一群 n≥1n \ge 1n≥1 匹马中，所有的马颜色都相同。基础情形：一匹马只有一种颜色。归纳步骤：从一群 n+1n + 1n+1 匹马中牵走一匹，由归纳假设，剩下的 nnn 匹颜色相同。把它牵回来，再牵走另一匹，剩下的 nnn 匹同样颜色相同。这两群马有重叠，所以全部 n+1n + 1n+1 匹马颜色都相同。漏洞在于：当 n=1n = 1n=1 时，两群马各只有一匹，并不重叠。从 1 到 2 的那一步不成立，所以骨牌在第一块之后就停住了。

Isabelle 中的归纳

Isabelle 也能检查归纳证明。你陈述引理，并告诉 Isabelle 使用归纳；Isabelle 随后把基础情形和归纳步骤显示为两个单独的目标，由你来证明。读懂这些目标，是本节要掌握的主要技能。

为什么光用 simp 不够

试着只用化简器来证明求和公式：

Isabelle故意出错的例子
lemma "2 * sum_upto n = n * (n + 1)"
  by simp
输出
Failed to finish proof⌂:
goal (1 subgoal):
 1. 2 * sum_upto n = n + n * n

化简器把 n * (n + 1) 重写成了 n + n * n，却动不了 sum_upto n。sum_upto 的两个等式都不与它匹配：第一个需要 0，第二个需要某个东西的 Suc，而 n 是一个任意的数，化简器对它一无所知。归纳恰好把证明分成这两种情况。

证明状态中的基础情形和归纳步骤

再次陈述这条引理，给它起个名字，并要求对 n 做归纳：

Isabelle
lemma sum_formula: "2 * sum_upto n = n * (n + 1)"
  apply (induction n)
输出
proof (prove)
goal (2 subgoals):
 1. 2 * sum_upto 0 = 0 * (0 + 1)
 2. ⋀n. 2 * sum_upto n = n * (n + 1) ⟹
        2 * sum_upto (Suc n) = Suc n * (Suc n + 1)

apply 把一个证明方法（proof method）应用到目标上，并显示还剩下什么要证明；方法 induction n 对 n 做归纳。原来的一个目标变成了两个子目标（subgoal）。子目标 1 是基础情形：把断言中的 n 换成 0。子目标 2 是归纳步骤，其中出现了两个新符号：

  • ⋀n.（输入 \And 或 !!）的意思是“对任意的 n”：在这个子目标中，n 代表任意一个数，除了子目标本身所说的以外，对它一无所知。
  • A ⟹ B（输入 ==>）的意思是“A 蕴涵 B”：要证明这个子目标，就要证明 B，而你可以假设 A。

⟹ 的左边是归纳假设；右边是关于 Suc n（也就是 n+1n + 1n+1⁠）的断言。和例 5.1 的纸上证明对照如下：

纸上证明 Isabelle 的子目标
基础情形 P(0)P(0)P(0) 1. 2 * sum_upto 0 = 0 * (0 + 1)
取任意一个 nnn 2. ⋀n.
设归纳假设 P(n)P(n)P(n) 成立 2 * sum_upto n = n * (n + 1) ⟹
证明 P(n+1)P(n + 1)P(n+1) 2 * sum_upto (Suc n) = Suc n * (Suc n + 1)

现在逐个证明这些子目标。simp 作用于第一个子目标：

Isabelle
  apply simp
输出
proof (prove)
goal (1 subgoal):
 1. ⋀n. 2 * sum_upto n = n * (n + 1) ⟹
        2 * sum_upto (Suc n) = Suc n * (Suc n + 1)

基础情形消失了：simp 用第一个等式把 sum_upto 0 重写成 0，并把两边都化成了 0。剩下的是归纳步骤。再应用一次 simp：

Isabelle
  apply simp
输出
proof (prove)
goal:
No subgoals!

在归纳步骤中，simp 用了 sum_upto 的第二个等式、归纳假设（化简器会使用 ⟹ 左边的假设）以及算术：正是纸上证明用到的那三样东西。已经没有子目标了，用 done 结束证明：

Isabelle
  done

现在这条引理成了一个名为 sum_formula 的定理，后面的证明可以使用它。

须知

由一串 apply 步骤组成、以 done 结尾的证明称为 apply 脚本（apply script）。模块 7 会用这种风格一步一步地构造证明，模块 10 则会介绍 Isar，一种读起来更像纸上证明的证明语言。目前，要查看各个步骤之间的证明状态，apply 脚本是最好的方式：把光标放在任意一行的后面，就能看到那一处的证明状态。

一行写完整个证明

一旦知道了证明的思路，你就可以把它写成一行：

Isabelle
lemma "2 * sum_upto n = n * (n + 1)"
  by (induction n) simp_all

lemma pow_gt: "n < pow 2 n"
  by (induction n) auto

by m₁ m₂ 先应用方法 m₁，再应用 m₂，如果最后还有子目标剩下，它就会失败。simp 不能用作 m₂，因为它只作用于第一个子目标；simp_all 会化简所有子目标，auto 也作用于所有子目标，它把化简和逻辑推理结合在一起。如果一个归纳的基础情形和归纳步骤都能由定义和归纳假设推出，首先就该试试 by (induction n) auto。

如果出了问题
  • Failed to finish proof 在 by simp 或 by auto 之后，且满足 sum_upto n（或另一个递归 应用于变量的函数）仍保留在目标中。 归纳法可能揭示定义情况。对于求和公式，尝试 by (induction n) auto；其他目标可能需要引理或不同的论证。
  • by (induction n) auto 之后出现 Failed to finish proof。查看剩下的子目标。第 5.5 节和第 5.6 节给出了常见的原因：对错误的变量做了归纳、缺少一条引理，以及归纳假设太弱。
  • 没有显示证明状态。按模块 1 所说，在 Output（输出）面板中勾选 Proof state（证明状态），并把光标放在 apply 那一行的末尾。

结构归纳法

自然数上的归纳遵循数的构造方式，即从 0 和 Suc 构造。每种数据类型都以同样的方式由它的构造子构造而成，所以每种数据类型都有一个形式相同的归纳原理，称为结构归纳法（structural induction）。

列表上的归纳

事实 5.2列表上的结构归纳法

设 P(xs)P(xs)P(xs) 是关于列表 xsxsxs 的一个陈述。如果

  1. P([ ])P([\,])P([]) 成立，并且
  2. 对每个 xxx 和 xsxsxs⁠，P(xs)P(xs)P(xs) 蕴涵 P(x#xs)P(x \mathbin{\#} xs)P(x#xs)⁠，

那么 P(xs)P(xs)P(xs) 对每个列表 xsxsxs 都成立。

它成立的理由和数上的归纳一样：每个列表都是从 [] 出发、有限次使用 # 构造出来的。实际上，它就是换了个样子的、对列表长度的归纳。下面的证明用 Isabelle 的记号书写等式，每行一步，就像前面 reverse [1, 2] 的求值过程那样。

例 5.3连接后的长度

断言：对所有列表 xs 和 ys，len (app xs ys) = len xs + len ys。

应该对哪个变量做归纳？app 会拆开它的第一个参数（app.2），而不去动第二个参数。所以对 xs 做归纳，并保持 ys 固定：P(xs)P(xs)P(xs) 就是 len (app xs ys) = len xs + len ys。

基础情形，xs = []：

  len (app [] ys)
= len ys                     由 app.1
= 0 + len ys                 算术
= len [] + len ys            由 len.1

归纳步骤：设归纳假设 len (app xs ys) = len xs + len ys 成立，证明断言对 x # xs 也成立：

  len (app (x # xs) ys)
= len (x # app xs ys)        由 app.2
= len (app xs ys) + 1        由 len.2
= len xs + len ys + 1        由归纳假设
= (len xs + 1) + len ys      算术
= len (x # xs) + len ys      由 len.2
在 Isabelle 中检验

树上的归纳

事实 5.3树上的结构归纳法

设 P(t)P(t)P(t) 是关于树 ttt 的一个陈述。如果

  1. P(Tip)P(\mathit{Tip})P(Tip) 成立，并且
  2. 对所有 lll⁠、xxx 和 rrr⁠，P(l)P(l)P(l) 和 P(r)P(r)P(r) 合起来蕴涵 P(Node l x r)P(\mathit{Node}\ l\ x\ r)P(Node l x r)⁠，

那么 P(t)P(t)P(t) 对每棵树 ttt 都成立。

现在归纳步骤有两个归纳假设，每棵子树各一个，因为一个结点是由两棵更小的树构造而成的。

归纳步骤：设两个归纳假设 mirror (mirror l) = l 和 mirror (mirror r) = r 都成立：

  mirror (mirror (Node l x r))
= mirror (Node (mirror r) x (mirror l))             由 mirror.2
= Node (mirror (mirror l)) x (mirror (mirror r))    由 mirror.2
= Node l x r                                        由两个归纳假设

当归纳需要一条引理时

把一个列表反转两次，会得到原来的列表。试着用通常的方式证明它：

Isabelle故意出错的例子
lemma "reverse (reverse xs) = xs"
  by (induction xs) auto
输出
Failed to finish proof⌂:
goal (1 subgoal):
 1. ⋀a xs.
       reverse (reverse xs) = xs ⟹ reverse (app (reverse xs) [a]) = a # xs

基础情形通过了，归纳步骤却没有。auto 把 reverse (reverse (a # xs)) 展开成 reverse (app (reverse xs) [a])，然后就卡住了：归纳假设说的是 reverse (reverse xs)，而目标是把 reverse 作用在一个 app 上，没有哪个等式说明这时该怎么办。用定义来重写帮不上忙；缺少的是一个关于 reverse 和 app 的事实。卡住的目标告诉你该找什么：reverse 作用在 app 上会怎样？把两个连接起来的列表反转，就是把两部分各自反转，再交换它们的位置。

例 5.5连接后的反转

这个证明需要两个关于 app 的简单事实。两者都对 xs 做归纳来证明：

  • 引理 A：app xs [] = xs。基础情形：由 app.1，app [] [] = []。归纳步骤：由 app.2 和归纳假设，app (x # xs) [] = x # app xs [] = x # xs。
  • 引理 B：app (app xs ys) zs = app xs (app ys zs)。基础情形：由 app.1，两边都是 app ys zs。归纳步骤：app (app (x # xs) ys) zs = app (x # app xs ys) zs = x # app (app xs ys) zs，由归纳假设，它等于 x # app xs (app ys zs)，再由 app.2，这就是 app (x # xs) (app ys zs)。

引理 C：reverse (app xs ys) = app (reverse ys) (reverse xs)，对 xs 做归纳。基础情形：reverse (app [] ys) = reverse ys，由引理 A，它等于 app (reverse ys) []，而 reverse [] = []。归纳步骤：

  reverse (app (x # xs) ys)
= reverse (x # app xs ys)                      由 app.2
= app (reverse (app xs ys)) [x]                由 reverse.2
= app (app (reverse ys) (reverse xs)) [x]      由归纳假设
= app (reverse ys) (app (reverse xs) [x])      由引理 B
= app (reverse ys) (reverse (x # xs))          由 reverse.2

定理：reverse (reverse xs) = xs，对 xs 做归纳。基础情形：两次使用 reverse.1，得 reverse (reverse []) = []。归纳步骤要用到 reverse [x] = app [] [x] = [x]：

  reverse (reverse (x # xs))
= reverse (app (reverse xs) [x])               由 reverse.2
= app (reverse [x]) (reverse (reverse xs))     由引理 C
= app [x] xs                                   由 reverse [x] = [x] 和归纳假设
= x # xs                                       由 app.2 和 app.1

Isabelle

  by (induction xs) auto

  by (induction xs) auto

属性（attribute）[simp] 使一条引理成为化简规则（simplification rule）：从此以后，simp 和 auto 会像使用定义等式一样，用它来重写。reverse_app 的证明就是这样用上 app_nil 和 app_assoc 的，reverse_reverse 的证明也是这样用上 reverse_app 的。如果你在这两条引理之前就去证明 reverse_app，它会卡在需要这两条引理的目标上，就像 reverse_reverse 在没有 reverse_app 时卡住一样。模块 9 会解释哪些引理适合用作化简规则。

要点

当归纳法陷入停滞时，请阅读停滞的目标。它通常包含一个无法被任何等式重写的项，例如 reverse (app (reverse xs) [a])。找到关于该项的一般事实，将其作为引理证明（通常通过归纳法本身），使其对证明可用，然后重试。上述引理适合作为 [simp] 规则；若以这种方式注册，任意引理可能导致无用的重写或循环。Module 9 讨论了该选择，Module 11 发展了归纳策略。

6

强归纳法

在普通的归纳中，归纳步骤证明 P(n+1)P(n + 1)P(n+1) 时只能使用 P(n)P(n)P(n)⁠，也就是紧挨在它前面的那块骨牌。有些证明需要更多。斐波那契数要往回看两步，而一个数的因数可以是任何比它小的数，不只是它前面的那一个。

事实 5.4强归纳法

设 P(n)P(n)P(n) 是关于自然数 nnn 的一个陈述。如果对每个 nnn⁠，由“P(m)P(m)P(m) 对所有 m<nm < nm<n 成立”（归纳假设）都能推出 P(n)P(n)P(n)⁠，那么 P(n)P(n)P(n) 对每个自然数 nnn 都成立。

用符号写就是：(∀n. (∀m<n. P(m))⟶P(n))⟶(∀n. P(n))(\forall n.\ (\forall m < n.\ P(m)) \imp P(n)) \imp (\forall n.\ P(n))(∀n. (∀m<n. P(m))⟶P(n))⟶(∀n. P(n))⁠。其中 ∀m<n. P(m)\forall m < n.\ P(m)∀m<n. P(m) 读作“对所有小于 n 的 m，P(m) 成立”，它是 ∀m. m<n⟶P(m)\forall m.\ m < n \imp P(m)∀m. m<n⟶P(m) 的简写，就像模块 4 中的有界量词 ∀x∈A\forall x \in A∀x∈A 一样。强归纳法（strong induction）也叫完全归纳法（complete induction）或累积归纳法（course-of-values induction）。它没有单独的基础情形。当 n=0n = 0n=0 时，不存在 m<0m < 0m<0⁠，所以归纳假设什么也没说，P(0)P(0)P(0) 必须在没有任何帮助的情况下证明；在实践中，用强归纳法的证明会单独处理最小的几个值。

强归纳法并不比普通的归纳更强，它可以由普通的归纳推出。对陈述 Q(n)Q(n)Q(n)⁠：“P(m)P(m)P(m) 对每个 m<nm < nm<n 成立”应用普通的归纳。Q(0)Q(0)Q(0) 成立，因为不存在 m<0m < 0m<0⁠。如果 Q(n)Q(n)Q(n) 成立，那么由强归纳法的前提，P(n)P(n)P(n) 成立，所以 P(m)P(m)P(m) 对每个 m<n+1m < n + 1m<n+1 都成立：这就是 Q(n+1)Q(n + 1)Q(n+1)⁠。因此 Q(n)Q(n)Q(n) 对每个 nnn 都成立，而 P(n)P(n)P(n) 可以由 Q(n+1)Q(n + 1)Q(n+1) 推出。

定义 5.6素数

如果自然数 p≥2p \ge 2p≥2⁠，并且它的因数只有 1 和 ppp⁠，就称 ppp 是素数（prime）。nnn 的素因数（prime factor）是能整除 nnn 的素数。

例 5.6从 2 起的每个数都有素因数

断言：每个自然数 n≥2n \ge 2n≥2 都有素因数。

证明：对 nnn 做强归纳，其中 P(n)P(n)P(n) 为“如果 n≥2n \ge 2n≥2⁠，那么 nnn 有素因数”。设 n≥2n \ge 2n≥2⁠，并假设 P(m)P(m)P(m) 对每个 m<nm < nm<n 都成立。

  • 如果 nnn 是素数，那么 nnn 本身就是 nnn 的一个素因数。
  • 如果 nnn 不是素数，它就有一个因数 aaa⁠，满足 1<a<n1 < a < n1<a<n⁠。由归纳假设，P(a)P(a)P(a) 成立，又因为 a≥2a \ge 2a≥2⁠，所以 aaa 有一个素因数 ppp⁠。由于 ppp 整除 aaa⁠，而 aaa 整除 nnn⁠，所以 ppp 整除 nnn⁠。

当 n<2n < 2n<2 时，没有什么需要证明的。由强归纳法，P(n)P(n)P(n) 对每个 nnn 都成立。

仅凭前一个实例不足以支持此论证：知道 n−1n - 1n−1 有素因子并不提供 nnn 的因子。除数 aaa 可以是低于 nnn 的任何数，因此强归纳法恰好提供了此证明所使用的假设。对强化命题的普通归纳法也能提供这些假设，如前文推导所示。

例 5.7斐波那契数的一个上界

断言：对每个自然数 nnn⁠，fib(n)<2n\mathit{fib}(n) < 2^nfib(n)<2n⁠。

证明：对 nnn 做强归纳。假设对每个 m<nm < nm<n⁠，都有 fib(m)<2m\mathit{fib}(m) < 2^mfib(m)<2m⁠。

  • n=0n = 0n=0⁠：fib(0)=0<1=20\mathit{fib}(0) = 0 < 1 = 2^0fib(0)=0<1=20⁠。
  • n=1n = 1n=1⁠：fib(1)=1<2=21\mathit{fib}(1) = 1 < 2 = 2^1fib(1)=1<2=21⁠。
  • n≥2n \ge 2n≥2⁠：这时 n=k+2n = k + 2n=k+2⁠，而 kkk 和 k+1k + 1k+1 都比 nnn 小。对两者都使用归纳假设，得
fib(k+2)=fib(k)+fib(k+1)<2k+2k+1<2k+1+2k+1=2k+2.\mathit{fib}(k+2) = \mathit{fib}(k) + \mathit{fib}(k+1) < 2^k + 2^{k+1} < 2^{k+1} + 2^{k+1} = 2^{k+2}. fib(k+2)=fib(k)+fib(k+1)<2k+2k+1<2k+1+2k+1=2k+2.

强归纳法是沿着 N\NN 上的序 <<< 进行的归纳，它之所以成立，是因为这个序是良基的。对每个良基关系 RRR（模块 4）都有同样的结论：如果对每个 xxx⁠，只要 P(y)P(y)P(y) 对所有满足 (y,x)∈R(y, x) \in R(y,x)∈R 的 yyy 都成立，就能推出 P(x)P(x)P(x)⁠，那么 P(x)P(x)P(x) 对每个 xxx 都成立。这称为良基归纳法（well-founded induction）。结构归纳法是它的一个特例：这时 RRR 把 xs 与 x # xs 联系起来，把 l 和 r 与 Node l x r 联系起来。

终止性

到目前为止，每个函数在每个输入上都会停下来：每次递归调用都作用在一个更小的参数上，而参数不可能无休止地变小。本节解释 Isabelle 为什么坚持要求终止性（termination），以及它怎样检查终止性。

为什么fun需要终止性

在编程语言中，递归代码可能永远运行而不返回结果。HOL 函数是数学全函数，其定义方程必须成立。未经证明的编程配方不能直接作为定义方程接受。查看此提议的定义：

bad(n)=bad(n)+1\mathit{bad}(n) = \mathit{bad}(n) + 1 bad(n)=bad(n)+1

如果存在一个在 N\NN 上具有此性质的函数 bad\mathit{bad}bad⁠，则从两边减去 bad(n)\mathit{bad}(n)bad(n) 将得到 0=10 = 10=1⁠。定义中的方程是一个声称某事为真的断言，而该断言对于每个函数均为假。如果 Isabelle 按原样接受它，则可证明 0=10 = 10=1⁠，与逻辑中已有的算术相矛盾（Module 2）。

所以 Isabelle 从不轻信 fun 的等式。它先根据这些等式构造出一个函数，再把这些等式作为定理证明出来，而这个证明需要一个说明递归会终止的论证。fun 会自动寻找这样的论证。对 bad 来说，这样的论证并不存在：

开头几行只是宣布新常量的名字和类型；整个定义是失败的，之后 bad 并没有被定义。从下往上读这条错误消息。最后一行是说，Isabelle 找不到终止序。它考察了一个递归调用 a)，即从 n 到 n 的调用（箭头 ~> 表示“调用”），以及一个度量（measure），即 size，对数来说，它就是这个数本身。要接受这个定义，Isabelle 必须证明在这次调用中度量严格变小（<）；对这个调用来说，这就意味着要证明 False，而这是做不到的。“Result matrix”（结果矩阵）记录了它找到的最好结果：度量保持不变或者变小（<=），这还不够。

要点

在 HOL 中，每个函数都是total：它对每个参数都有值。具有良基递归的完整且兼容的递归方程确定了一个全函数。函数包在fun接受它们作为定义定理之前会检查方程并证明终止性。在模块 1 中描述的受信任逻辑基础设施下，这在不引入无根据公理的情况下添加了定义。仅终止性不足以豁免冲突方程。

并不是每个不终止的等式都自相矛盾：每个函数都满足 f(n)=f(n)f(n) = f(n)f(n)=f(n)⁠。但 Isabelle 并不试图区分无害的情况和有害的情况；只有在能证明终止性时，它才会接受用 fun 给出的递归定义。

度量

定义 5.7度量

递归定义的度量是一个从参数到 N\NN 的函数 mmm⁠，它在每次递归调用时都严格变小：只要 f(a)f(a)f(a) 的定义调用了 f(b)f(b)f(b)⁠，就有 m(b)<m(a)m(b) < m(a)m(b)<m(a)⁠。

事实 5.5用度量证明终止性

对于在每种情况下具有有限次调用且在这些调用之外具有终止工作的递归定义，递减度量保证每次求值均终止。

原因在于第 5.3 节讲过的 N\NN 的良基性：一个永不停止的求值会产生无穷多层嵌套调用，参数依次为 a0,a1,a2,…a_0, a_1, a_2, \dotsa0​,a1​,a2​,…⁠，于是 m(a0)>m(a1)>m(a2)>⋯m(a_0) > m(a_1) > m(a_2) > \cdotsm(a0​)>m(a1​)>m(a2​)>⋯ 就是一条由自然数组成的无穷递降链。而这样的链并不存在。

不变式

归纳可以证明关于递归函数的事实，也可以证明关于一步一步运行的过程（例如循环、协议和机器）的事实。用于后者的工具是不变式（invariant）。

定义 5.8不变式

一个归纳不变式，此处称为不变式，是进程状态的一个性质，它在每个初始状态下成立，并且被每个步骤保持：如果它在步骤之前成立，则在步骤之后也成立。

事实 5.6不变式在每个可达状态中都成立

如果 III 是一个过程的不变式，那么无论经过多少步，III 在这个过程所到达的每个状态中都成立。

证明是对步数 kkk 做归纳。经过 0 步时，过程处于初始状态，而 III 在初始状态成立。如果 III 在 kkk 步之后成立，下一步会保持它，所以 III 在 k+1k + 1k+1 步之后也成立。

一个循环

该程序使用循环对从 1 到 n 的数字求和。假设 n 是一个固定的自然数，且算术运算使用无界整数；若使用固定宽度整数实现，则还需处理溢出论证：

i := 0
s := 0
while i < n:
    i := i + 1
    s := s + i
return s

断言：这个循环返回 sum_upto(n)\mathit{sum\_upto}(n)sum_upto(n)⁠。取不变式 III 为“s=sum_upto(i)s = \mathit{sum\_upto}(i)s=sum_upto(i) 并且 i≤ni \le ni≤n⁠”。

  • 初始时：i=0i = 0i=0⁠，s=0=sum_upto(0)s = 0 = \mathit{sum\_upto}(0)s=0=sum_upto(0)⁠，并且 0≤n0 \le n0≤n⁠。
  • 保持：假设 III 成立，并且循环又执行了一次，所以 i<ni < ni<n⁠。执行之后，i′=i+1i' = i + 1i′=i+1⁠，并且由 sum_upto.2，s′=s+(i+1)=sum_upto(i)+(i+1)=sum_upto(i+1)=sum_upto(i′)s' = s + (i + 1) = \mathit{sum\_upto}(i) + (i + 1) = \mathit{sum\_upto}(i + 1) = \mathit{sum\_upto}(i')s′=s+(i+1)=sum_upto(i)+(i+1)=sum_upto(i+1)=sum_upto(i′)⁠；又因为 i<ni < ni<n⁠，所以 i′≤ni' \le ni′≤n⁠。
  • 结束时：条件 i<ni < ni<n 为假，所以 i≥ni \ge ni≥n⁠；结合 i≤ni \le ni≤n 就得到 i=ni = ni=n⁠，而不变式说明 s=sum_upto(n)s = \mathit{sum\_upto}(n)s=sum_upto(n)⁠。

结合例 5.1，这个循环返回 n(n+1)/2n(n+1)/2n(n+1)/2⁠。它也会终止：n−in - in−i 是一个每步减少 1 的自然数，也就是一个度量；对循环来说，这样的度量称为变式（variant）。注意，虽然断言只涉及 sss⁠，不变式却需要 i≤ni \le ni≤n 这一部分：没有它，退出条件 i≥ni \ge ni≥n 就推不出 i=ni = ni=n⁠。找到一个足够强的不变式，是这类证明中需要创造力的部分。这种关于循环的推理方式可以追溯到罗伯特·弗洛伊德（Robert Floyd，1967 年）和托尼·霍尔（Tony Hoare，1969 年）。

一台机器

票机模型接受5分与10分硬币并退回其他所有硬币。我们仅对硬币插入进行建模，不包含购买或退款转换。其状态为信用额，初始值为0。信用额能否恰好为12分？无论顾客如何操作，答案是否定的，且一个不变式解释了原因。取III⁠：“信用额是5的倍数”。

  • 初始时：余额是 0，它是 5 的倍数。
  • 保持：一枚 5 分或 10 分的硬币使余额增加 5 或 10，余额仍是 5 的倍数。其他硬币都被退回，余额不变。

所以售票机能达到的每个余额都是 5 的倍数，而 12 不是。这个论证覆盖了任意长度的每一种投币序列：这是无穷多种运行过程，再多的测试也试不完。

归纳假设是关于眼前这个 nnn 的 P(n)P(n)P(n)⁠。假设 P(n+1)P(n + 1)P(n+1)⁠，或者假设 P(n)P(n)P(n) 对每个 nnn 都成立，就等于假设了你要证明的东西。
2
apply (induction xs) 之后，Isabelle 显示子目标 ⋀a xs. P xs ⟹ P (a # xs)。它说的是什么？
⋀ 使 a 和 xs 成为任意的。⟹ 的左边是归纳假设，右边是要证明的陈述。
3
为什么 Isabelle 坚持要求每个用 fun 定义的函数都终止？
在 HOL 中，每个函数都是全函数，而定义中的等式是在断言某件事为真。一个不终止的递归可能根本没有解，接受这样的等式会使逻辑不一致。fun 不去区分这类情况和无害的情况，所以它坚持要求终止性证明。
4
哪个度量能说明 app 会终止？
app (x # xs) ys 调用 app xs ys：第一个参数少了一个元素，而第二个参数保持不变。
5
要证明 P(n)P(n)P(n)⁠，你需要某个 mmm 的 P(m)P(m)P(m)⁠，而这个 mmm 可以是任何比 nnn 小的数。哪种证明方法合适？
强归纳法允许你假设 P(m)P(m)P(m) 对每个 m<nm < nm<n 都成立，而不只是 P(n−1)P(n - 1)P(n−1)⁠。
6
by (induction xs) auto 失败了，剩下的目标中含有 reverse (app (reverse xs) [a])。通常最好的下一步是什么？
卡住的目标表明缺少的是哪个事实。把引理 reverse (app xs ys) = app (reverse ys) (reverse xs) 作为化简规则之后，证明就能通过。
